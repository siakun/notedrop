# 03. 동적 프로그래밍 - 정책 반복·가치 반복

> 이 챕터는 **환경 모델 P와 R을 안다**는 가정에서 출발합니다. 이 전제 아래 MDP의 최적 정책을 찾는 두 가지 동적 프로그래밍 기법, 정책 반복과 가치 반복을 정리합니다. 마지막에는 5x5 그리드 월드 코드로 두 알고리즘의 수행 시간 차이도 확인합니다.

## 1. 앞 장 환경 복습과 4x4 랜덤 정책 확인

앞 챕터에서 만든 `GridworldEnv`를 그대로 가져와 랜덤 정책으로 에피소드를 몇 번 돌려 봅니다. 정책 개선 없이도 환경 구조만으로 종착점에 도달한다는 감각을 먼저 확인해 두려는 준비 운동입니다.

> [!info] Ch 02 코드 가져오기
> 앞 챕터의 `DiscreteEnv`와 `GridworldEnv` 코드를 `gridworld.py`로 저장해 같은 폴더에 둔 뒤 아래 예시를 실행합니다. Jupyter 환경이면 해당 셀을 먼저 실행해 이름을 같은 세션에 로드해 두는 방식도 됩니다.

```python
import numpy as np
import random
from gridworld import GridworldEnv   # 앞 챕터에서 만든 환경 코드

env = GridworldEnv(shape=(4, 4))     # 상태 16, 행동 4
actions = {0: "UP", 1: "RIGHT", 2: "DOWN", 3: "LEFT"}

# 출발이 종착점이면 0 스텝으로 끝나 버리므로 재샘플링
while True:
    obs, _ = env.reset(seed=0)
    if obs not in (0, env.nS - 1):
        break

step = 0
while True:
    a = random.randrange(env.nA)
    next_obs, reward, terminated, truncated, _ = env.step(a)
    print(f"step {step}: s={obs}, a={actions[a]}, r={reward}, s'={next_obs}")
    obs = next_obs
    step += 1
    if terminated or truncated:
        break
print(f"에피소드 종료: 총 {step} 스텝")
```

여러 번 반복하면 종료까지의 스텝 수가 3, 28, 6, 14 처럼 크게 흔들립니다. 균등 랜덤 정책이 종착점 방향을 전혀 모르기 때문입니다. 이 분산을 줄이는 "좋은 정책"을 찾는 것이 이 챕터의 목표입니다.

### 1.1 전이 확률 텐서 형태

DP 알고리즘은 `P[a, s, s']` 3 축 텐서와 `R[s, a]` 2 축 보상 행렬을 바로 곱셈으로 다룹니다. Ch 02에서 `dict[s][a] = [(prob, next_s, reward, done), ...]` 형태로 저장한 전이 정보를 다음 헬퍼로 텐서 모양으로 바꿔 둡니다.

```python
def build_tensors(env):
    nS, nA = env.nS, env.nA
    P = np.zeros((nA, nS, nS))                     # (a, s, s')
    R = np.zeros((nS, nA))                         # (s, a)
    for s in range(nS):
        for a in range(nA):
            for prob, next_s, reward, _done in env.P[s][a]:
                P[a, s, next_s] += prob
                R[s, a] += prob * reward
    return P, R

P_tensor, R_matrix = build_tensors(env)
assert (P_tensor >= 0).all()
assert np.allclose(P_tensor.sum(axis=-1), 1)       # 각 행 합 1 확인
```

> [!note] 텐서 · 랭크
> 수치 배열의 차원 수를 "랭크" 라 부릅니다. 랭크 1은 벡터, 랭크 2는 행렬, 랭크 3 이상은 **텐서** 라고 합니다. 이 챕터에서 등장하는 `P[a, s, s']`는 **랭크 3 텐서** 입니다.
>
> 이렇게 모양을 맞춰 두면 `np.einsum` 이나 `@` 연산으로 수십~수백 상태를 한 번에 갱신할 수 있어 DP 코드가 간결해집니다.

## 2. 벨만 최적 방정식

MDP 풀이의 최종 목표는 **최적 정책 $\pi^*$**와 **최적 가치 함수 $V^*$, $Q^*$**를 찾는 것입니다.

$$
V^*(s) = \max_\pi V^\pi(s), \qquad Q^*(s, a) = \max_\pi Q^\pi(s, a)
$$

> [!note] 최적 정책 존재 정리
> 임의의 유한 MDP 에는 다음을 만족하는 **최적 정책** $\pi^*$가 존재합니다.
> 1. 모든 정책 $\pi$에 대해, 모든 상태에서 $V^{\pi^*}(s) \ge V^\pi(s)$
> 2. $\pi^*$는 $V^*$를 달성합니다
> 3. $\pi^*$는 $Q^*$를 달성합니다
>
> 최적 정책의 존재가 수학적으로 보장되므로, 알고리즘이 수렴하기만 하면 우리는 그 해를 찾은 셈입니다.

### 2.1 Q*에서 정책 뽑기

**최적 행동 가치 함수** $Q^*$를 알면 최적 정책은 단순한 **argmax**로 얻어집니다.

$$
\pi^*(s) = \arg\max_{a} Q^*(s, a)
$$

값(최대 Q)이 아니라 그 값을 만드는 **행동 인덱스**를 돌려준다는 점이 argmax의 핵심입니다. 코드에서는 "가장 큰 Q를 주는 'a'는 1, 나머지는 0"으로 정책 행렬을 갱신합니다.

### 2.2 벨만 최적 방정식 (BOE)

최적 가치 함수는 자기 자신을 참조하는 다음 방정식을 만족합니다.

$$
V^*(s) = \max_{a} \sum_{s'} P(s' \mid s, a) \left[ R(s, a, s') + \gamma V^*(s') \right]
$$

$$
Q^*(s, a) = \sum_{s'} P(s' \mid s, a) \left[ R(s, a, s') + \gamma \max_{a'} Q^*(s', a') \right]
$$

Ch 02의 벨만 **기대** 방정식과 비교하면, 외부 $\sum$이 있던 자리에 $\max$가 들어왔습니다. 이 **max 연산이 비선형** 이라 닫힌 해가 존재하지 않으며, 따라서 반복 알고리즘으로 수치적으로 푸는 수밖에 없습니다. 이 반복 알고리즘 두 가지가 바로 정책 반복과 가치 반복입니다.

## 3. 동적 프로그래밍이란

### 3.1 부분 문제로 쪼개 누적하기

> [!note] 동적 프로그래밍 (Dynamic Programming, DP)
> 큰 문제를 작은 **부분 문제**로 분해하고, $i$ 번째 단계의 답으로부터 $(i+1)$ 번째 답을 얻는 **순환식**으로 푸는 알고리즘 기법입니다. 같은 부분 문제를 여러 번 푸는 대신 한 번 계산해 저장하고 재사용한다는 아이디어가 핵심입니다.

피보나치 수열 비유가 가장 직관적입니다.

$$
F_n = F_{n-1} + F_{n-2}, \qquad F_0 = 0,\; F_1 = 1
$$

$F_6$을 구하려면 $F_5$와 $F_4$가 필요하고, $F_5$는 $F_4$와 $F_3$이 필요합니다. 재귀로 풀면 같은 값을 여러 번 계산하지만, **바텀업**으로 $F_0, F_1 \to F_2 \to F_3 \to \cdots \to F_6$ 처럼 표에 값을 쌓아 올리면 각 값을 한 번씩만 계산하면 됩니다. 강화학습의 벨만 최적 방정식도 "다음 상태 값을 쓰는 재귀식" 이어서 같은 기법을 적용할 수 있습니다.

### 3.2 환경을 아는가 모르는가

| 환경 모델 | 대표 기법 |
|---|---|
| 완전히 안다 ($P$·$R$ 모두 주어짐) | 동적 프로그래밍 (정책 반복·가치 반복) |
| 모른다 (샘플만 얻음) | 몬테카를로 (Ch 04), TD·Q 러닝 (Ch 05) |

이 챕터는 **환경을 아는** 경우만 다룹니다. 실제 응용에서 이 전제는 드물지만, 모델-프리 알고리즘의 기반 아이디어가 모두 DP에서 출발하므로 반드시 짚고 넘어가야 합니다.

## 4. 정책 반복 (Policy Iteration)

### 4.1 두 단계의 교대

정책 반복은 두 단계를 번갈아 실행하며 정책을 개선합니다.

1. **정책 평가 (Policy Evaluation)**: 현재 정책 $\pi$에 대해 **벨만 기대 방정식**을 수렴할 때까지 반복 적용해 $V^\pi$를 계산합니다.
2. **정책 개선 (Policy Improvement)**: 얻은 $V^\pi$에서 $Q(s, a)$를 구하고, 각 상태에서 $\arg\max$ 행동을 새 정책으로 삼습니다.
3. 정책이 더 이상 바뀌지 않을 때까지 1 ~ 2를 반복합니다.

평가 단계의 벨만 기대 방정식은 다음과 같습니다.

$$
V^\pi(s) = \sum_{a} \pi(a \mid s) \sum_{s'} P(s' \mid s, a) \left[ R(s, a, s') + \gamma V^\pi(s') \right]
$$

### 4.2 행렬 형태로 쓰기

정책이 반영된 보상 $R_\pi$와 전이 확률 $P_\pi$를 미리 뽑으면 평가식을 간단히 쓸 수 있습니다.

$$
R_\pi(s) = \sum_a \pi(a \mid s) R(s, a), \qquad P_\pi(s, s') = \sum_a \pi(a \mid s) P(s' \mid s, a)
$$

$$
V^\pi = R_\pi + \gamma P_\pi V^\pi
$$

이 재귀식을 수렴할 때까지 반복하면 정책 평가가 끝납니다. 상태 수가 적으면 $(I - \gamma P_\pi)^{-1} R_\pi$로 닫힌 해를 구할 수도 있지만, 실전에서는 거의 반복 방식을 씁니다.

### 4.3 의사코드

```text
입력: 임의 정책 π
출력: 최적 정책 π*

repeat:
    # 1) 정책 평가
    V ← 0
    repeat:
        V_new = R_π + γ · P_π V
        if ||V_new - V|| < ε: break
        V = V_new

    # 2) 정책 개선
    for each s:
        Q(s, ·) = R(s, ·) + γ · Σ_{s'} P(·, s, s') · V(s')
        π_new(s) = one_hot(arg max_a Q(s, a))

    if π_new == π: break
    π = π_new
```

평가 단계가 매번 **내부 수렴 루프**를 돌아야 하므로 정책이 여러 번 바뀔수록 전체 연산량이 누적됩니다. 이 낭비를 줄이려는 시도가 다음 절의 가치 반복입니다.

## 5. 가치 반복 (Value Iteration)

### 5.1 평가 수렴을 기다리지 않는다

가치 반복은 "정책 평가를 끝까지 수렴시키기" 단계를 **생략** 합니다. 매 반복에서 벨만 **최적** 방정식을 한 번만 적용해 $V$를 갱신하고, 최종적으로 얻어진 $V^*$에서 정책을 한 번에 뽑습니다.

$$
V_{k+1}(s) = \max_{a} \sum_{s'} P(s' \mid s, a) \left[ R(s, a, s') + \gamma V_k(s') \right]
$$

정책 반복의 평가 식과 비교하면, 외부에 있던 $\sum_a \pi(a \mid s)$ 자리에 $\max_a$가 들어왔습니다. 이 한 줄 차이 덕분에 정책을 별도로 유지할 필요가 없어집니다.

### 5.2 의사코드

```text
입력: 임의 V_0 (보통 0으로 초기화)
출력: 최적 정책 π*

repeat:
    V_new(s) = max_a Σ_{s'} P(s' | s, a) · [R(s, a, s') + γ V(s')]
    if ||V_new - V|| < ε: break
    V = V_new

# 마지막에 정책 추출
π*(s) = one_hot(arg max_a Σ_{s'} P(s' | s, a) · [R(s, a, s') + γ V*(s')])
```

### 5.3 한 스텝 계산해 보기

그리드 위의 어떤 내부 상태 $s$에서 네 방향 행동의 한 스텝 lookahead를 손으로 계산해 보겠습니다. 초기 $V_0$는 모든 상태에서 0, 감소율 $\gamma = 1$, 보상 규약은 (종착 도달 +5, 벽에 부딪쳐 제자리 -2, 그 외 이동 -1) 입니다. 네 방향 중 서쪽으로 한 칸 가면 종착 상태에 도달하고, 북쪽은 벽에 부딪히며, 동·남은 일반 이동이라고 하면 표는 다음과 같이 정리됩니다.

| 행동 | 결과 | 즉시 보상 $R$ | $V_0(s')$ | $R + \gamma V_0(s')$ |
|---|---|---|---|---|
| 동 | 일반 이동 | -1 | 0 | -1 |
| 서 | **종착 도달** | +5 | 0 | +5 |
| 남 | 일반 이동 | -1 | 0 | -1 |
| 북 | 벽, 제자리 | -2 | 0 | -2 |

$\max = 5$ (서쪽). 따라서 $V_1(s) = 5$ 이고 $\pi_1(s) = \text{서}$ 입니다. 모든 상태에 대해 같은 방식으로 한 번 훑으면 $V_1$ 격자가 완성됩니다. 다음 반복에서 $V_1$을 $V_k$ 자리에 넣고 $V_2$를 계산, 이를 $\|V_{k+1} - V_k\|$가 허용 오차 이하가 될 때까지 반복합니다.

> [!info] 왜 더 빠른가
> 정책 반복은 "**내부 평가 수렴 루프 x 외부 정책 개선 루프**"의 이중 구조입니다. 반면 가치 반복은 단일 루프에서 `'max'`를 직접 적용합니다. 한 반복당 연산량은 비슷해도 **전체 반복 횟수**가 훨씬 적어 현실 문제에서 수십~수백 배 빨리 끝납니다.

## 6. 5x5 그리드 월드로 구현하기

### 6.1 환경과 텐서 준비

앞 챕터의 `GridworldEnv`는 `shape=(5, 5)`도 바로 지원하므로 그대로 확장합니다.

```python
env = GridworldEnv(shape=(5, 5))                   # 25 상태, 4 행동
P_tensor, R_matrix = build_tensors(env)            # 위에서 만든 헬퍼 사용
```

### 6.2 TensorDP 클래스

정책 평가·정책 개선·정책 반복·가치 반복을 메서드로 가지는 **모델 기반 DP 에이전트**를 NumPy로 구현합니다.

```python
class TensorDP:
    def __init__(self, P, R, gamma=1.0, error_tol=1e-5):
        self.P = P                                 # (nA, nS, nS)
        self.R = R                                 # (nS, nA)
        self.gamma = gamma
        self.error_tol = error_tol
        self.nA, self.nS, _ = P.shape
        self.reset_policy()

    def reset_policy(self):
        self.policy = np.ones((self.nS, self.nA)) / self.nA

    def set_policy(self, policy):
        self.policy = policy

    def _r_pi(self, policy):
        # (nS, nA) 성분별 곱의 행 합 -> (nS,)
        return (policy * self.R).sum(axis=1)

    def _p_pi(self, policy):
        # policy[s, a] * P[a, s, s'] -> (nS, nS)
        # einsum으로 한 번에 계산
        return np.einsum("sa,asn->sn", policy, self.P)

    def policy_evaluation(self, policy=None, v_init=None):
        policy = self.policy if policy is None else policy
        R_pi = self._r_pi(policy)
        P_pi = self._p_pi(policy)
        V = np.zeros(self.nS) if v_init is None else v_init.copy()

        while True:
            V_new = R_pi + self.gamma * P_pi @ V
            if np.linalg.norm(V_new - V) <= self.error_tol:
                return V_new
            V = V_new

    def policy_improvement(self, V):
        # Q[s, a] = R[s, a] + γ Σ_{s'} P[a, s, s'] · V[s']
        Q = self.R + self.gamma * np.einsum("asn,n->sa", self.P, V)
        best = Q.argmax(axis=1)
        new_policy = np.zeros_like(self.policy)
        new_policy[np.arange(self.nS), best] = 1.0
        return new_policy

    def policy_iteration(self):
        history = {"V": [], "pi": [], "steps": 0}
        policy = self.policy
        while True:
            V = self.policy_evaluation(policy)
            policy_new = self.policy_improvement(V)

            history["V"].append(V)
            history["pi"].append(policy_new)
            history["steps"] += 1

            if np.allclose(policy_new, policy):
                break
            policy = policy_new

        self.set_policy(policy_new)
        return history

    def value_iteration(self, v_init=None):
        history = {"V": [], "pi": [], "steps": 0}
        V = np.zeros(self.nS) if v_init is None else v_init.copy()

        while True:
            Q = self.R + self.gamma * np.einsum("asn,n->sa", self.P, V)
            V_new = Q.max(axis=1)

            best = Q.argmax(axis=1)
            policy_new = np.zeros((self.nS, self.nA))
            policy_new[np.arange(self.nS), best] = 1.0

            history["V"].append(V_new)
            history["pi"].append(policy_new)
            history["steps"] += 1

            if np.linalg.norm(V_new - V) <= self.error_tol:
                break
            V = V_new

        self.set_policy(policy_new)
        return history
```

핵심은 **`np.einsum("asn,n->sa", P, V)`** 한 줄입니다. 이 식은 "각 상태에서 각 행동을 했을 때, 다음 상태 가치의 기대값이 얼마인가"를 한 번에 계산합니다. 수식으로 쓰면 모든 상태·행동에 대해 $\sum_{s'} P(s' \mid s, a) V(s')$를 한꺼번에 구하는 셈입니다.

### 6.3 랜덤 정책 평가 시각화

직접 `matplotlib`으로 격자에 V 값을 찍고 정책 화살표를 덧그리는 헬퍼입니다.

```python
import matplotlib.pyplot as plt

ARROWS = {0: (0, -0.3), 1: (0.3, 0), 2: (0, 0.3), 3: (-0.3, 0)}   # UP,RIGHT,DOWN,LEFT

def visualize_value(ax, V, nx, ny, title="V"):
    grid = V.reshape(ny, nx)
    im = ax.imshow(grid, cmap="coolwarm")
    for y in range(ny):
        for x in range(nx):
            ax.text(x, y, f"{grid[y, x]:.1f}", ha="center", va="center", fontsize=9)
    ax.set_title(title); ax.set_xticks([]); ax.set_yticks([])
    return im

def visualize_policy(ax, policy, nx, ny, title="π"):
    for s in range(nx * ny):
        y, x = divmod(s, nx)
        for a, prob in enumerate(policy[s]):
            if prob > 0:
                dx, dy = ARROWS[a]
                ax.arrow(x, y, dx, dy, head_width=0.1, alpha=min(prob, 1.0))
    ax.set_xlim(-0.5, nx - 0.5); ax.set_ylim(ny - 0.5, -0.5)
    ax.set_xticks([]); ax.set_yticks([]); ax.set_title(title)
```

이제 TensorDP를 붙여 정책 반복 한 번 돌리기 전후의 V와 정책을 비교합니다.

```python
dp = TensorDP(P_tensor, R_matrix, gamma=1.0)
V_random = dp.policy_evaluation()                   # 균등 랜덤 정책 평가

fig, axes = plt.subplots(1, 2, figsize=(10, 5))
visualize_value(axes[0], V_random, 5, 5, title="V (random policy)")
visualize_policy(axes[1], dp.policy, 5, 5, title="π (random)")
plt.show()
```

균등 랜덤 정책 아래에서는 종착점 주변만 0에 가깝고, 먼 상태일수록 V가 -20 이하로 깊게 내려갑니다 (매 스텝 -1 보상이 누적되기 때문입니다). 화살표는 네 방향 모두 동일한 투명도로 그려집니다.

### 6.4 정책 개선 한 번 적용

```python
improved = dp.policy_improvement(V_random)
dp.set_policy(improved)
V_improved = dp.policy_evaluation()

fig, axes = plt.subplots(1, 2, figsize=(10, 5))
visualize_value(axes[0], V_improved, 5, 5, title="V (improved)")
visualize_policy(axes[1], dp.policy, 5, 5, title="π (improved)")
plt.show()

print("개선 전후 V 평균:", V_random.mean(), "->", V_improved.mean())
```

개선된 정책은 양쪽 종착점 방향으로 화살표가 모이고, V 값이 전체적으로 위로 올라갑니다. 좌상·우하 대각선을 축으로 대칭 패턴이 보이는 것도 그리드 월드 설계의 대칭성 덕분입니다.

## 7. 정책 반복 vs 가치 반복 실행 시간 비교

두 알고리즘이 같은 최적 정책으로 수렴하는지, 그리고 얼마나 빨리 끝나는지를 직접 측정합니다.

```python
import time

dp = TensorDP(P_tensor, R_matrix, gamma=1.0)

t0 = time.perf_counter()
hist_pi = dp.policy_iteration()
t_pi = time.perf_counter() - t0

dp.reset_policy()
t0 = time.perf_counter()
hist_vi = dp.value_iteration()
t_vi = time.perf_counter() - t0

print(f"정책 반복: {hist_pi['steps']} step, {t_pi*1000:.2f} ms")
print(f"가치 반복: {hist_vi['steps']} step, {t_vi*1000:.2f} ms")

# 최적 가치 함수 일치 확인 (argmax 타이로 정책 행렬 자체는 다를 수 있음)
V_pi = dp.policy_evaluation(hist_pi["pi"][-1])
V_vi = dp.policy_evaluation(hist_vi["pi"][-1])
print("V 일치:", np.allclose(V_pi, V_vi, atol=1e-4))
```

5x5 그리드 월드에서는 일반적으로 **가치 반복이 정책 반복보다 수십 배 빠르게** 끝납니다. 정책 반복은 외부 루프마다 내부 평가 수렴을 기다려야 하기 때문입니다.

두 종착점에 대해 대칭인 중앙선 상태에서는 두 방향의 Q가 같아 argmax 타이가 풀리는 방향이 알고리즘마다 달라질 수 있습니다. 그래서 정책 행렬 모양은 약간 달라도 **최적 가치 함수는 동일** 하게 수렴할 수 있습니다.

### 7.1 스텝별 수렴 과정 시각화

가치 반복의 히스토리를 차례로 그리면 **정보가 종착점에서 바깥으로 번지는** 모습이 드러납니다.

```python
steps = len(hist_vi["V"])
fig, axes = plt.subplots(steps, 2, figsize=(10, 4 * steps))
for i in range(steps):
    visualize_value(axes[i, 0], hist_vi["V"][i], 5, 5, title=f"V iter {i}")
    visualize_policy(axes[i, 1], hist_vi["pi"][i], 5, 5, title=f"π iter {i}")
plt.tight_layout(); plt.show()
```

첫 반복에서는 종착점에 바로 닿는 상태의 V만 유효한 값을 얻고, 반복이 진행되면서 인접 상태로 정보가 한 칸씩 번져 갑니다. 몇 번 안에 모든 상태의 화살표가 **최단 경로로 종착점을 가리키도록** 수렴합니다.

## 8. 정리

| 개념 | 요약 |
|---|---|
| MDP 풀이의 목표 | 최적 정책 $\pi^*$와 $V^*$, $Q^*$ 찾기 |
| 벨만 최적 방정식 (BOE) | $V^*(s) = \max_a \sum_{s'} P [R + \gamma V^*(s')]$. 닫힌 해 없음 |
| 환경을 아는 경우 | 동적 프로그래밍으로 BOE를 수치적으로 풀이 |
| 정책 반복 | 평가 수렴 + 개선의 이중 루프. 깔끔하지만 느림 |
| 가치 반복 | V에 `'max'`를 직접 적용하는 단일 루프. 대개 훨씬 빠름 |
| 공통 결과 | 같은 최적 정책·최적 가치 함수로 수렴 (유한 MDP 보장) |

다음 챕터(Part 7 Ch 04) 에서는 "환경 모델을 모를 때"로 제약을 풉니다. 전이 확률 $P$와 보상 $R$을 주지 않고, 에이전트가 환경과 상호작용하며 수집한 샘플만으로 정책을 개선하는 **몬테카를로 방법**을 다룹니다. 이어지는 Ch 05 에서는 시간차 학습(TD)·Q 러닝·DQN으로 확장됩니다.
