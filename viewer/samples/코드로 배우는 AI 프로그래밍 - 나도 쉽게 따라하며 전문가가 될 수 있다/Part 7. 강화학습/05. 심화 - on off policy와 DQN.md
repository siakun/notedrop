# 05. 심화 - on/off policy와 DQN

> 앞 챕터의 몬테카를로는 **에피소드가 끝난 뒤에만** 학습할 수 있다는 한계가 있었습니다. 그래서 한 스텝씩 바로 갱신할 수 있는 시간차(TD) 학습이 필요합니다. 이 챕터에서는 TD의 기본 아이디어를 도입한 뒤, on-policy 인 SARSA와 off-policy 인 Q-learning을 비교하고, 마지막에는 이를 딥러닝으로 확장한 **DQN**까지 이어 갑니다.

## 1. TD 학습 - MC와 DP의 중간 지점

### 1.1 MC의 한계를 TD가 푸는 방식

MC는 한 에피소드의 리턴 $G_t$가 확정된 뒤 $V(s) \leftarrow V(s) + \alpha (G_t - V(s))$로 갱신했습니다. 에피소드가 긴 문제나 종료가 없는 연속 문제에서는 이 방식 자체가 돌지 못합니다.

시간차(TD, Temporal Difference) 학습은 리턴을 **한 스텝 앞까지만** 실제로 관측하고 나머지는 **현재 추정 $V(s')$**로 대체합니다 (부트스트랩). TD(0)의 갱신식은 아래와 같습니다.

$$
V(s_t) \leftarrow V(s_t) + \alpha \bigl[ \underbrace{r_{t+1} + \gamma V(s_{t+1})}_{\text{TD target}} - V(s_t) \bigr]
$$

- $r_{t+1} + \gamma V(s_{t+1})$: TD target. 한 스텝 실제 보상 + 할인된 다음 상태 가치 추정
- $r_{t+1} + \gamma V(s_{t+1}) - V(s_t)$: TD error. 현재 추정이 target과 얼마나 떨어졌는지
- 이 오차를 학습률 $\alpha$로 섞어 $V(s_t)$를 보정

이 갱신이 **스텝마다** 가능하다는 점이 MC 대비 결정적 장점입니다.

### 1.2 TD 에이전트 뼈대

Ch 04의 `MCAgent`와 목적은 같지만, 에피소드 전체를 받는 `update(episode)` 대신 한 번의 전이 `(s, a, r, s', done)`을 받는 `sample_update`가 기본 갱신 단위가 됩니다. 이 차이가 스텝 단위 학습을 가능하게 만드는 지점입니다.

```python
import numpy as np

class TDAgent:
    def __init__(self, gamma: float, n_states: int, n_actions: int,
                 epsilon: float, lr: float):
        self.gamma = gamma
        self.n_states = n_states
        self.n_actions = n_actions
        self.epsilon = epsilon
        self.lr = lr
        self.V = np.zeros(n_states)
        self.Q = np.zeros((n_states, n_actions))

    def get_action(self, state: int) -> int:
        if np.random.rand() < self.epsilon:
            return np.random.randint(self.n_actions)
        return int(np.argmax(self.Q[state]))

    def sample_update(self, s, a, r, next_s, done):
        # TD(0): V(s) <- V(s) + lr * (r + gamma * V(s') * (1 - done) - V(s))
        target = r + self.gamma * self.V[next_s] * (1.0 - done)
        self.V[s] += self.lr * (target - self.V[s])
```

### 1.3 MC vs TD 분산·편향

두 방법을 비교하면 특성이 깔끔하게 갈립니다.

| 축 | MC | TD(0) |
|---|---|---|
| 업데이트 단위 | 에피소드 끝에 한 번 | 스텝마다 |
| 사용하는 정보 | 실제 리턴 $G_t$ | 한 스텝 보상 + 부트스트랩 $V(s')$ |
| 편향 | 없음 (표본 평균은 불편 추정) | 있음 ($V(s')$가 아직 부정확하면 타겟도 왜곡) |
| 분산 | 큼 (여러 스텝 확률 누적) | 작음 |
| 종료가 없는 문제 | 불가 | 가능 |

### 1.4 n-step TD

TD(0)와 MC의 중간으로 **n 스텝** 실제 보상 뒤 부트스트랩하는 방식도 있습니다.

$$
G_t^{(n)} = r_{t+1} + \gamma r_{t+2} + \cdots + \gamma^{n-1} r_{t+n} + \gamma^n V(s_{t+n})
$$

$n$을 키우면 MC에 가까워져 편향이 줄고 분산이 커집니다. $n=1$은 TD(0), $n=\infty$는 MC. 실무에서는 보통 $n = 3 \sim 5$ 정도에서 좋은 절충을 얻습니다.

## 2. On-policy vs Off-policy

TD가 등장하면서 "어떤 정책으로 모은 데이터를 어떤 정책 학습에 쓰는가" 라는 질문이 중요해집니다.

> [!note] 타깃 정책(target policy) vs 행동 정책(behavior policy)
> - **타깃 정책 $\pi$**: 궁극적으로 학습시키려는 정책
> - **행동 정책 $b$**: 환경과 상호작용하며 실제로 행동을 뽑는 정책
> - 두 정책이 같으면 **on-policy**, 달라도 학습이 가능하면 **off-policy**

### 2.1 On-policy의 제약과 Importance Sampling

on-policy는 정책이 바뀌는 순간부터 과거 경험이 "다른 분포에서 나온 샘플"이 되어 재사용에 제한이 생깁니다. 굳이 과거 데이터를 쓰려면 두 분포의 비율을 곱해 보정해야 합니다. 이것이 **Importance Sampling** 입니다.

즉, 행동 정책과 타깃 정책이 다르면 과거 표본에 다시 가중치를 줘야 한다는 뜻입니다.

$$
\mathbb{E}_{a \sim \pi} [f(a)] = \mathbb{E}_{a \sim b} \left[ \frac{\pi(a \mid s)}{b(a \mid s)} f(a) \right]
$$

### 2.2 Off-policy의 강점

off-policy는 "다음 상태에서 **타깃 정책이** 무슨 행동을 고를 것인가"만 업데이트에 쓰기 때문에 행동 정책이 어떤 탐험을 섞어 모은 데이터든 **그대로 재사용** 할 수 있습니다. 나중에 볼 Q-learning과 DQN은 타깃을 **탐욕 정책**으로 고정하고 `'max'`를 취하는 방식이라 Importance Sampling 보정 없이도 바로 학습할 수 있습니다.

## 3. SARSA - on-policy TD 제어

> [!note] SARSA
> State-Action-Reward-State-Action. 현재와 다음 행동 모두를 **동일 정책**에서 뽑아 $Q(s, a)$를 갱신하는 on-policy TD 제어 알고리즘.

갱신식은 다음과 같습니다.

$$
Q(s_t, a_t) \leftarrow Q(s_t, a_t) + \alpha \bigl[ r_{t+1} + \gamma \, Q(s_{t+1}, a_{t+1}) - Q(s_t, a_t) \bigr]
$$

TD(0)의 $V$ 자리에 $Q$가 들어왔고, 다음 상태의 가치를 **다음에 실제로 고를 행동** $a_{t+1}$의 Q로 평가합니다. 이 "실제로 고르는" 부분이 on-policy의 결정적 특징입니다.

### 3.1 의사코드

```text
Q(s, a) <- 0
repeat (episode):
    초기 상태 s 관측
    a <- epsilon-greedy(Q, s)
    while not done:
        r, s' <- env.step(a)
        a' <- epsilon-greedy(Q, s')
        Q(s, a) <- Q(s, a) + alpha * (r + gamma * Q(s', a') - Q(s, a))
        s, a <- s', a'
```

### 3.2 구현

`TDAgent`를 상속해 `Q`를 갱신하는 버전입니다.

```python
class SARSAAgent(TDAgent):
    def sample_update(self, s, a, r, next_s, next_a, done):
        target = r + self.gamma * self.Q[next_s, next_a] * (1.0 - done)
        self.Q[s, a] += self.lr * (target - self.Q[s, a])
```

에피소드 루프에서는 상태 `s`의 행동 `a`를 먼저 뽑고, 스텝을 돌려 받은 `next_s`에서 **다음 행동 `next_a`까지 뽑은 뒤** `update`를 호출합니다.

```python
def run_sarsa_episode(env, agent, seed=None):
    obs, _ = env.reset(seed=seed)
    a = agent.get_action(obs)
    ep_reward = 0.0
    while True:
        next_obs, r, terminated, truncated, _ = env.step(a)
        done = terminated or truncated
        next_a = agent.get_action(next_obs)
        agent.sample_update(int(obs), int(a), float(r), int(next_obs), int(next_a), float(done))
        ep_reward += r
        obs, a = next_obs, next_a
        if done:
            break
    return ep_reward
```

## 4. Q-learning - off-policy TD 제어

Q-learning은 다음 상태의 가치를 **다음에 실제로 고를 행동이 아니라, 그 상태에서 가능한 최고 Q**로 평가합니다.

$$
Q(s_t, a_t) \leftarrow Q(s_t, a_t) + \alpha \bigl[ r_{t+1} + \gamma \max_{a'} Q(s_{t+1}, a') - Q(s_t, a_t) \bigr]
$$

타깃이 탐욕 정책이라는 점이 SARSA 와의 유일한 차이지만, 이 한 줄이 알고리즘을 **off-policy**로 바꿉니다. 행동 선택은 여전히 $\epsilon$-greedy 같은 탐험 섞인 정책으로 하되, 업데이트는 "다음 상태에서 최적 행동을 골랐다고 가정" 하고 이뤄지니까요.

### 4.1 구현

```python
class QLearningAgent(TDAgent):
    def sample_update(self, s, a, r, next_s, done):
        target = r + self.gamma * self.Q[next_s].max() * (1.0 - done)
        self.Q[s, a] += self.lr * (target - self.Q[s, a])
```

`next_action` 인자가 없어진 것이 SARSA 와의 유일한 코드 차이입니다. 에피소드 루프도 한층 단순해집니다.

```python
def run_qlearn_episode(env, agent, seed=None):
    obs, _ = env.reset(seed=seed)
    ep_reward = 0.0
    while True:
        a = agent.get_action(obs)
        next_obs, r, terminated, truncated, _ = env.step(a)
        done = terminated or truncated
        agent.sample_update(int(obs), int(a), float(r), int(next_obs), float(done))
        ep_reward += r
        obs = next_obs
        if done:
            break
    return ep_reward
```

## 5. SARSA vs Q-learning - CliffWalking 실험

4x4 그리드 월드는 두 알고리즘의 차이를 잘 드러내지 못합니다. 고전 예제인 **CliffWalking**은 on/off policy의 실용적 차이를 극명하게 보여 줍니다. 가로 12 x 세로 4의 격자, 하단에 절벽(큰 음수 보상), 목표는 우하단.

```python
import gymnasium as gym

cliff_env = gym.make("CliffWalking-v0")               # 48 상태, 4 행동
n_states  = cliff_env.observation_space.n
n_actions = cliff_env.action_space.n

sarsa = SARSAAgent(gamma=0.9, n_states=n_states, n_actions=n_actions,
                   epsilon=0.1, lr=0.1)
qlearn = QLearningAgent(gamma=0.9, n_states=n_states, n_actions=n_actions,
                        epsilon=0.1, lr=0.1)
```

두 에이전트를 같은 환경에서 학습시켜 에피소드별 **총 보상**을 수집합니다.

```python
import matplotlib.pyplot as plt

N_EP = 500
sarsa_rewards = []
qlearn_rewards = []

for ep in range(N_EP):
    sarsa_rewards.append(run_sarsa_episode(cliff_env, sarsa, seed=ep))
    qlearn_rewards.append(run_qlearn_episode(cliff_env, qlearn, seed=ep))

def moving_avg(x, w=20):
    return np.convolve(x, np.ones(w) / w, mode="valid")

plt.plot(moving_avg(sarsa_rewards),  label="SARSA (on-policy)")
plt.plot(moving_avg(qlearn_rewards), label="Q-learning (off-policy)")
plt.xlabel("episode"); plt.ylabel(f"reward (moving avg, w=20)")
plt.legend(); plt.grid(); plt.show()
```

> [!example] CliffWalking 에서의 전형적 차이
> - **Q-learning**: 절벽 바로 위를 따라가는 **최단 경로**를 학습합니다. 다만 $\epsilon$ 탐험 중에 절벽에 한 번 떨어지면 큰 음수 보상이 누적되어 에피소드 평균 보상이 자주 크게 요동칩니다.
> - **SARSA**: 절벽에서 한 줄 위로 **안전하게 돌아가는 경로**를 학습합니다. 다음 행동도 $\epsilon$-greedy로 뽑는다는 사실이 타깃에 반영되므로, "탐험 중에 떨어질 위험"을 정책 자체가 회피하는 쪽으로 학습합니다.

이 차이는 "어떤 정책이 옳은가"의 문제가 아닙니다. **Q-learning은 최적 정책**을, **SARSA는 현재 탐험을 가정한 최선**을 학습할 뿐입니다. 탐험이 끝난 뒤(배포 시 $\epsilon = 0$)까지 가정하면 Q-learning 쪽이 높은 보상을 주지만, 실제 학습 중의 안전이 더 중요한 물리 시스템에서는 SARSA 쪽이 더 타당할 수 있습니다.

한 줄로 요약하면 **Q-learning은 더 공격적이고, SARSA는 더 보수적** 입니다.

이 차이는 "어떤 정책이 옳은가"의 문제가 아닙니다. **Q-learning은 최적 정책**을, **SARSA는 현재 탐험을 가정한 최선**을 학습할 뿐입니다. 탐험이 끝난 뒤(배포 시 $\epsilon = 0$)까지 가정하면 Q-learning 쪽이 높은 보상을 주지만, 실제 학습 중의 안전이 더 중요한 물리 시스템에서는 SARSA 쪽이 더 타당할 수 있습니다.

## 6. DQN - 함수 근사와 Experience Replay

### 6.1 Q 테이블의 한계

지금까지 다룬 Q-learning은 `Q[n_states, n_actions]` **테이블**에 모든 값을 저장했습니다. 상태 공간이 커지면 이 테이블은 바로 폭발합니다. CartPole 같은 연속 상태(카트 위치·속도, 막대 각도·각속도)는 테이블화 자체가 불가능합니다.

해결책은 Q를 **신경망 함수 $Q_\theta(s, a)$**로 근사하는 것입니다. 이 아이디어에 다음 두 장치를 더해 안정화한 것이 DeepMind의 DQN (Mnih et al., Nature 2015) 입니다.

> [!info] DQN 3대 요소
> 1. **Q 네트워크**: 상태 $s$를 입력받아 각 행동의 Q 값을 출력합니다. 큰 상태 공간을 테이블 대신 함수로 다루기 위해 필요합니다.
> 2. **Experience Replay**: 경험 $(s, a, r, s', \text{done})$을 버퍼에 저장해 두고 **무작위 배치**로 다시 뽑아 학습합니다. 연속 샘플의 상관을 줄이고 같은 경험을 여러 번 재사용하기 위해 필요합니다.
> 3. **Target Network**: 타깃 계산용 네트워크 $Q_{\theta^-}$를 따로 둡니다. 타깃이 매 스텝 함께 흔들려 학습이 불안정해지는 문제를 줄이기 위해 필요합니다.

### 6.2 손실 함수

DQN은 다음 손실을 최소화합니다.

$$
L(\theta) = \mathbb{E} \left[ \bigl( r + \gamma \max_{a'} Q_{\theta^-}(s', a') - Q_\theta(s, a) \bigr)^2 \right]
$$

Q-learning의 TD 오차 제곱을 신경망 회귀 손실로 그대로 옮긴 형태입니다. 실전에서는 바깥 이상치에 둔감한 **Huber loss** (`SmoothL1Loss`)를 쓰는 것이 관행입니다.

### 7.1 Q 네트워크

간단한 MLP. 출력 활성화는 Identity로 두어야 Q 값(실수)이 그대로 나옵니다.

```python
import torch
import torch.nn as nn

class QNet(nn.Module):
    def __init__(self, state_dim: int, action_dim: int, hidden=(128, 128)):
        super().__init__()
        layers, prev = [], state_dim
        for h in hidden:
            layers += [nn.Linear(prev, h), nn.ReLU()]
            prev = h
        layers.append(nn.Linear(prev, action_dim))
        self.net = nn.Sequential(*layers)

    def forward(self, s):
        return self.net(s)
```

### 7.2 Replay 버퍼

고정 크기 deque로 FIFO 대체를 자연스럽게 처리합니다.

```python
import random
from collections import deque

class ReplayBuffer:
    def __init__(self, max_size: int):
        self.buffer = deque(maxlen=max_size)

    def push(self, sample):
        self.buffer.append(sample)                    # (s, a, r, s', done)

    def sample(self, batch_size: int):
        return random.sample(self.buffer, batch_size)

    def __len__(self):
        return len(self.buffer)
```

### 7.3 DQN 에이전트

행동 선택($\epsilon$-greedy), 배치 학습, 타깃 네트워크 동기화 메서드를 한 클래스에 모읍니다.

```python
import torch.optim as optim

class DQNAgent:
    def __init__(self, state_dim, action_dim, gamma=0.99,
                 lr=5e-4, epsilon=0.1, device="cpu"):
        self.action_dim = action_dim
        self.gamma = gamma
        self.epsilon = epsilon
        self.device = device

        self.qnet        = QNet(state_dim, action_dim).to(device)
        self.qnet_target = QNet(state_dim, action_dim).to(device)
        self.qnet_target.load_state_dict(self.qnet.state_dict())

        self.optimizer = optim.Adam(self.qnet.parameters(), lr=lr)
        self.loss_fn   = nn.SmoothL1Loss()

    def get_action(self, state_np):
        if random.random() < self.epsilon:
            return random.randrange(self.action_dim)
        s = torch.as_tensor(state_np, dtype=torch.float32, device=self.device).unsqueeze(0)
        with torch.no_grad():
            return int(self.qnet(s).argmax(dim=1).item())

    def learn(self, batch):
        s, a, r, ns, d = zip(*batch)
        s  = torch.as_tensor(np.array(s),  dtype=torch.float32, device=self.device)
        a  = torch.as_tensor(a,  dtype=torch.int64,   device=self.device).unsqueeze(1)
        r  = torch.as_tensor(r,  dtype=torch.float32, device=self.device).unsqueeze(1)
        ns = torch.as_tensor(np.array(ns), dtype=torch.float32, device=self.device)
        d  = torch.as_tensor(d,  dtype=torch.float32, device=self.device).unsqueeze(1)

        q = self.qnet(s).gather(1, a)                      # (B, 1)
        with torch.no_grad():
            q_next = self.qnet_target(ns).max(dim=1, keepdim=True).values
            target = r + self.gamma * q_next * (1.0 - d)

        loss = self.loss_fn(q, target)
        self.optimizer.zero_grad()
        loss.backward()
        self.optimizer.step()
        return float(loss.item())

    def sync_target(self):
        self.qnet_target.load_state_dict(self.qnet.state_dict())
```

### 7.4 학습 루프

Gymnasium 5-tuple 규약에 맞춰 돌립니다.

```python
import numpy as np
import gymnasium as gym

np.random.seed(0)
random.seed(0)
torch.manual_seed(0)

env = gym.make("CartPole-v1")
state_dim = env.observation_space.shape[0]               # 4
action_dim = env.action_space.n                          # 2

agent = DQNAgent(state_dim, action_dim, gamma=0.99, lr=5e-4, epsilon=1.0)
buffer = ReplayBuffer(max_size=50_000)

BATCH = 64
WARMUP = 1_000                                   # 버퍼에 이 정도 스텝이 쌓일 때까지는 학습 생략
EPS_START, EPS_END = 1.0, 0.05
TARGET_SYNC = 10                                 # 에피소드 단위 동기화 주기
TOTAL_EPISODES = 500

reward_history = []
for ep in range(TOTAL_EPISODES):
    # 재현성을 위해 첫 에피소드만 고정 시드, 이후에는 환경 기본 RNG 흐름에 맡깁니다.
    obs, _ = env.reset(seed=0 if ep == 0 else None)
    ep_reward = 0.0

    while True:
        a = agent.get_action(obs)
        next_obs, r, terminated, truncated, _ = env.step(a)
        done = terminated or truncated
        buffer.push((obs, a, r, next_obs, float(done)))
        ep_reward += r
        obs = next_obs

        if len(buffer) >= WARMUP:
            agent.learn(buffer.sample(BATCH))

        if done:
            break

    if ep % TARGET_SYNC == 0:
        agent.sync_target()

    # epsilon decay (선형)
    agent.epsilon = max(EPS_END, EPS_START - (EPS_START - EPS_END) * ep / TOTAL_EPISODES)

    reward_history.append(ep_reward)
    if ep % 20 == 0:
        print(f"ep={ep:>4}  reward={ep_reward:>6.1f}  eps={agent.epsilon:.3f}")

env.close()
```

초반에는 WARMUP 스텝 약 1,000 동안 학습이 이뤄지지 않으므로, 눈에 띄는 성능 향상은 보통 첫 30~50 에피소드 이후에 나타납니다.

이후에는 300 ~ 500 에피소드 안에서 에피소드 보상이 CartPole-v1의 상한 500에 근접하는 구간이 자주 관찰됩니다. 다만 재현성·환경 편차가 있으므로 실제 수렴 속도와 최종 성능은 시드와 하이퍼파라미터에 따라 달라질 수 있습니다.

> [!warning] 연속 상태 · 작은 보상의 안정화 노하우
> - 학습이 불안정하면 `TARGET_SYNC`를 스텝 단위로 바꾸거나 (예: 500 스텝마다) **soft update** ($\theta^- \leftarrow \tau \theta + (1-\tau) \theta^-$)로 교체
> - 버퍼 크기·배치 크기·학습률은 상호 연동이 커서 한 개를 바꾸면 다른 값도 재탐색 필요
> - 보상이 희박한 문제(sparse reward)는 DQN 만으로는 어려움. PER(Prioritized Experience Replay)·Double DQN·Dueling DQN으로 개선

## 8. DQN 이후의 주요 알고리즘

DQN은 강화학습 부흥의 기폭제였지만, 이후에도 발전이 이어졌습니다. 실무에서 자주 마주치는 이름만 짧게 짚어 두겠습니다.

- **Double DQN** (van Hasselt et al., 2016): DQN 타깃의 max 연산이 Q 값을 과대평가하는 편향을 교정. 한 네트워크는 최적 행동 선택, 다른 네트워크는 해당 행동의 Q 값 평가
- **Dueling DQN** (Wang et al., 2016): Q를 상태 가치 $V(s)$와 장점 $A(s, a)$로 분해해 상태 가치 추정의 분산을 줄임
- **PER (Prioritized Experience Replay)**: TD 오차가 큰 경험을 더 자주 뽑아 학습 효율 향상
- **Actor-Critic / A2C / A3C**: 정책(Actor)과 가치(Critic)를 동시 학습. 정책 경사의 분산을 가치 함수로 줄임
- **TRPO / PPO** (Schulman et al.): 정책 업데이트 전후 분포 차이를 **신뢰 영역**으로 제약. PPO는 TRPO의 단순화 버전이자 현재 가장 널리 쓰이는 on-policy 알고리즘
- **DDPG / SAC**: 연속 행동 공간을 다루는 Actor-Critic 계열. 로봇 제어·연속 제어 문제에 표준
- **AlphaGo 계열 (AlphaGo -> AlphaGo Zero -> AlphaZero -> MuZero)**: 자기 대국 + 몬테카를로 트리 탐색 + 딥 함수 근사의 결합

> [!note] 실무 적용 관점
> 강화학습은 "환경 정의"와 "보상 설계"의 난이도가 진입장벽의 대부분입니다. 로봇 제어·반도체 플로어플랜·추천 시스템·데이터센터 냉각 제어 등 의사결정의 순서가 중요한 문제에서 실용 사례가 늘고 있습니다. 이 책에서 다룬 MDP 용어·TD/MC 감각·DQN 구현을 기반으로 필요한 시점에 PPO·DDPG·SAC 같은 알고리즘으로 확장하는 것이 전형적인 학습 경로입니다.
