# 02. 웹 크롤링 - BeautifulSoup과 Selenium

> 텍스트 분석은 이미 쌓인 데이터를 다루는 일처럼 보이지만, 실무 프로젝트는 대개 **데이터 수집**에서 시작됩니다. 이 챕터에서는 웹에서 텍스트를 가져오는 기본 방법을 정리합니다. 정적 페이지에는 BeautifulSoup, 동적 페이지에는 Selenium이 주로 쓰이며, 함께 알아야 할 실무 주의점도 짚습니다.

## 1. 크롤링이 필요한 순간

NLP·시장 조사·가격 비교·리뷰 분석 같은 프로젝트는 모두 "원본 텍스트를 어디서 얻을 것인가"로 시작합니다. 공식 API가 있으면 그쪽이 최우선이지만, API가 없거나 필요한 항목이 빠진 경우 **웹 크롤링**이 현실적인 대안입니다.

크롤링 전 반드시 확인할 것들이 있습니다.

- **robots.txt**: 사이트가 어느 경로의 크롤링을 허용/금지했는지. 예: `https://example.com/robots.txt`
- **이용 약관**: 자동 수집·재배포를 금지하는 조항이 있는지
- **API 존재 여부**: 공식 API·RSS·오픈 데이터셋이 있으면 그쪽 우선
- **요청 빈도**: 짧은 간격 대량 요청은 서버 부담·차단 원인. `time.sleep()`으로 간격 두기

저작권·개인정보 보호·서비스 거부 공격(DoS)으로 오해받을 수 있는 속도 등 **법적·윤리적 경계**를 지키는 것이 실전 크롤링의 전제입니다. 이 챕터의 예시 코드도 공개 뉴스·위키처럼 접근이 열려 있는 페이지를 전제합니다.

## 2. HTML의 구조를 읽는 법

크롤링은 결국 "HTML 문서에서 원하는 조각을 뽑아내는" 일입니다. HTML은 트리 구조입니다.

```html
<html>
  <body>
    <div id="content">
      <h1 class="title">최신 헤드라인</h1>
      <ul>
        <li><a href="/article/1">기사 제목 1</a></li>
        <li><a href="/article/2">기사 제목 2</a></li>
      </ul>
    </div>
  </body>
</html>
```

요소를 **태그(tag)**, 속성을 `class="..."` `id="..."` `href="..."` 처럼 씁니다. 브라우저의 **개발자 도구(F12)**로 실제 페이지 소스를 열어 어떤 태그·클래스가 목표 텍스트를 감싸고 있는지 확인하는 것이 첫 단계입니다.

개발자 도구에서 자주 쓰는 기능:

- 요소 선택(화살표 아이콘): 페이지의 특정 영역을 클릭해 해당 HTML 노드 찾기
- **Copy -> Copy selector**: CSS selector 문자열 획득
- **Copy -> Copy XPath**: XPath 문자열 획득

## 3. BeautifulSoup - 정적 페이지의 표준

**BeautifulSoup**은 HTML/XML 파싱용 파이썬 라이브러리입니다. 서버가 이미 완성된 HTML을 돌려주는 정적 페이지에 잘 맞습니다.

### 3.1 설치와 기본 요청

```bash
pip install requests beautifulsoup4
```

```python
import requests
from bs4 import BeautifulSoup

url = "https://example-news.com/"
resp = requests.get(
    url,
    headers={"User-Agent": "Mozilla/5.0"},   # UA 없이 차단되는 사이트가 많음
    timeout=10,
)
resp.raise_for_status()
soup = BeautifulSoup(resp.text, "html.parser")
```

`html.parser`는 표준 라이브러리 내장이라 설치가 필요 없습니다. 더 관대한 파서가 필요하면 `pip install lxml` 후 `"lxml"`을 선택할 수 있습니다.

### 3.2 요소 찾기

```python
# 가장 자주 쓰는 두 함수
soup.find("h1", class_="title")         # 첫 번째 매칭
soup.find_all("a")                       # 전체 매칭 리스트

# CSS selector 방식
soup.select_one("div#content h1.title")
soup.select("div#content ul li a")

# 텍스트와 속성
a = soup.select_one("ul li a")
a.get_text(strip=True)                   # "기사 제목 1"
a.get("href")                            # "/article/1"
a["href"]                                # 같은 결과, 없으면 KeyError
```

`class_` 뒤에 언더스코어가 붙는 이유는 파이썬 예약어 `class`와 충돌을 피하기 위함입니다.

### 3.3 뉴스 목록에서 본문까지 - 2단계 크롤링 패턴

실무에서 가장 흔한 패턴은 "**목록 페이지에서 기사 URL을 수집 -> 각 URL에서 본문 크롤링**"의 2단계입니다.

```python
import time
import re

LIST_URL = "https://example-news.com/tech/"
UA = {"User-Agent": "Mozilla/5.0"}

# 1) 목록 페이지에서 기사 URL 추출
resp = requests.get(LIST_URL, headers=UA, timeout=10)
soup = BeautifulSoup(resp.text, "html.parser")

article_urls = []
for a in soup.select("ul.article-list li a"):
    href = a.get("href")
    if href:
        # 상대 경로를 절대 경로로
        if href.startswith("/"):
            href = "https://example-news.com" + href
        article_urls.append(href)

# 2) 각 URL에서 제목·본문 수집
def fetch_article(url):
    r = requests.get(url, headers=UA, timeout=10)
    r.raise_for_status()
    s = BeautifulSoup(r.text, "html.parser")

    title = s.select_one("h1.article-title").get_text(strip=True)
    body_nodes = s.select("div.article-body p")
    body = "\n".join(p.get_text(strip=True) for p in body_nodes)

    # 광고·"기자 이메일" 같은 꼬리 제거
    body = re.sub(r"[a-z0-9._-]+@[a-z0-9.-]+", " ", body, flags=re.I)
    body = re.sub(r"\s+", " ", body).strip()
    return {"url": url, "title": title, "body": body}

articles = []
for url in article_urls[:20]:      # 앞 20개만 테스트
    try:
        articles.append(fetch_article(url))
    except Exception as e:
        print("skip:", url, e)
    time.sleep(1.0)                 # 서버 예의: 요청 간격 두기
```

### 3.4 DataFrame으로 저장

수집 결과는 Pandas DataFrame으로 묶어 CSV로 저장하면 이후 분석에 바로 연결됩니다.

```python
import pandas as pd

df = pd.DataFrame(articles)
df.to_csv("articles.csv", index=False, encoding="utf-8-sig")
```

`utf-8-sig`는 한국어를 Excel에서 깨짐 없이 열기 위한 인코딩 팁입니다.

## 4. BeautifulSoup의 한계 - 동적 페이지

BeautifulSoup은 `requests.get()`이 돌려준 HTML **그 자체**만 봅니다. 요즘 사이트들은 대부분 JavaScript로 "페이지 로드 후 데이터를 추가로 불러와 그려 넣는" 구조라, `requests`가 받은 초기 HTML에는 실제 콘텐츠가 없는 경우가 많습니다.

대표적인 증상:

- 브라우저로 보면 기사 목록이 쭉 나오는데 `requests.get().text`에는 빈 컨테이너만
- 로그인이 필요한 페이지
- "더보기" 버튼이나 무한 스크롤로 콘텐츠가 점진적으로 추가되는 페이지
- 검색어 입력·필터 클릭 등 사용자 상호작용이 필요한 페이지

이런 페이지는 초기 HTML만 읽어서는 원하는 데이터를 얻기 어렵습니다. 즉, BeautifulSoup만으로는 해결되지 않는 경우가 많습니다.

해결책은 크게 두 가지입니다.

- **내부 API 역공학**: 개발자 도구 "Network" 탭에서 실제 데이터가 오가는 JSON 엔드포인트를 찾아 `requests`로 직접 호출. 성공하면 가장 빠른 경로
- **Selenium 같은 브라우저 자동화**: 실제 브라우저를 띄워 JS를 실행한 뒤의 결과 HTML을 읽어 옴

첫 번째가 가능하면 우선이지만, 많은 사이트가 CSRF 토큰·서명 파라미터 등으로 보호되어 쉽지 않습니다. 두 번째가 범용 해법입니다.

## 5. Selenium - 브라우저 자동화

**Selenium**은 실제 브라우저(Chrome·Firefox 등)를 프로그램이 조작하게 해 주는 도구입니다. JS 실행·클릭·스크롤·로그인까지 사람의 조작을 거의 그대로 자동화할 수 있습니다.

### 5.1 설치

```bash
pip install selenium
```

최근의 Selenium **4.6 이상**에는 **Selenium Manager**가 내장돼 있어, 크롬 드라이버를 수동으로 내려받지 않아도 자동으로 잡아 주는 경우가 많습니다.

구버전 Selenium을 쓴다면 `webdriver-manager` 같은 보조 패키지를 쓰거나 드라이버 바이너리를 수동으로 지정해야 할 수 있습니다.

도커·CI 같이 'root'로 크롬을 띄우는 환경에서는 샌드박스 초기화 에러가 날 수 있습니다. 이때는 `opts.add_argument("--no-sandbox")`를 추가해 우회할 수 있지만, 일반 데스크톱에서는 보안 샌드박스를 끄는 효과가 있으므로 기본값으로 두지 않는 편이 좋습니다.

### 5.2 기본 패턴

```python
from selenium import webdriver
from selenium.webdriver.common.by import By
from selenium.webdriver.chrome.options import Options

opts = Options()
opts.add_argument("--headless=new")        # 창 없이 백그라운드 실행 (Chrome 109+)
opts.add_argument("user-agent=Mozilla/5.0")

driver = webdriver.Chrome(options=opts)
driver.get("https://example-news.com/tech/")

# 로드 후 DOM에 렌더된 요소 조회
titles = driver.find_elements(By.CSS_SELECTOR, "h2.article-title")
for t in titles:
    print(t.text)

driver.quit()
```

`find_element` / `find_elements`는 CSS selector·XPath·id·class 등 다양한 **locator 전략**을 받습니다.

| locator | 사용 예 | 특징 |
|---|---|---|
| `By.CSS_SELECTOR` | `div.article h2` | 가장 일반적. BeautifulSoup과 같은 감각 |
| `By.XPATH` | `//div[@class='article']/h2` | 강력·세밀, 문법 따로 배움 필요 |
| `By.ID` | `title-main` | 빠름, 'id'가 있을 때만 |
| `By.CLASS_NAME` | `article-title` | 단일 클래스명 매칭만 가능 |
| `By.LINK_TEXT` | `"더보기"` | 링크 텍스트 정확히 일치 |

개발자 도구의 **Copy XPath**를 그대로 받아 쓰되, 페이지 구조가 조금만 바뀌면 깨지는 긴 XPath보다 **의미 있는 class·data 속성** 기반 XPath를 직접 쓰는 쪽이 안정적입니다.

### 5.3 입력·클릭과 로그인 자동화

```python
from selenium.webdriver.support.ui import WebDriverWait
from selenium.webdriver.support import expected_conditions as EC

driver.get("https://example.com/login")

# 명시적 대기: 특정 요소가 나타날 때까지
id_box = WebDriverWait(driver, 10).until(
    EC.presence_of_element_located((By.ID, "userid"))
)
id_box.send_keys("my-id")
driver.find_element(By.ID, "password").send_keys("my-password")
driver.find_element(By.CSS_SELECTOR, "button[type='submit']").click()

# 로그인 후 페이지 이동 대기
WebDriverWait(driver, 10).until(
    EC.url_contains("/mypage")
)
```

`WebDriverWait` + `expected_conditions` 조합이 Selenium 실전의 핵심입니다. `time.sleep()`을 쓰면 네트워크 속도에 따라 실패하기 쉽고, 너무 오래 기다리면 느려집니다. "요소가 보일 때까지 최대 N 초" 식의 **명시적 대기**가 안정적입니다.

### 5.4 무한 스크롤 처리

유튜브 댓글·트위터 타임라인처럼 아래로 스크롤해야 추가 콘텐츠가 로드되는 페이지는 JavaScript를 직접 실행해 스크롤을 내립니다.

```python
import time

driver.get("https://example-video.com/watch?v=xxx")

last_height = driver.execute_script("return document.body.scrollHeight")
while True:
    driver.execute_script("window.scrollTo(0, document.body.scrollHeight);")
    time.sleep(2)    # 새 콘텐츠 로드 대기

    new_height = driver.execute_script("return document.body.scrollHeight")
    if new_height == last_height:
        break        # 더 이상 늘어나지 않으면 끝
    last_height = new_height

# 이 시점에서 driver.page_source에 전체 댓글이 로드된 상태
```

### 5.5 iframe 안쪽 크롤링

페이지 속에 `<iframe>`으로 다른 문서가 박혀 있는 경우, 그 안의 요소는 기본 driver로 접근할 수 없습니다. 먼저 iframe으로 전환해야 합니다.

```python
driver.switch_to.frame("iframe-name-or-id")
# 이제 iframe 내부 요소 조회 가능
driver.find_element(By.CSS_SELECTOR, "div.inner")

driver.switch_to.default_content()       # 원래 페이지로 복귀
```

## 6. Selenium + BeautifulSoup 결합 패턴

둘을 함께 쓰면 각자의 장점을 살릴 수 있습니다. Selenium으로 **페이지를 렌더** 하고, 그 결과 HTML을 **BeautifulSoup에 넘겨 파싱** 하는 흐름입니다.

```python
from bs4 import BeautifulSoup

# Selenium으로 페이지 로드
driver.get(url)
time.sleep(2)

# 렌더된 HTML을 BeautifulSoup에 전달
soup = BeautifulSoup(driver.page_source, "html.parser")
titles = [t.get_text(strip=True)
          for t in soup.select("h2.article-title")]
```

BeautifulSoup의 편안한 파싱 API를 그대로 쓰면서 JS 렌더링 문제만 Selenium으로 우회하는 실무 관용 패턴입니다. 속도는 느리지만 구현·디버깅이 간단해 처음 작성할 때 특히 유리합니다.

## 7. 실전 체크리스트

웹 크롤러를 실제로 운영하기 전에 살펴보면 좋은 항목입니다.

- **요청 예의**: `time.sleep(1~2)` 기본. 동시 요청은 `aiohttp`·`asyncio`로 제어하되 초당 수십 건 이상은 피함
- **재시도·타임아웃**: 네트워크 실패가 흔하므로 `requests`에 `timeout` 필수, `tenacity` 같은 라이브러리로 지수 백오프
- **캐싱**: 같은 URL을 반복 요청하지 않도록 로컬에 HTML을 저장
- **User-Agent·세션**: `requests.Session()`으로 쿠키·헤더 유지
- **로그·모니터링**: 수집된 아이템 수, 실패 URL, 응답 상태 코드
- **저장 포맷**: 분석용은 CSV/Parquet, 원본 아카이브는 HTML 그대로 저장
- **법·윤리**: robots.txt 준수, 개인정보 최소 수집, 수집 허용 범위 초과 시 중단

## 마무리

웹 크롤링은 NLP 프로젝트의 "재료 수급" 단계입니다. 정적 페이지에는 가벼운 BeautifulSoup, 동적 페이지·사용자 상호작용이 필요한 경우에는 Selenium 또는 두 도구의 결합이 기본 선택지입니다. 기술보다 더 중요한 것은 **크롤링 예의와 법적 경계**를 지키는 태도입니다.

다음 챕터에서는 이렇게 수집한 텍스트를 재료로 **감성 분석**을 수행합니다. 사전 기반 접근과 지도학습 기반 접근, 한국어·영어 차이를 함께 살펴봅니다.
