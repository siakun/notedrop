# 01. 웹 서비스 기초 - Flask와 HTML로 모델 서빙

> Jupyter Notebook에서 학습한 AI 모델은 **개발자 자신**만 쓸 수 있는 상태입니다. 사용자에게 모델을 내보내려면 HTTP 요청을 받아 예측값을 돌려주는 구조가 필요하고, 그 표준이 **웹 서비스** 입니다.
>
> Part 8은이 관점에서 접근합니다. 이 챕터에서는 웹 서버·WAS 개념, HTML 최소 지식, Flask 라우팅·템플릿, form 처리를 먼저 정리합니다. 다음 챕터에서 Chart.js 시각화와 실제 AI 모델 서빙으로 이어집니다.

## 1. 왜 AI 개발자가 웹을 알아야 하는가

Jupyter의 시각화·출력은 **개발자용** 입니다. 사용자용 인터페이스의 사실상 표준은 HTML 이고, 학습된 모델을 `.pkl`로 저장해 둔다고 그 자체로 서비스가 되는 것은 아닙니다. 세 가지 사슬이 이어져야 비로소 AI 서비스가 됩니다.

- **URL 경로**를 받아 파이썬 함수를 호출하는 **웹 프레임워크** (Flask)
- 사용자가 입력·결과를 보는 **HTML** 화면
- 학습된 모델을 **파일로 저장** 하고 요청 시 로드해 `predict`만 호출하는 서빙 패턴

AI 생태계가 파이썬 중심이라 학습 코드와 웹 서버를 **같은 언어**로 엮는 쪽이 배포가 쉽습니다. 그래서 Flask·FastAPI가 AI 서빙의 기본 선택지가 됩니다. Node.js·Go 같은 다른 언어의 웹 서버에서 파이썬 모델을 쓰려면 프로세스 간 통신이나 모델 재구현 비용이 크게 늘어납니다.

## 2. 웹 서버와 WAS

### 2.1 서버와 클라이언트

- **서버**: 데이터와 로직을 보관하고 요청에 응답하는 쪽
- **클라이언트**: 서버에 요청을 보내고 응답을 화면에 그려 주는 쪽 (브라우저·모바일 앱 등)

웹 페이지의 고정 레이아웃은 보통 클라이언트가 가진 HTML에 포함돼 있고, 게시물처럼 **계속 바뀌는 데이터**는 서버가 가진 DB에서 가져옵니다. 인터넷이 끊기면 홈페이지가 열리지 않는 이유는 데이터 본체가 서버에 있기 때문입니다.

### 2.2 WEB 서버와 WAS

| 구분 | 역할 | 예시 |
|---|---|---|
| WEB 서버 | 정적 자원(HTML·이미지·CSS 등) 응답 | Apache, Nginx |
| WAS (Web Application Server) | DB 조회·비즈니스 로직·AI 모델 추론 등 동적 처리 | Tomcat, WebLogic, **Flask + Gunicorn** |

클라이언트 요청은 먼저 WEB 서버로 들어오고, 정적 자원은 즉시 응답됩니다. 동적 처리가 필요한 요청만 WAS로 넘어가 결과가 WEB 서버를 거쳐 돌아옵니다. 현대 배포에서는 두 역할을 하나의 서버가 겸하는 경우가 많아, 실질적으로는 "앞단 Nginx + 뒷단 Flask"의 2단 구조가 일반적입니다.

### 2.3 스케일링과 로드 밸런싱

한 대의 서버로 동시 접속자 수천 명을 감당하기 어려운 순간이 옵니다. 대응은 두 갈래입니다.

- **Scale-up**: 서버 한 대의 성능을 키움 (비용 급증, 한계 명확)
- **Scale-out**: 값싼 서버 여러 대에 트래픽을 나눔 (로드 밸런싱 필요)

대표 로드 밸런서가 Nginx 입니다. 알고리즘은 라운드 로빈, 가중 라운드 로빈, 최소 연결, IP 해시 등 환경에 맞는 것을 고릅니다.

> [!warning] Flask의 동시성 한계
> Flask의 기본 개발 서버 (`app.run()`)는 싱글 스레드에 가깝습니다. 요청 하나에 10 초가 걸리는 엔드포인트에 100 명이 동시 접속하면 마지막 사람은 약 1,000 초를 기다려야 합니다. 실제 배포에서는 **Gunicorn** 같은 WSGI 게이트웨이에 Flask를 올려 프로세스·스레드 풀을 띄우거나, 비동기가 핵심이면 **FastAPI + Uvicorn**을 선택지로 고려합니다. 이 챕터에서는 개발 서버로 실습하지만 배포 체크리스트는 머리에 담아 두세요.

## 3. HTML 최소 지식

### 3.1 실습 환경

에디터는 Part 1 Ch 01에서 설치한 **VSCode**를 그대로 씁니다. Python 확장 외에 HTML 편집에 도움이 되는 `HTML CSS Support` (퍼블리셔 ecmel)와 `Live Preview` (Microsoft 공식) 두 가지만 추가로 설치하면 편집 창 옆에서 HTML 렌더 결과를 바로 볼 수 있습니다.

### 3.2 기본 문서 구조

```html
<!doctype html>
<html lang="ko">
<head>
  <meta charset="utf-8">
  <title>첫 HTML</title>
</head>
<body>
  <h1>Hello</h1>
  <p>웹 서비스의 시작 문서입니다.</p>
</body>
</html>
```

- **doctype**: 이 문서가 HTML5 임을 브라우저에 선언
- **html**: 루트 태그. `lang="ko"`로 기본 언어 지정
- **head**: 화면에 보이지 않는 메타 정보 (title·meta·link·script)
- **body**: 실제로 렌더되는 영역

태그 이름은 소문자로 쓰고, 여는 태그와 닫는 태그를 짝 맞춥니다. `<br>`, `<img>`, `<hr>` 같이 내용이 없는 빈 태그는 닫지 않습니다. 속성은 `src="경로"` 처럼 `이름="값"` 형태로 적습니다. UTF-8 인코딩(`<meta charset="utf-8">`)은 한글 서비스에서 사실상 필수입니다.

### 3.3 AI 서비스에 필요한 최소 태그 세트

HTML은 수십 개 태그가 있지만 모델 서빙 UI에 바로 쓰이는 건 다음 정도입니다.

| 분류 | 태그 | 역할 |
|---|---|---|
| 제목·문단 | `<h1>~<h6>`, `<p>` | 제목 크기별 계층, 문단 |
| 줄 바꿈·구분 | `<br>`, `<hr>` | 줄 바꿈, 수평 구분선 |
| 인라인 강조 | `<strong>`, `<em>` | 의미론적 강조 (화면 낭독기가 인식) |
| 목록 | `<ul>`, `<ol>`, `<li>` | 불릿·번호 리스트 |
| 표 | `<table>`, `<tr>`, `<th>`, `<td>` | 격자형 데이터 |
| 이미지·링크 | `<img>`, `<a>` | 그림, 하이퍼링크 |
| 폼 | `<form>`, `<input>`, `<label>` | 사용자 입력 |
| 그룹 | `<div>`, `<span>` | 블록·인라인 영역 묶기 |

현대 레이아웃은 `<table>`이 아닌 `<div>` + CSS 조합이 표준입니다. `<table>`은 순수하게 격자 데이터 (게시판·통계표·예측 결과 표시 등) 에만 씁니다.

#### 표 태그 기본 구조

```html
<table border="1">
  <thead>
    <tr><th>이름</th><th>전공</th><th>학년</th></tr>
  </thead>
  <tbody>
    <tr><td>홍길동</td><td>컴퓨터공학</td><td>3</td></tr>
    <tr><td colspan="2">주소: 서울시 ...</td><td>-</td></tr>
  </tbody>
</table>
```

- `<tr>` 한 줄, `<td>` / `<th>` 한 셀. `<th>`는 제목 셀로 굵게 가운데 정렬됨
- `colspan="N"`은 가로로 N 개 열 병합, `rowspan="N"`은 세로로 N 개 행 병합. 병합한 만큼 옆의 원래 셀은 **삭제** 해야 열 개수가 맞습니다
- `<thead>`, `<tbody>`, `<tfoot>`은 시각 효과가 없지만 접근성·스크롤 제어에 의미론적 역할을 합니다
- 각 `<tr>`은 열 개수가 일정해야 합니다 (병합을 고려한 뒤에도)

AI 서비스에서는 예측 결과를 행 단위로 나열하는 표를 자주 씁니다. Ch 02에서 Jinja `{% for %}` 루프와 결합해 반복 출력 패턴을 다룹니다.

### 3.4 이미지와 하이퍼링크

```html
<img src="static/iris.jpg" alt="붓꽃 사진" width="200">
<a href="/predict" target="_blank">예측 페이지 열기</a>
```

- `<img>`의 `alt`는 이미지 로드 실패 시 대체 텍스트이자 화면 낭독기가 읽는 내용. 생략하지 마세요.
- `<a>`의 `target="_blank"`는 새 탭에서 열기. 기본값 `_self`는 현재 창에서 이동. 외부 URL을 새 탭으로 열 때는 보안상 `rel="noopener noreferrer"`를 함께 두는 것이 표준입니다.
- Flask 앱에서는 **정적 파일** (이미지·CSS·JS)을 `static/` 폴더에 두고 `/static/파일명`으로 접근합니다.

### 3.5 폼 (form)

AI 서비스의 핵심은 사용자 입력을 서버로 넘기는 폼입니다.

```html
<form action="/predict" method="post">
  <label for="sl">꽃받침 길이</label>
  <input type="text" id="sl" name="sl">
  <label for="sw">꽃받침 너비</label>
  <input type="text" id="sw" name="sw">
  <label for="pl">꽃잎 길이</label>
  <input type="text" id="pl" name="pl">
  <label for="pw">꽃잎 너비</label>
  <input type="text" id="pw" name="pw">
  <input type="submit" value="예측">
</form>
```

- `action`: 제출 시 호출할 URL (Flask 라우트)
- `method`: GET 또는 POST (뒤의 "GET vs POST" 절에서 설명)
- `<input name="sl">`의 `name`이 서버에서 값을 꺼낼 때 쓰는 **키**
- `<label for="sl">` + `<input id="sl">` 처럼 id로 **명시적 연결** 하는 방식을 권장합니다. `<label>`로 `<input>`을 감싸는 암묵적 방식도 동작하지만, 화면 낭독기 호환성과 모바일 터치 타깃 확장 측면에서 명시적 연결이 안전합니다.

## 4. Flask 기초

### 4.1 설치와 최소 앱

```bash
pip install flask
```

```python
# app.py
from flask import Flask

app = Flask(__name__)

@app.route("/")
def index():
    return "Hello World!"

if __name__ == "__main__":
    app.run(host="127.0.0.1", port=5000, debug=True)
```

터미널에서 `python app.py`로 실행한 뒤 브라우저에서 `http://127.0.0.1:5000/`에 접속하면 "Hello World!"가 보입니다. `debug=True`는 코드 수정 시 자동 재시작과 상세 에러 페이지를 제공합니다. 배포 시에는 반드시 `False`로 바꿔야 합니다 (디버거를 통한 원격 코드 실행 위험).

> [!warning] 파일명 주의
> 작업 폴더에 `flask.py`가 있으면 `from flask import Flask`가이 파일 자신을 import 하려 해서 순환 오류가 납니다. 앱 파일명은 `app.py`가 관례입니다.

### 4.2 라우팅

URL 경로와 파이썬 함수를 묶는 것이 `@app.route` 데코레이터입니다.

```python
@app.route("/")
def index():
    return "Hello World"

@app.route("/about")
def about():
    return "서비스 소개"

@app.route("/board/writing")
def board_writing():
    return "글쓰기"
```

- 경로는 반드시 `/`로 시작
- 같은 화면을 여러 경로로 내려 주려면 `@app.route`를 두 개 쌓으면 됩니다
- 함수 이름은 중복되지 않게 유지 (내부 엔드포인트 이름으로 쓰임)

### 4.3 host와 port

```python
app.run(host="127.0.0.1", port=5000)
```

- `host="127.0.0.1"` (루프백): 같은 컴퓨터에서만 접속 가능. 외부 공개 시 `0.0.0.0` 또는 고정 IP로 변경
- `port=5000`: 포트 번호. 개발 단계는 5000·8080이 관례

한 대의 컴퓨터에서 여러 네트워크 프로그램이 동시에 동작하므로, 들어오는 패킷을 **어느 프로그램에 전달할지 구분하는 번호**가 포트입니다.

| 포트 | 용도 |
|---|---|
| 80 | HTTP (브라우저가 생략해도 자동 적용) |
| 443 | HTTPS |
| 3306 | MySQL |
| 5000 · 8080 | 개발 임시 포트 관례 |

80 포트는 OS·다른 웹 서버와 충돌할 수 있어 개발 중에는 피합니다.

### 4.4 가변 URL

URL 경로 자체에 변수를 꽂아 여러 페이지를 라우트 하나로 처리할 수 있습니다.

```python
@app.route("/user/<username>")
def show_user(username: str):
    return f"안녕하세요 {username} 님"

@app.route("/post/<int:post_id>")
def show_post(post_id: int):
    return f"글 번호 {post_id}"
```

- `<username>`: 기본 `string` 타입
- `<int:post_id>`: 정수로 제한 (문자가 들어오면 404)
- 그 외 타입 컨버터: `float`, `path`, `uuid`

### 4.5 requests로 클라이언트 테스트

Flask 서버를 켜 둔 채 별도 파이썬 세션에서 `requests`로 호출해 응답을 확인할 수 있습니다.

```python
import requests

r = requests.get("http://127.0.0.1:5000/")
print(r.status_code)    # 200
print(r.text)           # Hello World!
```

대표 HTTP 상태 코드는 200 (정상), 404 (URL 없음), 500 (서버 내부 에러) 입니다.

## 5. 템플릿 렌더링 (render_template)

### 5.1 templates 폴더 규칙

Flask는 **`app.py`와 같은 디렉터리의 `templates/` 폴더**에서 HTML을 찾습니다. 폴더 이름은 정확히 `templates`로 고정돼 있습니다.

```
my_app/
├── app.py
├── static/              # 이미지·CSS·JS (선택)
└── templates/
    ├── hello.html
    └── iris_form.html
```

### 5.2 기본 사용

```python
from flask import Flask, render_template

app = Flask(__name__)

@app.route("/hello")
def hello():
    return render_template("hello.html")
```

```html
<!-- templates/hello.html -->
<!doctype html>
<html>
<body>
  <h1>Hello</h1>
  <a href="/">홈으로</a>
</body>
</html>
```

### 5.3 변수 전달과 Jinja 표현식

`render_template`의 키워드 인자로 값을 넘기면 템플릿 안에서 `{{ 변수 }}`로 꺼낼 수 있습니다. 템플릿 엔진은 **Jinja2** 입니다.

```python
@app.route("/greet")
def greet():
    return render_template("greet.html", name="홍길동", age=29)
```

```html
<p>안녕하세요 {{ name }} 님, 나이는 {{ age }} 입니다.</p>
```

Jinja의 세 가지 문법을 기억해 두세요.

| 구문 | 용도 | 예 |
|---|---|---|
| `{{ ... }}` | 표현식 출력 | `{{ name }}`, `{{ age + 1 }}` |
| `{% ... %}` | 제어 흐름 | `{% if %}`, `{% for %}` |
| `{# ... #}` | 주석 (렌더 안 됨) | `{# TODO 나중에 채우기 #}` |

### 5.4 조건문과 반복문

```html
{% if label == "setosa" %}
  <p>Setosa 품종입니다.</p>
{% elif label == "versicolor" %}
  <p>Versicolor 품종입니다.</p>
{% else %}
  <p>Virginica 품종입니다.</p>
{% endif %}

<ul>
{% for item in items %}
  <li>{{ item }}</li>
{% endfor %}
</ul>

<table>
{% for k, v in row.items() %}
  <tr><td>{{ k }}</td><td>{{ v }}</td></tr>
{% endfor %}
</table>
```

파이썬 문법과 거의 같지만 블록을 `{% endif %}`, `{% endfor %}`로 **명시적으로 닫는다**는 점이 차이입니다. HTML 편집기에서 들여쓰기가 불안정한 점을 보완하는 설계입니다.

## 6. Form과 request

### 6.1 request.form 기본

사용자가 폼 submit 버튼을 누르면 `<form action>`의 URL로 POST 요청이 갑니다. Flask는 `request.form`으로 값을 받습니다.

```python
from flask import Flask, request, render_template

app = Flask(__name__)

@app.route("/form")
def form():
    return render_template("form.html")

@app.route("/submit", methods=["POST"])
def submit():
    data = request.form                    # ImmutableMultiDict (dict 처럼 쓰면 됨)
    return render_template("result.html", data=data)
```

```html
<!-- templates/form.html -->
<form action="/submit" method="post">
  <label>이름 <input type="text" name="name"></label>
  <label>나이 <input type="text" name="age"></label>
  <input type="submit" value="전송">
</form>
```

```html
<!-- templates/result.html -->
<h2>받은 값</h2>
<ul>
{% for k, v in data.items() %}
  <li>{{ k }}: {{ v }}</li>
{% endfor %}
</ul>
```

개별 값은 `request.form["name"]` 또는 `request.form.get("name", "")`로 꺼냅니다. 존재 여부가 불확실한 필드는 `.get` 쪽이 안전합니다 (없으면 기본값 반환).

### 6.2 타입 변환은 필수

`<input>`에서 숫자를 입력해도 서버에 도착하는 값은 **항상 문자열** 입니다. 산술·모델 입력에 쓰려면 반드시 `int()`·`float()`로 캐스팅해야 합니다.

```python
@app.route("/predict", methods=["POST"])
def predict():
    sl = float(request.form["sl"])
    sw = float(request.form["sw"])
    pl = float(request.form["pl"])
    pw = float(request.form["pw"])
    # 이제 sl, sw, pl, pw를 numpy 배열로 묶어 모델.predict에 넣을 수 있습니다
    ...
```

타입 캐스팅을 빠뜨리면 `TypeError: can only concatenate str (not "int") to str` 처럼 쉽게 오류가 납니다.

### 6.3 GET vs POST

| 방식 | 데이터 위치 | 특성 | 주 용도 |
|---|---|---|---|
| GET | URL 쿼리스트링 (`?key=value` 형태) | 캐시·북마크 가능, URL에 노출 | 공개 조회, 검색 |
| POST | HTTP body | URL 노출 없음, 캐시 안 됨 | 로그인, 모델 입력, 파일 업로드 |

GET도 HTTPS 위에서는 암호화될 수 있습니다. 하지만 URL은 서버 로그나 Referer 헤더 등에 남기 쉬워 노출 위험이 여전히 있습니다.

그래서 민감 정보는 POST가 관례입니다. AI 예측 요청도 입력값의 개인정보 포함 여부와 무관하게 POST를 기본으로 삼는 편이 좋습니다.

## 7. 한 URL에서 GET/POST 분기

하나의 라우트가 "제출 전에는 입력 폼, 제출 후에는 결과 메시지" 두 역할을 겸하도록 만드는 패턴입니다. 로그인 페이지처럼 같은 URL을 쓰는 흐름에 적합합니다.

```python
@app.route("/login", methods=["GET", "POST"])
def login():
    msg = ""
    if request.method == "POST":
        user = request.form.get("id", "")
        pw   = request.form.get("pw", "")
        if user and pw:
            msg = f"로그인 성공 (ID: {user})"
        elif user or pw:
            msg = "아이디와 비밀번호를 모두 입력해 주세요."
        else:
            msg = "입력값이 없습니다."
    return render_template("login.html", msg=msg)
```

```html
<!-- templates/login.html -->
<form action="/login" method="post">
  <input type="text"     name="id" placeholder="아이디">
  <input type="password" name="pw" placeholder="비밀번호">
  <input type="submit" value="로그인">
</form>

{% if msg %}<p>{{ msg }}</p>{% endif %}
```

| 시나리오 | 메서드 | id | pw | msg |
|---|---|---|---|---|
| 첫 진입 | GET | - | - | (빈 값, 메시지 숨김) |
| 둘 다 입력 | POST | abc | 123 | "로그인 성공 (ID: abc)" |
| 하나만 입력 | POST | abc | - | "아이디와 비밀번호를 모두..." |
| 둘 다 빈칸 | POST | - | - | "입력값이 없습니다." |

실무에서는이 패턴보다는 GET 라우트와 POST 라우트를 별도로 분리하는 편이 흔합니다. 다만 `request.method`로 분기하는 개념 자체는 다른 웹 프레임워크에도 공통이므로 기억해 두면 좋습니다.

## 8. 참고 - AJAX 맛보기

지금까지 다룬 폼 전송은 **페이지 전체가 새로 로드** 됩니다. 결과 영역 일부만 갱신하고 싶거나 페이지 이동 없이 JSON을 주고받고 싶다면 **AJAX (Asynchronous JavaScript and XML)** 방식이 표준입니다. Flask 쪽에서는 `request.get_json()`으로 JSON body를 받고 `jsonify`로 돌려주는 조합이면 됩니다.

```python
from flask import Flask, request, jsonify, render_template

app = Flask(__name__)

@app.route("/ajax_page")
def ajax_page():
    return render_template("ajax.html")

@app.route("/ajax", methods=["POST"])
def ajax():
    data = request.get_json()           # JSON body -> dict
    data["server_note"] = "processed"   # 서버가 값을 살짝 보태 돌려줌
    return jsonify(result="ok", echo=data)
```

```html
<!-- templates/ajax.html -->
<input type="text" id="msg" placeholder="보낼 메시지">
<button id="send">전송</button>
<pre id="resp"></pre>

<script>
  document.getElementById("send").onclick = async () => {
    const res = await fetch("/ajax", {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({ msg: document.getElementById("msg").value }),
    });
    const data = await res.json();
    document.getElementById("resp").textContent = JSON.stringify(data, null, 2);
  };
</script>
```

브라우저 `fetch` API는 현대 표준이라 별도 라이브러리 없이 바로 쓸 수 있습니다. 결과가 페이지 리로드 없이 `<pre id="resp">` 영역에만 나타나는 점이 기존 form 방식과의 핵심 차이입니다. 이 패턴의 확장(실시간 갱신·차트 연동·서버 푸시)은 다음 챕터(Part 8 Ch 02)에서 SSE와 함께 본격적으로 다룹니다.
