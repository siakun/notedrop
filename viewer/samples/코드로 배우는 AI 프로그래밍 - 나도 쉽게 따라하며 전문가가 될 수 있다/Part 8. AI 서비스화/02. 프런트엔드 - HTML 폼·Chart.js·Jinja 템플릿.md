# 02. 프런트엔드 - HTML 폼·Chart.js·Jinja 템플릿

> Ch 01에서 만든 Flask 라우트와 최소 HTML 위에 **사용자 UI**를 덧붙여 AI 서비스다운 인터페이스를 만들 차례입니다.
>
> 이 챕터는 흐름이 분명합니다. 먼저 입력 UI를 확장하고, 그 다음 결과를 Chart.js로 시각화합니다. 이어서 Jinja 템플릿 상속으로 공통 레이아웃을 재사용하고, 마지막으로 **SSE (Server-Sent Events)**로 실시간 갱신까지 연결합니다.

## 1. 앵커 링크 - 같은 페이지 내 내비게이션

`<a href="...">` 링크는 다른 페이지뿐 아니라 **같은 페이지 안의 특정 위치** 로도 이동할 수 있습니다. 긴 문서의 목차, "맨 위로" 버튼 같은 UX에 쓰이는 기본 패턴입니다.

핵심은 **id 기반 점프**. `href`에 `#id이름`을 적으면 해당 id를 가진 요소로 스크롤됩니다.

```html
<ul>
  <li><a href="#intro">서비스 소개</a></li>
  <li><a href="#predict">예측 체험</a></li>
  <li><a href="#about">개발자 정보</a></li>
</ul>

<h2 id="intro">서비스 소개</h2>
<p>...</p>

<h2 id="predict">예측 체험</h2>
<p>...</p>

<h2 id="about">개발자 정보</h2>
<p>...</p>
```

> [!note] 앵커 링크 규칙
> `href`에 해시 기호(`#`) + 대상 요소의 `id`를 붙이면 한 페이지 안에서 점프합니다. "해시 + id 연결" 딱 두 가지만 기억하면 됩니다.

## 2. 고급 폼 - 입력 타입과 접근성

앞에서 본 기본 폼과 GET/POST 처리 위에, 여기서는 **의미에 맞는 input 타입**과 **그룹화·접근성**을 더해 완성도 높은 폼을 만드는 법을 봅니다.

### 2.1 label의 두 가지 사용 방식

Ch 01에서 권장한 **명시적 연결** 방식입니다. id로 묶으면 화면 낭독기 호환성·터치 타깃 확장에 유리합니다.

```html
<label for="userid">아이디</label>
<input type="text" id="userid" name="userid">
```

`<label>`로 `<input>`을 감싸는 **암묵적 연결** 방식도 동작은 같습니다. 간단한 경우 한 줄로 쓸 수 있어 편합니다.

```html
<label>아이디 <input type="text" name="userid"></label>
```

> [!example] label이 살리는 UX
> 체크박스·라디오 버튼은 네모·동그라미 영역만 작게 클릭 대상이 됩니다. `<label>`로 글자를 묶어 두면 **글자 영역까지 클릭 가능** 해집니다. 설문 페이지가 답답하게 느껴지는 주된 원인이 `<label>` 누락입니다.

### 2.2 `<fieldset>`과 `<legend>`로 그룹화

관련 입력 요소를 하나로 묶고 제목을 붙이는 구조입니다. 브라우저가 자동으로 테두리 박스와 제목을 그려 줍니다.

```html
<fieldset>
  <legend>개인 정보</legend>
  <label for="email">이메일</label>
  <input type="email" id="email" name="email">
  <label for="userid">아이디</label>
  <input type="text"  id="userid" name="userid">
  <label for="pw">비밀번호</label>
  <input type="password" id="pw" name="pw">
</fieldset>
```

접근성 도구에도 같은 묶음이 하나의 폼 그룹으로 전달되어 화면 낭독기 사용자가 "개인 정보 폼" 단위로 인식할 수 있습니다.

### 2.3 input 공통 속성

가장 먼저 알아야 할 두 가지가 `name`과 `value` 입니다.

| 속성 | 역할 |
|---|---|
| name | 서버에 전달될 때의 키 (Flask의 `request.form["name"]`) |
| value | 초기값 또는 사용자가 입력·선택한 값 |
| size | 화면에 보이는 입력칸 너비 (문자 수 기준) |
| maxlength | 최대 입력 가능 문자 수 |
| hidden (type) | 화면에 안 보이지만 서버로 값 함께 전달 |

> [!warning] size의 함정
> `size`는 "화면에 보이는 글자 수" 이지 "입력 제한"이 아닙니다. 게다가 영문은 1, 한글은 2로 계산되어 `size=5`로 해도 한글이 그만큼 안 보일 수 있습니다. 입력을 실제로 제한하려면 `maxlength`를 씁니다.

`type="hidden"`은 사용자가 보지 않지만 서버로 함께 전달되는 값입니다. 두 로그인 폼을 같은 URL로 보낼 때 어느 쪽인지 구분하거나, 어느 게시판에서 온 제출인지 식별할 때 씁니다.

```html
<input type="hidden" name="board_id" value="free">
```

### 2.4 text 계열 타입

HTML5는 의미에 맞는 여러 input 타입을 제공합니다. 브라우저가 자동으로 유효성 검사·전용 UI를 붙여 주는 점이 장점입니다.

| type | 설명 | 브라우저 동작 |
|---|---|---|
| text | 일반 텍스트 | 제약 없음 |
| search | 검색 상자 | 입력 중 x 버튼 제공 |
| password | 비밀번호 | 마스킹 표시 |
| url | URL 입력 | 제출 시 형식 검사 |
| email | 이메일 | @ 포함 간단 검사 |
| tel | 전화번호 | 의미 표시용 (엄격 검사는 없음) |
| number | 숫자 | 스피너, `min·max·step` 지원 |
| range | 범위 슬라이더 | 슬라이더 UI |

```html
<input type="number" name="age"   min="0"  max="100" step="1" value="20">
<input type="range"  name="level" min="0"  max="10"  step="2" value="4">
```

### 2.5 radio vs checkbox

| 구분 | 선택 개수 | name 규칙 |
|---|---|---|
| radio | 그룹에서 **1 개만** | 같은 그룹은 name을 **동일** 하게 |
| checkbox | **여러 개** 가능 | 독립 항목이면 name을 다르게, 같은 그룹이면 name을 공유 가능 |

```html
<label><input type="radio" name="subject" value="grammar">문법</label>
<label><input type="radio" name="subject" value="conversation">회화</label>

<label><input type="checkbox" name="mail1" value="news">뉴스</label>
<label><input type="checkbox" name="mail2" value="event">이벤트</label>
<label><input type="checkbox" name="mail3" value="tips">팁</label>
```

라디오는 같은 `name`을 공유해야 "하나의 선택 그룹"으로 묶입니다. 위 체크박스 예제는 **독립 항목** 이라 `name`을 다르게 둔 경우입니다. 여러 선택값을 하나의 키로 묶고 싶다면 같은 `name`을 공유하고 서버에서 `request.form.getlist(...)`로 받는 방식도 흔합니다. 서버에는 **체크된 항목의 name, value 만** 도착합니다.

### 2.6 color, date, reset, image

```html
<input type="color" name="mycolor" value="#ff0000">

<input type="date"           name="birthday">
<input type="month"          name="month">
<input type="time"           name="meeting">
<input type="datetime-local" name="due">

<input type="reset" value="초기화">
<input type="image" src="static/submit.png" alt="제출">
```

`type="color"`는 색상 선택기 UI를 띄우고 `#RRGGBB` 형식으로 전달합니다. 날짜·시간 계열은 브라우저가 달력·시계 위젯을 제공하므로 별도 JavaScript 없이 입력 UI가 완성됩니다. `reset`은 모든 입력을 **초기 value**로 되돌립니다 (빈 값이 아닙니다).

### 2.7 폼 부가 속성

| 속성 | 동작 |
|---|---|
| autofocus | 페이지 로드 시 해당 입력칸에 자동 포커스 |
| placeholder | 입력 전 회색 힌트 텍스트, 타이핑 시 사라짐 |
| readonly | 수정 불가. value는 서버로 그대로 전송 |
| required | 필수 입력. 비어 있으면 제출 차단 |

```html
<input type="email" name="email" autofocus placeholder="이메일 입력" required>
<input type="text"  name="id" value="USER001" readonly>
```

`readonly`는 게시글 작성자·등록 시각처럼 **서버가 아는 값을 화면에 표시하되 변경을 막고 싶을 때** 유용합니다.

### 2.8 `<select>`, `<textarea>`, `<button>`

```html
<select name="major">
  <option value="cs">컴퓨터공학과</option>
  <option value="ee" selected>전자공학과</option>
  <option value="me">기계공학과</option>
</select>

<select name="hobby" multiple>
  <option value="book">독서</option>
  <option value="movie">영화</option>
  <option value="game">게임</option>
</select>

<textarea name="content" cols="40" rows="10"></textarea>

<button type="submit">
  <img src="static/go.png" alt=""> 제출하기
</button>
```

- `selected`: 초기 선택 항목
- `multiple`: 여러 항목 동시 선택 허용 (UX가 복잡해 실무에서는 잘 안 씀)
- `<textarea>`: 여러 줄 평문 입력. `cols`·`rows`로 크기 지정
- `<button>`: `<input type="submit">`과 기능은 같지만 **안쪽에 이미지·서식이 포함된 자식 태그**를 넣을 수 있어 커스텀 버튼에 유리

## 3. Chart.js 기초

AI 예측 결과를 숫자로만 나열하기보다 **차트**로 시각화하면 이해가 훨씬 쉬워집니다. **Chart.js**는 간단하면서도 유연한 자바스크립트 차트 라이브러리입니다 (chartjs.org).

### 3.1 CDN 로드와 캔버스

```html
<head>
  <title>My Chart</title>
  <script src="https://cdn.jsdelivr.net/npm/chart.js@4"></script>
</head>
```

본문에 `<canvas>` 태그로 그림 영역을 잡고, 그 id를 JS에서 `getContext('2d')`로 받아 `new Chart(...)`에 넘깁니다.

```html
<canvas id="myChart" width="480" height="300"></canvas>

<script>
  const ctx = document.getElementById("myChart").getContext("2d");

  const config = {
    type: "bar",
    data: {
      labels: ["Red", "Blue", "Yellow", "Green", "Purple", "Orange"],
      datasets: [{
        label: "# of Votes",
        data: [12, 19, 3, 5, 2, 3],
        backgroundColor: "rgba(255, 99, 132, 0.2)",
        borderColor:     "rgba(255, 99, 132, 1)",
        borderWidth: 1,
      }],
    },
    options: {
      scales: {
        y: { beginAtZero: true },
      },
    },
  };

  const myChart = new Chart(ctx, config);
</script>
```

### 3.2 config의 3 대 필드

| 키 | 역할 |
|---|---|
| type | 차트 종류. `line`·`bar`·`radar`·`doughnut`·`pie`·`polarArea`·`bubble`·`scatter` 중 하나 |
| data.labels | x 축 라벨 배열 |
| data.datasets | 시리즈 배열. 여러 개 겹쳐 그릴 수 있음 |
| datasets[i].label | 범례 이름 |
| datasets[i].data | y 값 배열 |
| datasets[i].backgroundColor | 채움 색 |
| datasets[i].borderColor | 테두리·선 색 |
| options.scales.y.beginAtZero | y 축을 0부터 시작할지 |

`rgba(R, G, B, A)`의 A는 투명도(0 ~ 1). 0.2는 연한 파스텔, 1.0은 불투명입니다.

### 3.3 여러 데이터셋 겹치기

`datasets` 배열에 객체를 추가하면 시리즈를 겹쳐 그릴 수 있습니다. `labels`는 공용이라 하나만 유지합니다.

```javascript
datasets: [
  { label: "A", data: [12, 19, 3, 5, 2, 3], borderColor: "red" },
  { label: "B", data: [10,  1, 13,15,21,13], borderColor: "blue" },
]
```

### 3.4 제목과 축 라벨

```javascript
options: {
  plugins: {
    title: { display: true, text: "차트 타이틀" },
  },
  scales: {
    x: { title: { display: true, text: "색상" } },
    y: {
      beginAtZero: true,
      title: { display: true, text: "투표 수" },
    },
  },
}
```

## 4. Chart.js 동적 조작

차트를 사용자 액션(버튼 클릭) 이나 타이머로 **갱신** 하려면 `config.data`를 수정한 뒤 `myChart.update()`를 호출합니다.

### 4.1 버튼으로 데이터 변경·추가·삭제

```html
<canvas id="chart" style="max-width:480px;"></canvas>
<div>
  <button id="reData">데이터 변경</button>
  <button id="addData">데이터 추가</button>
  <button id="addDataSet">데이터셋 추가</button>
  <button id="delData">데이터 삭제</button>
  <button id="delDataSet">데이터셋 삭제</button>
</div>

<script src="https://cdn.jsdelivr.net/npm/chart.js@4"></script>
<script>
  const ctx = document.getElementById("chart").getContext("2d");
  const config = {
    type: "line",
    data: {
      labels: [0, 1, 2, 3, 4, 5],
      datasets: [{
        label: "chart1",
        data: [12, 19, 10, 10, 10, 10],
        borderColor: "red",
      }],
    },
    options: { scales: { y: { beginAtZero: true } } },
  };
  const myChart = new Chart(ctx, config);

  // 전체 데이터를 랜덤 값으로 덮어쓰기
  document.getElementById("reData").onclick = () => {
    for (const ds of config.data.datasets) {
      ds.data = ds.data.map(() => Math.random() * 50);
    }
    myChart.update();
  };

  // 마지막에 라벨·값 하나씩 추가
  document.getElementById("addData").onclick = () => {
    const labels = config.data.labels;
    labels.push(labels.length ? labels[labels.length - 1] + 1 : 0);
    for (const ds of config.data.datasets) {
      ds.data.push(Math.floor(Math.random() * 50));
    }
    myChart.update();
  };

  // 새 데이터셋(라인) 추가
  document.getElementById("addDataSet").onclick = () => {
    config.data.datasets.push({
      label: `chart${config.data.datasets.length + 1}`,
      data: config.data.labels.map(() => Math.random() * 50),
      borderColor: `hsl(${Math.random() * 360}, 70%, 50%)`,
    });
    myChart.update();
  };

  // 마지막 데이터 값 / 마지막 데이터셋 삭제
  document.getElementById("delData").onclick = () => {
    config.data.labels.pop();
    for (const ds of config.data.datasets) ds.data.pop();
    myChart.update();
  };
  document.getElementById("delDataSet").onclick = () => {
    config.data.datasets.pop();
    myChart.update();
  };
</script>
```

핵심 패턴은 **`config.data.labels`·`datasets[i].data`를 직접 조작한 뒤 `myChart.update()` 호출** 입니다.

> [!warning] 빈 상태에서 addData의 엣지 케이스
> 데이터를 전부 삭제한 뒤 `addData`를 누르면 `labels[-1]`이 `undefined`가 되어 `undefined + 1 = NaN`이 됩니다. 위 코드는 `labels.length` 체크로 방어해 뒀습니다. 디버깅은 `console.log`로 확인합니다 (브라우저 F12 -> Console 탭).

> [!warning] labels 타입 함정
> 초기 `labels`를 `["0","1","2","3","4","5"]` 처럼 **문자열** 배열로 두면 `labels[last] + 1`이 `"51"` 같은 **문자열 연결** 결과가 되어 축이 망가집니다. 숫자 라벨이 필요하면 처음부터 `[0, 1, 2, 3, 4, 5]`로 숫자를 넣으세요.

### 4.2 setInterval로 자동 갱신

주기적으로 값을 흔드는 라이브 차트 예시입니다.

```javascript
setInterval(() => {
  for (const ds of config.data.datasets) {
    for (let i = 0; i < ds.data.length; i++) {
      ds.data[i] += Math.random() * 2 - 1;         // -1 ~ +1 변동
    }
  }
  myChart.update();
}, 1000);                                          // 1,000 ms = 1 초
```

`setInterval`의 두 번째 인자는 **밀리초** 단위입니다. 이 구조에 뒤의 SSE를 얹으면 서버가 보낸 AI 예측 결과로 실제 라이브 차트가 완성됩니다.

## 5. Jinja 템플릿 상속

앞에서 본 Jinja 기본 문법 위에, 이제는 서비스 규모가 커질 때 필요한 **템플릿 상속**을 얹습니다. 헤더·푸터·공통 레이아웃을 매 페이지에 복붙하는 문제를이 기능이 해결합니다.

### 5.1 베이스 템플릿 정의

```html
<!-- templates/base.html -->
```

`{% block 이름 %}...{% endblock %}`은 **자식 템플릿이 덮어쓸 수 있는 구멍** 입니다.

### 5.2 자식 템플릿

```html
<!-- templates/predict.html -->
{% extends "base.html" %}

{% block title %}예측 결과 - AI 서비스{% endblock %}

{% block content %}
  <h2>예측 결과</h2>
  <p>입력한 꽃은 <strong>{{ label }}</strong> 품종입니다.</p>

  <table>
    <tr><th>특성</th><th>값</th></tr>
    {% for k, v in features.items() %}
      <tr><td>{{ k }}</td><td>{{ v }}</td></tr>
    {% endfor %}
  </table>
{% endblock %}
```

`{% extends %}`로 부모를 지정하고, 필요한 `block`만 덮어씁니다. 헤더·푸터·스크립트 로드 같은 공통 요소는 베이스에서 한 번만 유지하면 됩니다.

### 5.3 url_for로 경로 관리

Flask가 제공하는 `url_for`는 라우트 함수 이름을 받아 URL을 돌려줍니다. 배포 시 라우트 경로가 바뀌어도 템플릿을 수정할 필요가 없습니다.

```html
<a href="{{ url_for('index') }}">홈</a>
<a href="{{ url_for('predict_form') }}">예측 체험</a>
<img src="{{ url_for('static', filename='iris.jpg') }}" alt="붓꽃">
```

정적 파일은 `static` 엔드포인트로 접근합니다 (`static/` 폴더 규약).

## 6. 실시간 통신 개요

지금까지의 폼 전송·`render_template` 방식은 한 번 요청하면 **페이지 전체가 새로 로드** 됩니다. 차트에 서버의 최신 값을 계속 흘려 넣거나, 알림·피드를 리로드 없이 갱신하려면 **실시간 통신** 패턴이 필요합니다.

### 6.1 HTTP는 1 회성

HTTP 한 번의 교환은 "요청(Request) -> 응답(Response)" 단발로 끝납니다. 주고받은 뒤 연결이 닫히고 서버·클라이언트는 서로 독립 상태가 됩니다. 이 1 회성을 우회해 지속 통신을 흉내 내는 세 방식이 있습니다.

| 방식 | 방향 | 메커니즘 | 대표 용도 |
|---|---|---|---|
| Polling | 클라이언트 -> 서버 (반복 요청) | 일정 주기로 `fetch` 반복 | 저빈도 상태 확인 |
| SSE (Server-Sent Events) | 서버 -> 클라이언트 (단방향) | 한 번 연결 후 서버가 지속 전송 | 실시간 차트, 알림 피드 |
| WebSocket | 양방향 | TCP 기반 영구 연결 | 채팅, 멀티플레이 게임 |

> [!warning] 방향성 정리
> Polling·SSE는 **단방향** 입니다. Polling은 클라이언트가 서버를 계속 찌르고, SSE는 서버가 클라이언트로 계속 밀어 보냅니다. 양방향이 필요하면 WebSocket을 선택합니다.

AI 서비스 맥락에서는 "서버가 예측 결과를 브라우저로 계속 밀어 주기"가 가장 흔한 패턴이라 **SSE가 가성비가 가장 좋습니다**. 구현 코드가 짧고 HTML 쪽도 `EventSource` 한 줄이면 끝납니다.

## 7. SSE 실습 - 서버 시각 실시간 전송

가장 단순한 SSE 예시로, 서버가 1 초마다 현재 시각을 `yield`로 흘려 보내고 브라우저가 이를 `<div>`에 표시합니다.

### 7.1 Flask 서버

```python
# app.py
from flask import Flask, Response, render_template
from datetime import datetime
import time

app = Flask(__name__)

def time_stream():
    while True:
        now = datetime.now().isoformat(timespec="seconds")
        yield f"data: {now}\n\n"                     # SSE 포맷: 'data: ...\n\n'
        time.sleep(1)

@app.route("/sse_page")
def sse_page():
    return render_template("sse.html")

@app.route("/sse")
def sse():
    return Response(time_stream(), mimetype="text/event-stream")

if __name__ == "__main__":
    app.run(host="127.0.0.1", port=5000)
```

> [!note] SSE의 필수 규약
> - `mimetype="text/event-stream"` 필수
> - 한 이벤트 포맷은 `"data: <내용>\n\n"` (개행 두 번이 한 이벤트의 끝)
> - `return`이 아닌 `yield`로 지속 전송 (제너레이터)

### 7.2 HTML 측

```html
<!-- templates/sse.html -->
<!doctype html>
<html>
<body>
  <p>서버 시각: <span id="now"></span></p>
  <script>
    const src = new EventSource("/sse");
    src.onmessage = (e) => {
      document.getElementById("now").textContent = e.data;
    };
  </script>
</body>
</html>
```

브라우저의 `EventSource`가 `/sse` 경로를 구독하고, 서버가 `yield` 할 때마다 `onmessage`가 호출됩니다. 페이지 전체 리로드 없이 `<span>`의 내부 텍스트만 바뀌는 점이 핵심입니다.

## 8. SSE + Chart.js - 실시간 차트

앞에서 본 Chart.js 동적 조작 위에 SSE를 얹으면 **서버가 보낸 값을 자동으로 끝에 이어 그리는** 라이브 차트가 됩니다.

### 8.1 Flask 서버 - 랜덤 정수 스트림

```python
# app.py에 추가
import random

def value_stream():
    while True:
        yield f"data: {random.randint(0, 50)}\n\n"
        time.sleep(1)

@app.route("/chart_sse_page")
def chart_sse_page():
    return render_template("chart_sse.html")

@app.route("/chart_sse")
def chart_sse():
    return Response(value_stream(), mimetype="text/event-stream")
```

실제 서비스에서는 `value_stream` 안에서 모델 `predict` 결과나 DB의 최근 값을 읽어 `yield` 합니다.

### 8.2 HTML - 수신 즉시 차트에 push

```html
<!-- templates/chart_sse.html -->
{% extends "base.html" %}
{% block content %}
  <h2>실시간 차트</h2>
  <canvas id="liveChart" style="max-width:640px;"></canvas>

  <script>
    const ctx = document.getElementById("liveChart").getContext("2d");
    const config = {
      type: "line",
      data: {
        labels: [],
        datasets: [{ label: "실시간 값", data: [], borderColor: "blue" }],
      },
      options: { animation: false, scales: { y: { beginAtZero: true } } },
    };
    const chart = new Chart(ctx, config);

    let tick = 0;
    const src = new EventSource("/chart_sse");
    src.onmessage = (e) => {
      const value = Number(e.data);
      if (Number.isNaN(value)) return;             // 숫자 아닌 메시지 무시
      config.data.labels.push(tick++);
      config.data.datasets[0].data.push(value);

      // 최근 20 개만 유지하는 슬라이딩 윈도
      if (config.data.labels.length > 20) {
        config.data.labels.shift();
        config.data.datasets[0].data.shift();
      }
      chart.update();
    };
  </script>
{% endblock %}
```

1 초마다 라벨에 카운터를 push 하고 데이터셋에 서버가 보낸 값을 push 한 뒤 `chart.update()`만 호출하면 끝입니다. `animation: false`는 매 갱신마다 깜빡임을 줄여 주는 옵션입니다.

> [!info] 통신 범위 주의
> Ch 01에서 본 `render_template`은 **Flask 서버 <-> HTML 태그** 간 통신이었습니다. 반면 Chart.js는 **브라우저 JavaScript 안**에서 동작하는 라이브러리입니다. 둘을 잇는 다리가 바로 SSE (또는 AJAX/WebSocket) 입니다. 이 구분을 명확히 해 두면 실시간 기능의 디버깅이 훨씬 쉬워집니다.
