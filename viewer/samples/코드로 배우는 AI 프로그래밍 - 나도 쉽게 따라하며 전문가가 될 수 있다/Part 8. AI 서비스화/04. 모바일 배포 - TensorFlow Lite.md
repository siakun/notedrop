# 04. 모바일 배포 - TensorFlow Lite

> 서버 기반 서빙은 인터넷 연결이 필요하고, 매 요청마다 네트워크 왕복이 생깁니다. 그래서 지연, 프라이버시, 오프라인 동작이 중요한 경우에는 **기기가 모델을 직접 들고 로컬에서 추론하는 방식**, 즉 **온디바이스(on-device) 추론**이 필요합니다.
>
> 이 챕터에서는 그 표준 도구인 **TensorFlow Lite(TFLite)**를 다룹니다. Keras 모델을 `.tflite`로 변환하고, 양자화로 경량화하고, 로컬 Python에서 검증한 뒤, 안드로이드 앱에서 실제로 호출하는 흐름까지 따라가 봅니다.

## 1. 온디바이스 추론이 필요한 이유

서버 서빙 (Ch 03)과 온디바이스 추론은 대체재가 아니라 각자 적합한 상황이 다릅니다.

| 관점 | 서버 서빙 (Flask/FastAPI) | 온디바이스 추론 (TFLite) |
|---|---|---|
| 네트워크 | 필수 | 불필요 (오프라인 동작) |
| 지연 | 왕복 + 서버 처리 시간 | 기기 CPU/GPU 추론 시간만 |
| 프라이버시 | 원본 데이터가 서버로 전송 | 원본 데이터가 기기 밖으로 안 나감 |
| 하드웨어 | 서버 GPU 무제한 활용 가능 | 기기 메모리·연산 한계 |
| 모델 업데이트 | 서버 배포로 즉시 반영 | 앱 업데이트 필요 |
| 스케일링 | 트래픽에 따라 비용 증가 | 단말 수만큼 자동 분산 |

사진 필터, 실시간 번역, 음성 웨이크워드 탐지처럼 **저지연·프라이버시·오프라인** 요건이 강한 응용에는 온디바이스가 유리합니다. 반대로 대형 언어모델이나 빈번한 재학습이 필요한 모델은 서버 쪽이 자연스럽습니다. 실무에서는 **두 방식을 섞어 쓰는** 하이브리드도 많습니다 (간단한 전처리·분류는 단말, 어려운 예측은 서버).

## 2. TensorFlow Lite 개요

TFLite는 구글이 만든 **모바일·임베디드용 경량 TensorFlow 런타임** 입니다. 원본 TensorFlow (`tf.keras` 등) 모델을 `.tflite` 플랫 버퍼 포맷으로 변환하면 다음 장점이 생깁니다.

- **작은 바이너리**: 런타임이 원본 TF보다 훨씬 가볍습니다 (수 MB 수준)
- **빠른 추론**: 그래프 최적화·고정 shape·양자화로 단말 CPU 에서도 실용 속도
- **풍부한 타깃**: 안드로이드·iOS·라즈베리파이·마이크로컨트롤러까지 지원

전체 배포 흐름은 이렇게 정리됩니다.

```text
[학습 환경]
  Keras 모델 (.h5 또는 SavedModel)
    │
    │ TFLiteConverter.from_keras_model(...)
    │ (선택) post-training quantization
    ▼
  .tflite 파일
    │
    │ (복사)
    ▼
[모바일 앱]
  Interpreter로 .tflite 로드
    │ 이미지 전처리 (리사이즈·정규화)
    ▼
  set_tensor / invoke / get_tensor
    │ 출력 logits / 확률
    ▼
  UI에 결과 표시
```

## 3. Keras -> TFLite 변환 기본

여기서는 이미 학습된 **6-class 분류 모델**이 하나 있다고 가정하겠습니다. 예를 들어 캔, 유리, 종이, 플라스틱, 비닐, 일반쓰레기를 분류하는 모델입니다.

구체적으로는 Part 5 Ch 04에서 다룬 전이학습 방식으로 ResNet50을 fine-tuning 한 모델이라고 생각하면 됩니다.

### 3.1 기본 변환

```python
import tensorflow as tf

# model: tf.keras.Model 이미 학습·fit 완료된 상태
converter = tf.lite.TFLiteConverter.from_keras_model(model)
tflite_model = converter.convert()

with open("recycle_classifier.tflite", "wb") as f:
    f.write(tflite_model)

print("saved:", len(tflite_model) // (1024 * 1024), "MB")
```

`convert()` 한 번이면 끝이지만, 이 기본 변환은 **원본 float32 가중치를 그대로** 옮기므로 파일 크기가 별로 줄지 않습니다 (ResNet50 기준 약 100 MB 내외, 정확한 크기는 모델·버전에 따라 다름). 실제 모바일 배포에는 다음 절의 양자화가 사실상 필수입니다.

### 3.2 SavedModel 로부터 변환

학습과 변환을 다른 세션에서 하려면 중간에 SavedModel을 거칩니다.

```python
# 1) 학습 스크립트에서 저장
# TF 2.16+ (Keras 3) 에서는 model.export가 SavedModel 출력용 권장 API 입니다.
model.export("saved_resnet50_recycle")

# 2) 변환 스크립트에서 로드 + 변환
converter = tf.lite.TFLiteConverter.from_saved_model("saved_resnet50_recycle")
tflite_model = converter.convert()
```

SavedModel은 서명(signature), 자산(assets), 변수까지 묶어 저장하는 표준 포맷입니다. `from_keras_model`이 메모리에 있는 Keras 객체에서 직접 변환하는 방식이라면, `from_saved_model`은 디스크에 저장된 모델을 대상으로 변환하므로 CI와 재현성 관점에서 더 깔끔합니다.

구형 Keras 2 환경에서는 `model.save("경로")`가 같은 폴더 단위 SavedModel을 만들어 줍니다. 반면 Keras 3의 `model.save("file.keras")`는 단일 파일 포맷이 기본이므로, 변환 파이프라인에서는 `model.export`를 쓰는 편이 더 명확합니다.

## 4. 양자화 (Quantization)

양자화는 가중치·활성값을 **더 작은 수치 타입**으로 줄여 모델 크기와 추론 시간을 동시에 개선하는 기법입니다. TFLite가 기본으로 지원하는 세 가지를 비교하면 다음과 같습니다.

| 방식 | 가중치 타입 | 활성값 | 필요 데이터 | 일반 크기 감소 | 정확도 영향 |
|---|---|---|---|---|---|
| Dynamic range | int8 | float32 | 없음 | 약 1/4 | 거의 없음 |
| Float16 | float16 | float16 | 없음 | 약 1/2 | 거의 없음 |
| Full integer (int8) | int8 | int8 | 대표 데이터셋 필수 | 약 1/4 | 소폭 감소 (보정 필요) |

가장 빠르고 안전하게 쓸 수 있는 것이 **dynamic range quantization** 입니다. 데이터셋 없이 가중치만 int8로 압축하고 추론 시 필요한 부분만 float로 되돌려 계산합니다.

### 4.1 Dynamic range 양자화

```python
converter = tf.lite.TFLiteConverter.from_keras_model(model)
converter.optimizations = [tf.lite.Optimize.DEFAULT]
tflite_q = converter.convert()

with open("recycle_classifier_q.tflite", "wb") as f:
    f.write(tflite_q)
```

한 줄 (`converter.optimizations = [tf.lite.Optimize.DEFAULT]`) 만으로 가중치가 int8로 압축됩니다. ResNet50 기준 FP32 약 100 MB -> 양자화 후 25 ~ 30 MB 수준으로, 보통 3 ~ 4 배 축소됩니다 (정확한 수치는 직접 변환 후 측정 권장).

### 4.2 Float16 양자화

GPU 가속기를 가진 단말(아이폰·일부 안드로이드 플래그십) 에서는 float16이 크기를 절반으로 줄이면서도 정확도 손실이 거의 없고, float 연산이 GPU에서 그대로 가속되어 유리합니다.

```python
converter = tf.lite.TFLiteConverter.from_keras_model(model)
converter.optimizations = [tf.lite.Optimize.DEFAULT]
converter.target_spec.supported_types = [tf.float16]
tflite_fp16 = converter.convert()
```

### 4.3 Full integer 양자화 (활성값까지 int8)

마이크로컨트롤러·엣지 TPU 처럼 float 연산이 느리거나 없는 하드웨어에서는 활성값까지 int8로 만들어야 합니다. 이를 위해 **대표 데이터셋(representative dataset)**으로 활성값의 분포를 추정해야 합니다.

```python
import numpy as np
from tensorflow.keras.applications.resnet50 import preprocess_input

def representative_data_gen():
    # 실제 학습 이미지 중 100~500 장을 학습 시 전처리와 동일하게 통과시켜 내보냅니다.
    # ResNet50 (caffe) 전처리는 평균 -128 근처 값이 나오므로 rand() 더미는 활성값 분포를
    # 왜곡합니다. 아래는 뼈대만 보여주는 placeholder - 실제로는 train 데이터 로더를 사용하세요.
    for _ in range(100):
        x = np.random.rand(1, 224, 224, 3).astype(np.float32) * 255.0
        yield [preprocess_input(x)]

converter = tf.lite.TFLiteConverter.from_keras_model(model)
converter.optimizations = [tf.lite.Optimize.DEFAULT]
converter.representative_dataset = representative_data_gen
# 순수 int8 하드웨어가 아니면 fallback을 허용해 변환 실패를 피합니다.
converter.target_spec.supported_ops = [
    tf.lite.OpsSet.TFLITE_BUILTINS_INT8,
    tf.lite.OpsSet.TFLITE_BUILTINS,
]
converter.inference_input_type = tf.int8
converter.inference_output_type = tf.int8
tflite_int8 = converter.convert()
```

`representative_data_gen` 에는 **실제 학습 데이터** 100 ~ 500 장을 **학습 시 전처리와 똑같이 적용한 뒤** 반복자로 내보내야 합니다. 대표 데이터셋은 실제 전처리된 학습 샘플이어야 한다는 점이 핵심입니다.

랜덤 더미로 돌리면 활성값 분포가 실제와 달라 양자화 정확도가 크게 떨어질 수 있습니다. 정확도가 민감한 문제에서는 양자화 전후 평가 스크립트를 돌려 허용 범위인지 확인하는 단계도 필수입니다.

> [!info] 언제 어느 양자화를 쓸까
> - 빠르게 크기만 줄이고 싶다: **dynamic range**
> - GPU 가속 단말이 타깃이다: **float16**
> - 엣지 TPU·MCU 등 int 전용 하드웨어: **full integer**
> - 양자화 후 정확도 저하가 커서 학습 단계부터 고려하고 싶다: **QAT (Quantization Aware Training)**. 학습 중에 가짜 양자화 노드를 삽입해 가중치를 int8 친화적 분포로 유도하는 방식으로, Post-Training Quantization 만으로 품질이 안 나올 때 다음 카드입니다.

## 5. 변환한 `.tflite` Python에서 검증

앱에 올리기 전에 같은 PC에서 `.tflite`를 로드해 동작을 확인하는 단계가 있어야 디버깅이 수월합니다. `tensorflow` 패키지에 포함된 `tf.lite.Interpreter`로 간단히 됩니다.

```python
import numpy as np
import tensorflow as tf
from tensorflow.keras.preprocessing import image
from tensorflow.keras.applications.resnet50 import preprocess_input

interpreter = tf.lite.Interpreter(model_path="recycle_classifier_q.tflite")
interpreter.allocate_tensors()

in_det  = interpreter.get_input_details()[0]
out_det = interpreter.get_output_details()[0]

# 이미지 전처리 (모델이 학습된 전처리와 동일해야 합니다)
img = image.load_img("sample_can.jpg", target_size=(224, 224))
x = image.img_to_array(img)
x = np.expand_dims(x, axis=0).astype(np.float32)
x = preprocess_input(x)

interpreter.set_tensor(in_det["index"], x)
interpreter.invoke()
probs = interpreter.get_tensor(out_det["index"])[0]

# ImageDataGenerator.flow_from_directory는 클래스 폴더명을 알파벳순으로 인덱싱합니다.
# 학습 때와 동일한 정렬 순서인지 반드시 확인한 뒤 사용하세요.
CLASSES = sorted(["can", "glass", "paper", "plastic", "trash", "vinyl"])
top = int(np.argmax(probs))
print(f"예측: {CLASSES[top]} (확률 {probs[top]:.3f})")
```

전처리가 학습 시와 **완전히 같아야** 한다는 점이 핵심입니다 (ResNet50의 경우 `preprocess_input`으로 ImageNet 평균 빼기가 필수). 이 단계에서 분류가 의도대로 나와야 모바일 앱 쪽 코드도 같은 전처리를 구현해 일치시킬 수 있습니다.

> [!warning] 모바일 용으로만 돌린다면 tflite_runtime
> 모바일·엣지 기기에서 Python 기반 추론을 돌린다면 `tensorflow` 전체가 아니라 경량 `tflite_runtime` 패키지만 설치해도 됩니다. 디스크 용량이 훨씬 작아 라즈베리파이에 올릴 때 유리합니다.

## 6. 안드로이드 앱에 배포

변환한 `.tflite`를 실제 안드로이드 앱에서 호출하는 순서를 큰 그림으로 정리합니다. 구체적 UI·권한 처리는 플랫폼 공식 문서가 훨씬 상세하므로 여기서는 **AI 부분의 뼈대**만 추립니다.

### 6.1 프로젝트 세팅

1. 안드로이드 스튜디오 새 프로젝트 생성 (언어는 Kotlin 권장).
2. `recycle_classifier_q.tflite` 파일을 `app/src/main/assets/` 폴더에 복사.
3. 모듈 `build.gradle`에 TFLite 의존성을 추가합니다.


### 6.2 저수준 API - `Interpreter` 직접 호출

```kotlin
import android.graphics.Bitmap
import org.tensorflow.lite.Interpreter
import java.nio.ByteBuffer
import java.nio.ByteOrder

class RecycleClassifier(assetManager: android.content.res.AssetManager) {
    private val interpreter: Interpreter

    init {
        val fileDescriptor = assetManager.openFd("recycle_classifier_q.tflite")
        val inputStream = java.io.FileInputStream(fileDescriptor.fileDescriptor)
        val channel = inputStream.channel
        val modelBuffer = channel.map(
            java.nio.channels.FileChannel.MapMode.READ_ONLY,
            fileDescriptor.startOffset,
            fileDescriptor.declaredLength,
        )
        interpreter = Interpreter(modelBuffer)
    }

    fun classify(bitmap: Bitmap): FloatArray {
        val resized = Bitmap.createScaledBitmap(bitmap, 224, 224, true)
        val input = ByteBuffer.allocateDirect(4 * 224 * 224 * 3).apply {
            order(ByteOrder.nativeOrder())
            rewind()
            for (y in 0 until 224) for (x in 0 until 224) {
                val px = resized.getPixel(x, y)
                val r = (px shr 16 and 0xFF).toFloat()
                val g = (px shr  8 and 0xFF).toFloat()
                val b = (px        and 0xFF).toFloat()
                // ResNet50 preprocess_input (caffe): RGB -> BGR 순으로 채널을 뒤집고
                // ImageNet 평균 [103.939, 116.779, 123.68]을 각 채널에서 뺍니다.
                putFloat(b - 103.939f)
                putFloat(g - 116.779f)
                putFloat(r - 123.68f)
            }
        }
        val output = Array(1) { FloatArray(6) }
        interpreter.run(input, output)
        return output[0]
    }
}
```

카메라·갤러리에서 받은 `Bitmap`을 `classify`에 넘기면 6 개 클래스에 대한 확률 배열이 돌아옵니다. UI 쪽에서는 `argmax`로 최상위 클래스 라벨을 사용자에게 보여 주고, 필요한 경우 "캔은 내용물 비우고 배출해 주세요" 같은 안내 문구를 매핑하면 됩니다.

### 6.3 고수준 API - Task Library

`tensorflow-lite-task-vision`은 이미지 분류용 고수준 래퍼 (`ImageClassifier`)를 제공해 전처리·후처리를 대부분 자동화합니다. 사전학습 모델이 "모델 메타데이터"를 포함하도록 변환돼 있으면 리사이즈·정규화를 라이브러리가 알아서 처리하므로 코드가 수십 줄 짧아집니다. 운영 앱에서는 이쪽을 기본으로 고려합니다.

## 7. iOS · 라즈베리파이 · 웹

안드로이드 외 플랫폼도 같은 `.tflite` 파일을 공유합니다.

- **iOS**: CocoaPods `TensorFlowLiteSwift`나 SwiftPM의 `TensorFlowLiteTaskVision`을 의존성으로 추가. Core ML이 더 Apple 친화적이지만 크로스플랫폼 기준 모델을 유지하기에는 TFLite가 편합니다.
- **라즈베리파이**: 위에서 언급한 `tflite_runtime`만 설치해 Python 스크립트로 바로 추론 가능. Coral Edge TPU를 붙이면 int8 양자화 모델을 하드웨어 가속할 수 있습니다.
- **웹**: **TensorFlow.js**가 자매 프로젝트로 있어 `.tflite`가 아닌 `tfjs` 포맷으로 변환해 씁니다. 크기 제약이 커 초경량 모델이 주 대상입니다.

## 8. 베스트 프랙티스

| 관심사 | 권장 |
|---|---|
| 모델 크기 | Dynamic range 양자화를 **기본값**으로 (한 줄 변경, 3~4 배 감소) |
| 정확도 검증 | 양자화 전후를 **같은 검증 세트**로 비교, 허용 범위 안인지 확인 |
| 전처리 일관성 | 학습 시 전처리 함수(resize·mean subtraction·정규화)를 모바일 측에서 **똑같이 재구현** |
| 모델 메타데이터 | `tflite-support`의 `MetadataWriter`로 라벨·정규화 정보를 파일에 내장 |
| 번들링 | `noCompress 'tflite'`로 APK 압축 제외, `gzip` 재압축 오버헤드 방지 |
| 업데이트 | 앱 버전과 독립적으로 모델만 교체하려면 서버에서 내려받아 내부 저장소에 저장하는 구조 채택 |
| 성능 측정 | `Interpreter` 생성 비용은 앱 시작 시 한 번만, `run()` 지연은 기기별로 측정 |
| 실패 처리 | 모델 로드 실패, 권한 실패, OOM에 대한 UI fallback을 반드시 준비 |

## 9. Part 8 마무리와 본편 전체 정리

Part 8 에서는 AI 모델을 **서비스**까지 엮는 전 과정을 훑었습니다.

| Ch | 주제 | 핵심 |
|---|---|---|
| 01 | Flask·HTML 기초 | URL에 함수를 묶고 HTML로 결과를 돌려주기 |
| 02 | 프런트엔드 | 폼 고급·Chart.js·Jinja 상속·SSE 실시간 차트 |
| 03 | AI 모델 서빙 실전 | joblib 저장·Flask 라우트·REST JSON API |
| 04 | TensorFlow Lite | 온디바이스 추론, 양자화, 안드로이드 배포 |

본편 Part 1 ~ Part 8은 이렇게 이어집니다.

- Part 1: 파이썬·NumPy·Pandas로 **언어 도구**를 갖춤
- Part 2: 기호주의 AI (규칙·퍼지·탐색·유전)로 **AI의 고전 계보**를 이해
- Part 3: 전통 머신러닝으로 **데이터 -> 모델** 루틴 확립
- Part 4: 딥러닝 기초 (MLP·CNN·RNN)로 **표현 학습**의 감각
- Part 5: 컴퓨터 비전·XAI로 **이미지·설명 가능성**
- Part 6: 자연어처리로 **텍스트 분석 파이프라인**
- Part 7: 강화학습으로 **순차 의사결정**을 모델링
- Part 8: AI 서비스화로 **배포**까지 이어 "쓸 수 있는 모델" 완성

각 Part는 독립적으로 읽어도 되지만, 순서대로 읽으면 "데이터를 어떻게 모델로 바꾸고, 그 모델을 어떻게 서비스로 내보내는가"라는 한 가지 흐름이 관통합니다. 부록 (A 윤리·B 블록체인 메타버스·C AWS 클라우드)은 본편의 기술 주제 바깥에서 AI를 둘러싼 맥락을 보강하는 역할을 합니다.
