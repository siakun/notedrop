# 03. 탐색 기반 AI - 상태 공간과 휴리스틱

> 초기 AI에서 탐색은 지능을 설명하는 가장 직접적인 틀이었습니다. 가능한 상태를 펼쳐 놓고 그 안에서 목표에 이르는 경로를 찾는 문제로 지능적 행동을 이해한 것입니다. 이 챕터에서는 상태 공간·맹목 탐색·휴리스틱 탐색·게임 트리·제약 만족 문제를 차례로 살펴보고, 끝에서 이 사고가 현대 기계학습과 어떻게 이어지는지 연결합니다.

## 1. 왜 "탐색" 이 출발점이었나

1950~1960년대의 AI 연구자들은 체스·퍼즐·정리 증명처럼 **규칙과 상태가 명확한 문제**에 먼저 관심을 두었습니다. 이런 문제는 "지금 상태"와 "다음 상태로 가는 방법"만 있으면 "목표 상태"까지 경로를 찾는 문제로 바꿔 쓸 수 있었고, 그 경로 찾기가 곧 지능의 작동 방식으로 여겨졌습니다.

이 관점에서는 문제를 푼다는 것이 **상태 공간(State Space)을 탐색**하는 일입니다. 실제로 현재까지 남아 있는 탐색 알고리즘(DFS·BFS·A*·미니맥스 등) 대부분이 이 시기에 그 원형이 정립되었습니다.

## 2. 상태와 오퍼레이터, 그리고 하노이 타워

탐색 기반 AI의 기본 언어는 두 가지입니다.

- **상태(State)**: 지금 문제가 놓인 상황
- **오퍼레이터(Operator)**: 한 상태를 다른 상태로 변환하는 허용된 행동

이 두 개념으로 하노이 타워 같은 전형적 퍼즐을 풀어 볼 수 있습니다. 세 개의 기둥 A·B·C와 크기가 서로 다른 원반 세 개가 있고, 한 번에 하나씩만 옮길 수 있으며 큰 원반을 작은 원반 위에 올릴 수 없습니다.

- 상태: 각 기둥 위 원반의 배치. 예: `A=[3,2,1]`, `B=[]`, `C=[]`
- 오퍼레이터: "기둥 X의 맨 위 원반을 기둥 Y로 옮긴다" 중 규칙을 위반하지 않는 것만 허용
- 초기 상태: 모든 원반이 A에 있음
- 목표 상태: 모든 원반이 C에 있음

이렇게 정의하고 나면 문제 풀이는 "초기 상태에서 출발해 오퍼레이터를 적용하며 목표 상태에 이르는 경로를 찾는 일" 이 됩니다. 상태 공간을 그래프로 그려 두고 경로 탐색 알고리즘을 돌리는 방식입니다.

## 3. 프레임 문제와 탐색의 한계

상태·오퍼레이터 모델의 가장 유명한 한계가 **프레임 문제(Frame Problem)**입니다. 이것은 "행동이 일어난 뒤에도 그대로인 사실을 어떻게 처리할 것인가"를 묻는 문제입니다. 한 상태에서 다음 상태로 넘어갈 때 변하는 것을 적는 일은 비교적 쉽지만, "**변하지 않는 것 전체**"를 자동으로 유지하는 일은 훨씬 어렵습니다. 1969년 John McCarthy와 Patrick Hayes가 이 문제를 정식화했습니다.

예를 들어 로봇이 방에서 의자를 옮겼다면, 우리는 "의자의 위치가 변했다" 만 기술하고 싶지만 형식적으로는 "벽의 위치는 그대로다", "창문은 그대로다", "조명은 꺼져 있다" 같은 무수한 변하지 않은 사실도 모두 명시해야 합니다.

관련 개념 두 가지도 함께 기억해 두면 좋습니다.

- **래미피케이션(Ramification) 문제**: 한 행동의 간접적인 파급 효과를 어디까지 계산할 것인가
- **퀄리피케이션(Qualification) 문제**: 행동이 성공하기 위한 전제 조건을 어디까지 모두 적어 둘 것인가

세 문제는 모두 "현실 세계를 기호로 온전히 쓰려면 얼마나 많은 말을 적어야 하는가" 라는 질문으로 이어지며, 이는 이후 연결주의로 흐름이 기운 이유 중 하나이기도 합니다.

## 4. 맹목적 탐색 - DFS와 BFS

탐색 알고리즘은 크게 **맹목적(Blind, Uninformed)** 탐색과 **휴리스틱(Informed)** 탐색으로 나뉩니다. 맹목적 탐색은 목표까지의 거리·비용에 대한 힌트 없이, 구조적 순서대로 공간을 펼쳐 봅니다. 대표가 DFS와 BFS입니다.

```python
# 그래프가 인접 리스트로 주어졌다고 가정
graph = {
    "A": ["B", "C"],
    "B": ["D", "E"],
    "C": ["F"],
    "D": [], "E": ["F"], "F": [],
}

def dfs(graph, start, goal):
    stack, visited = [start], []
    while stack:
        node = stack.pop()
        if node in visited:
            continue
        visited.append(node)
        if node == goal:
            return visited
        # LIFO 이므로 깊이 우선
        stack.extend(reversed(graph[node]))
    return None

def bfs(graph, start, goal):
    from collections import deque
    queue, visited = deque([start]), []
    while queue:
        node = queue.popleft()
        if node in visited:
            continue
        visited.append(node)
        if node == goal:
            return visited
        # FIFO 이므로 너비 우선
        queue.extend(graph[node])
    return None

dfs(graph, "A", "F")   # ['A', 'B', 'D', 'E', 'F']          (방문 순서)
bfs(graph, "A", "F")   # ['A', 'B', 'C', 'D', 'E', 'F']     (방문 순서)
```

두 함수 모두 목표에 도달할 때까지의 **방문 순서**를 반환합니다. 차이는 다음에 펼쳐 볼 노드를 **스택**에서 꺼내느냐 **큐**에서 꺼내느냐 하나뿐이지만, 결과적으로 DFS는 한 가지를 끝까지 내려갔다가 돌아오고, BFS는 시작점에서 가까운 층부터 차례로 훑습니다. DFS는 메모리가 적게 들지만 최단 경로를 보장하지 않고, BFS는 가중치가 모두 같은 그래프에서 시작점으로부터의 최단 거리를 층 단위로 보장합니다. 어느 쪽도 "목표에 얼마나 가까운지"에 대한 힌트는 사용하지 않습니다.

## 5. 휴리스틱 탐색 - 감을 섞어 가지 치기

현실 문제에서 상태 공간은 어마어마하게 큽니다. 체스 한 판의 가능한 국면 수만 해도 우주의 원자 수를 넘는 수준으로 알려져 있어, 맹목적 탐색으로는 현실적인 시간 안에 끝낼 수 없습니다.

**휴리스틱(Heuristic)** 탐색은 "목표까지 남은 비용에 대한 추정치" 를 도입해 탐색 순서를 바꿉니다. 추정치는 완벽하지 않아도 되며, 어느 정도 합리적이기만 하면 탐색 가지의 대부분을 쳐 낼 수 있습니다.

### 5.1 8-퍼즐과 평가 함수

3x3 격자의 숫자 퍼즐에서 "목표 배열과 다른 타일의 개수" 나 "각 타일이 목표 위치까지 이동해야 할 맨해튼 거리 합" 같은 값이 대표적 휴리스틱입니다. 탐색 엔진은 이 추정치가 낮은 상태부터 먼저 펼쳐 봅니다.

```text
휴리스틱 h(n) = 현재 배치에서 목표와 어긋난 타일 수
```

### 5.2 A* 알고리즘

가장 유명한 휴리스틱 탐색 알고리즘이 **A*** (A-star)입니다. 1968년 Peter Hart·Nils Nilsson·Bertram Raphael이 SRI에서 제안했습니다. 평가 함수가 다음 식으로 정의됩니다.

```text
f(n) = g(n) + h(n)

g(n): 시작 상태에서 현재 노드 n까지 실제로 든 비용
h(n): n에서 목표까지 남은 비용의 휴리스틱 추정치
f(n): n을 거쳐 목표에 도달할 때의 총 비용 추정
```

우선순위 큐에서 `f(n)`이 작은 노드부터 꺼내 펼칩니다. 이때 `h(n)`이 실제 남은 비용보다 크지 않으면, 즉 **admissible**하면 A*는 **최단 경로를 보장**합니다. 그래서 A*와 그 변종은 내비게이션의 최단 경로 탐색, 로봇 경로 계획, 게임 NPC의 길찾기 등에 널리 쓰입니다.

### 5.3 Hill-Climbing과 국소 최대 함정

A*만큼 정교하지 않은 휴리스틱 탐색으로 **언덕 등반(Hill-Climbing)**이 있습니다. 현재 상태에서 평가값이 더 나은 이웃이 있으면 그쪽으로 이동하고, 더 나은 이웃이 없으면 멈추는 탐욕적 방식입니다. 구현이 간단하고 메모리를 거의 쓰지 않지만 두 가지 함정이 자주 걸립니다.

- **국소 최대 (Local Maximum)**: 주변보다는 높지만 전체 최고점은 아닌 봉우리에 갇힘
- **평탄 (Plateau)**: 이웃 평가값이 모두 같아 방향을 정할 수 없음

이 문제의식은 다음 챕터의 **유전 알고리즘**으로 이어집니다. 한 점에서만 이동하는 대신 여러 해를 동시에 유지하고 교배·돌연변이로 해 공간을 퍼뜨리는 전략이 국소 최대를 우회하는 한 방법입니다.

### 5.4 외판원 문제 (TSP)

순회 도시 수가 늘면 모든 순열을 다 보기 어렵습니다 (n 개 도시에 대해 `(n-1)!/2` 경로). 휴리스틱 탐색은 여기서도 "가장 가까운 도시부터 방문" 같은 간단한 규칙으로 초기 해를 얻고, 이후 국소 개선을 섞어 현실적인 답을 짧은 시간에 만들어 냅니다.

## 6. 게임 트리 - 미니맥스와 알파-베타 가지치기

상대가 있는 게임은 "내 차례에 내가 어떤 수를 두면, 상대가 어떤 반격을 할 수 있는가"를 **트리**로 펼쳐 봅니다.

- **미니맥스(Minimax)**: 내 차례에서는 점수를 **최대화**, 상대 차례에서는 **최소화** 한다고 가정하며 말단의 평가값을 위로 전파
- **알파-베타 가지치기(Alpha-Beta Pruning)**: 이미 나온 결과로 미뤄 봤을 때 계산해 볼 필요가 없는 가지를 중간에 잘라내 미니맥스 탐색 속도를 수십~수백 배 높이는 기법

```python
def minimax(state, depth, is_max, evaluate, next_states):
    if depth == 0 or state.is_terminal():
        return evaluate(state)

    if is_max:
        best = float("-inf")
        for child in next_states(state):
            best = max(best, minimax(child, depth - 1, False, evaluate, next_states))
        return best
    else:
        best = float("inf")
        for child in next_states(state):
            best = min(best, minimax(child, depth - 1, True, evaluate, next_states))
        return best
```

체스에서는 탐색만으로도 매우 강한 성능을 낼 수 있었습니다. 1997년 DeepBlue가 카스파로프를 이긴 것도 미니맥스, 알파-베타 가지치기, 정교한 평가 함수, 막대한 연산 자원의 조합 덕분이었습니다. 반면 바둑은 상태 공간이 훨씬 커서 탐색만으로는 사람을 이기기 어려웠습니다. 그래서 AlphaGo처럼 몬테카를로 트리 탐색에 신경망 가치·정책망을 결합한 방식이 필요했습니다.

## 7. 제약 만족 문제 (CSP)

일부 문제는 "경로 자체" 보다 "모든 제약을 만족하는 해 하나" 를 찾는 것이 목표입니다. 이런 부류를 **제약 만족 문제(Constraint Satisfaction Problem, CSP)** 라 부릅니다. 변수·도메인·제약 세 가지로 정의합니다.

- **변수(Variables)**: 결정해야 할 대상들
- **도메인(Domain)**: 각 변수가 가질 수 있는 값의 범위
- **제약(Constraints)**: 변수들이 함께 만족해야 할 조건

대표 예가 **8-Queen 문제** 입니다. 8x8 체스판에 퀸 8개를 놓되, 서로를 공격하지 않아야 합니다. 변수는 각 열에 두는 퀸의 행 위치, 도메인은 `{0..7}`, 제약은 "같은 행·같은 대각선 금지" 입니다.

```python
def n_queens(n):
    solutions = []

    def backtrack(cols):
        row = len(cols)
        if row == n:
            solutions.append(cols[:])
            return
        for col in range(n):
            if all(c != col and abs(c - col) != row - r
                   for r, c in enumerate(cols)):
                cols.append(col)
                backtrack(cols)
                cols.pop()

    backtrack([])
    return solutions

len(n_queens(8))   # 92  (8-Queen의 전체 해 개수)
```

백트래킹(backtracking)은 CSP 풀이의 기본 구조이며, 여기에 제약 전파·변수 순서 휴리스틱·대칭성 활용 같은 기법이 얹히면 실용적인 스케줄링·배치 문제에도 적용됩니다. 스도쿠 솔버·스포츠 리그 일정·반도체 레이아웃 검증·배송 경로 배정 등이 모두 CSP의 응용 사례입니다.

## 8. 탐색 AI와 현대 기계학습의 연결

탐색 기반 AI는 "데이터 기반 딥러닝"에 밀려 역사 속으로 사라진 것처럼 보이지만, 현대 AI 곳곳에 탐색의 흔적이 살아 있습니다.

- **하이퍼파라미터 탐색**: 학습률·층 수·드롭아웃 같은 설정을 바꿔 가며 모델을 학습시키는 작업은 상태 공간 탐색과 수학적 구조가 같습니다. Grid Search·Random Search·Bayesian Optimization이 대표적
- **강화학습의 트리 탐색**: 앞서 언급한 AlphaGo의 몬테카를로 트리 탐색, MuZero의 계획 모듈 등은 미니맥스 계열 탐색과 신경망을 결합합니다
- **경로 계획 로보틱스**: 자율주행·드론·창고 로봇이 실시간으로 쓰는 경로 찾기는 여전히 A*와 그 변종이 주력입니다
