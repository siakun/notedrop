## 1. EC2 인스턴스 생성과 접속

### 1.1 인스턴스 시작 절차

AWS 매니지먼트 콘솔 -> EC2 -> 인스턴스 -> "인스턴스 시작" 을 차례로 선택합니다. 최근 UI는 한 페이지에서 모든 옵션을 설정하는 형태이며, 이름·태그 입력 필드가 상단에 상시 노출됩니다.

> [!note] 핵심 구성 요소
> - **이름·태그**: 테스트용·운영용을 구분해 두지 않으면 나중에 비용이 누적됩니다
> - **AMI**: Amazon Linux가 기본입니다. AWS 자원 요청 시 자격 증명 연동이 쉽습니다
> - **인스턴스 유형**: t2.micro·t3.micro가 Free Tier 대상 (리전 조건 충족 시). 소규모 웹 1 개에는 충분합니다. 대역폭·메모리 부담이 있으면 T2/T3 Small
> - **키 페어**: RSA 기반 PPK(PuTTY) 또는 PEM(macOS·Linux)
> - **보안 그룹**: 신규 생성 시 22 번 SSH 포트가 기본 인바운드로 열립니다
> - **스토리지**: EBS 범용 SSD(gp3) 8 GB 기본

### 1.2 접속 방법 3 가지

1. **웹 브라우저 콘솔 접속** (EC2 Instance Connect)
    - EC2 인스턴스 선택 -> "연결" 버튼 -> 브라우저 내 SSH 터미널
    - 별도 프로그램이 필요 없지만 복붙에 제약이 있습니다
2. **PuTTY** (Windows)
    - 키 페어(PPK) 로 `ec2-user`로 접속
3. **FileZilla** (SFTP)
    - 사이트 관리자 -> 새 사이트 -> 프로토콜 SFTP, 포트 22, 로그온 유형 "키 파일"
    - 사용자는 `ec2-user` 고정 (Amazon Linux 이미지 기본 계정)

> [!warning] 인바운드 규칙 확인
> 기존 보안 그룹을 재사용하면 22 번 포트가 열려 있지 않을 수 있습니다. 인스턴스 상세 -> 보안 탭에서 22 번 TCP 인바운드 규칙이 있는지 확인하세요.

### 1.3 인스턴스 관리 상식

- **중지(Stop) vs 종료(Terminate)**: 중지는 전원 끄기(재시작 가능), 종료는 삭제(EBS 볼륨도 자동 제거)
- **AMI**: 인스턴스 전체(연결 스토리지 포함) 백업
- **스냅샷**: 특정 EBS 볼륨만 백업
- **탄력적 IP(Elastic IP)**: 중지·재시작 시 Public IP가 바뀌는 문제를 해결합니다. **인스턴스에 연결된 상태는 무료, 미연결 상태는 비용 발생** (자원 낭비 방지 정책)
- **EC2 글로벌 보기**: 다른 리전에 방치된 인스턴스를 한 화면에서 확인해 삭제할 수 있습니다

> [!info] 리전별 가격 차이
> AWS는 리전마다 요금이 다릅니다. 트래픽 지연이 크게 중요하지 않은 테스트는 저렴한 리전을 고릅니다.

## 2. S3 버킷 생성과 정적 웹사이트 호스팅

Ch 02에서 S3 개념·생성 흐름을 다뤘으므로, 여기서는 **정적 웹사이트 호스팅**에 특화된 부분만 짚습니다.

### 2.1 퍼블릭 접근 허용 2 단계

1. 버킷 권한 -> "모든 퍼블릭 액세스 차단 편집" -> 차단 해제
2. 버킷 정책에 JSON 정책 추가

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "PublicReadGetObject",
      "Effect": "Allow",
      "Principal": "*",
      "Action": "s3:GetObject",
      "Resource": "arn:aws:s3:::YOUR-BUCKET-NAME/*"
    }
  ]
}
```

두 단계 중 하나만 해제해도 외부 접근이 안 됩니다. 둘 다 필요합니다.

### 2.2 정적 웹사이트 호스팅 활성화

- 버킷 -> 속성 -> "정적 웹 사이트 호스팅" 활성화
- Index 문서(`index.html`), Error 문서(`error.html`) 지정
- 도메인 연결 시에는 Route 53과 결합합니다

> [!info] 서버리스 웹사이트 구성
> S3 (정적 프런트) + Lambda (백엔드 함수) + DynamoDB (DB) 조합으로 간단한 게시판·로그인 사이트를 서버 관리 부담 없이 구축할 수 있습니다. Lambda 구성은 뒤의 `9. Lambda - 서버리스 이미지 썸네일 파이프라인`에서 구체적으로 다룹니다.

## 3. AWS CLI와 IAM 사용자

### 3.1 IAM 사용자 생성

관리 콘솔 -> IAM -> 사용자 -> 사용자 추가:

1. 사용자 이름 입력
2. 자격 유형: **프로그래밍 방식 액세스** (CLI·SDK 용 Access Key·Secret Key 발급) 또는 관리 콘솔 액세스
3. 권한 설정
    - 기존 그룹에 추가
    - 기존 사용자 권한 복사
    - 기존 정책 직접 연결 (예: `AdministratorAccess`, 실습 외에는 최소 권한 정책 권장)
4. 태그 (선택)
5. 생성 직후 Access Key ID와 Secret Access Key를 반드시 복사합니다 (CSV 다운로드 권장)

> [!warning] Secret Access Key는 생성 시점에만 노출됩니다
> IAM 사용자 생성 직후에만 Secret Access Key를 확인할 수 있습니다. 이후에는 조회가 불가하므로 CSV로 다운로드하거나 즉시 저장하세요. 분실하면 새 키를 만들고 기존 키를 삭제해야 합니다.

> [!warning] 루트 계정 사용 금지 권장
> 최초 가입 시 이메일로 만든 루트 계정은 모든 권한을 가집니다. 외부 작업 시 보안 위험이 크므로, 앞 장의 계정 보안 강화 절에서 설명한 것처럼 IAM에서 필요한 권한만 가진 사용자를 만들어 사용하는 것이 표준입니다.

### 3.2 AWS CLI 설정

EC2 인스턴스·로컬 PC 어디서든 동일합니다. Windows는 MSI 설치, macOS는 Homebrew, Linux는 패키지 매니저로 설치합니다.

## 4. Cloud9 통합 개발 환경

### 4.1 Cloud9 개요

> [!note] AWS Cloud9
> 웹 브라우저에서 동작하는 통합 개발 환경(IDE) 입니다. 백엔드는 EC2 인스턴스이며, Python·Node.js·Java·Go 등 다수 언어를 지원합니다.

- **도구 비용은 무료**, 연결된 EC2 인스턴스 비용만 발생합니다
- 자동 중지(Auto-hibernate) 설정 가능 (예: 30 분 유휴 시 중지)
- 공유·협업 기능으로 여러 개발자가 동시에 작업할 수 있습니다

> [!warning] 신규 리전에서 Cloud9이 보이지 않을 수 있음
> Cloud9의 신규 생성 가능 여부는 리전과 시점에 따라 달라질 수 있습니다. 현재 리전에서 Cloud9 메뉴가 보이지 않는다면 공식 문서에서 지원 여부를 먼저 확인하세요.
>
> 지원되지 않는 경우에는 VSCode Remote-SSH + EC2 조합을 대안으로 쓸 수 있습니다.

### 4.2 생성 절차

서비스 -> 개발자 도구 -> Cloud9 -> Create environment:

1. 이름·설명
2. Environment type
    - **Create a new EC2 instance** (기본)
    - Existing compute (기존 EC2를 SSH로 연결)
3. 인스턴스 타입 (t3.micro 또는 t2.micro)
4. 플랫폼 (Amazon Linux 2 권장)
5. 자동 중지 시간 (30 분 기본)
6. Network: 작업 리전의 서브넷 선택 (다른 리전으로 잘못 설정되면 생성 실패)

생성 후 "Open IDE" 를 클릭하면 편집기·터미널·파일 탐색기가 통합된 화면이 뜹니다. 작업 공간 경로는 `/home/ec2-user/environment/{project}/` 입니다.

### 5.3 버킷 생성 (createBucket.py)

```python
import boto3
import botocore
import configparser


def readConfig():
    config = configparser.ConfigParser()
    config.read('./config.ini')
    return config['S3']


def verifyBucketName(s3Client, bucket):
    try:
        s3Client.head_bucket(Bucket=bucket)
        raise SystemExit('This bucket has already been created...')
    except botocore.exceptions.ClientError as e:
        error_code = int(e.response['Error']['Code'])
        if error_code == 404:
            print('Existing Bucket Not Found, please proceed')
        if error_code == 403:
            raise SystemExit('Bucket already owned by another AWS account')


def createBucket(s3Client, name):
    session = boto3.session.Session()
    current_region = session.region_name
    if current_region == 'us-east-1':
        s3Client.create_bucket(Bucket=name)
    else:
        s3Client.create_bucket(
            Bucket=name,
            CreateBucketConfiguration={'LocationConstraint': current_region},
        )


def verifyBucket(s3Client, bucket):
    waiter = s3Client.get_waiter('bucket_exists')
    waiter.wait(Bucket=bucket)
    print('The bucket ' + bucket + ' is now available.')


client = boto3.client('s3')
config = readConfig()
bucket_name = config['bucket_name']

verifyBucketName(client, bucket_name)
createBucket(client, bucket_name)
verifyBucket(client, bucket_name)
```

> [!note] Waiter 패턴
> `get_waiter('bucket_exists')` 처럼 AWS 리소스가 완전히 생성·삭제될 때까지 폴링하며 대기하는 패턴입니다. 생성 직후 바로 다음 작업을 하면 "리소스 없음" 에러가 발생하는 레이스 컨디션을 방지합니다.

### 5.5 CSV -> JSON 변환 후 재업로드 (changeData.py)

```python
import boto3
import json
import csv
import io
import configparser


def getCSVFile(s3Client, bucket, key):
    bytes_buffer = io.BytesIO()
    s3Client.download_fileobj(Bucket=bucket, Key=key, Fileobj=bytes_buffer)
    return bytes_buffer.getvalue().decode('utf-8')


def createObject(s3Client, bucket, key, data, contentType, metadata=None):
    if metadata is None:
        metadata = {}
    s3Client.put_object(
        Bucket=bucket,
        Key=key,
        Body=data,
        ContentType=contentType,
        Metadata=metadata,
    )


def convertToJSON(input_text):
    jsonList = []
    keys = []
    csvReader = csv.reader(input_text.split('\n'), delimiter=',')
    for i, row in enumerate(csvReader):
        if i == 0:
            keys = row
        else:
            if not row:
                continue
            obj = {keys[x]: row[x] for x in range(len(keys)) if x < len(row)}
            jsonList.append(obj)
    return json.dumps(jsonList, indent=4)


config = configparser.ConfigParser()
config.read('./config.ini')
s3cfg = config['S3']
client = boto3.client('s3')

csvStr = getCSVFile(
    client,
    s3cfg['bucket_name'],
    s3cfg['key_name'] + s3cfg['source_file_extension'],
)
jsonStr = convertToJSON(csvStr)
createObject(
    client,
    s3cfg['bucket_name'],
    s3cfg['key_name'] + s3cfg['processed_file_extension'],
    jsonStr,
    s3cfg['processed_content_type'],
)
```

## 6. 주변 네트워크 서비스 - VPC·Route 53·CloudFront

앞 장에서 VPC·서브넷·보안 그룹을 자세히 다뤘으므로, 여기서는 통합 실습 관점에서 추가로 기억해 둘 것만 정리합니다.

### 6.1 VPC 요약

- **CIDR 블록**: 10.0.0.0/16 같은 IP 범위 지정. VPC·서브넷 모두 CIDR로 주소 공간 할당
- **Public Subnet**: Internet Gateway와 연결된 라우팅 테이블로 외부 인터넷 접근 가능
- **Private Subnet**: 외부 직접 접근 차단. NAT Gateway를 통해 외부 요청 가능 (반대 방향은 차단)
- **Route Table**: Subnet 별로 1 개 연결. 대상 CIDR과 게이트웨이 매핑
- **Internet Gateway**: VPC를 외부 인터넷과 연결
- **보안 그룹**: 인스턴스 단위 방화벽. 기본 인바운드 거부, 아웃바운드 허용
- **VPC Peering**: 서로 다른 VPC 간 P2P 통신
- **VPN / Direct Connect**: 온프레미스와 AWS 연결. Direct Connect는 전용선 기반

### 6.2 Route 53

도메인 이름과 IP 주소 간 매핑을 제공하는 AWS의 DNS 입니다. AWS 내부 뿐 아니라 외부 리소스에도 라우팅할 수 있습니다. 다중 리전 배포에서는 지연 시간 기반 라우팅·가중치 기반 라우팅 같은 고급 기능을 사용합니다.

### 6.3 CloudFront

> [!note] CDN (Content Delivery Network)
> 전 세계에 분산된 Edge Location 이나 POP(Point of Presence)에서 콘텐츠를 캐싱해, 사용자와 가까운 위치에서 응답을 돌려줍니다. 원본(Origin) 서버까지 매번 가지 않아도 되므로 지연이 감소합니다.

- 종량제 (데이터 전송량 + HTTP 요청 수 + 무효화 요청 비용)
- SSL 인증서는 ACM(AWS Certificate Manager) 을 통해 무료 발급·연동 가능
- Edge 캐싱으로 응답 시간을 수 배 단축할 수 있습니다

### 6.4 Cognito와 IAM Role (보안 요약)

- **Amazon Cognito**: 외부 사용자 인증·회원가입·소셜 로그인·MFA를 백엔드 없이 중개합니다
- **IAM Policy**: 어떤 리소스에 어떤 작업을 허용·거부할지 JSON으로 기술합니다
- **IAM Role**: Policy 집합을 이름으로 묶은 "모자". 사용자·EC2·Lambda 등에 임시로 부여합니다

IAM Policy 자체는 앞 장에서 자세히 다뤘고, 여기서는 실습에 필요한 역할만 다시 짚습니다.

## 7. EC2 Auto Scaling과 ALB

### 7.1 Launch Template 생성

EC2 -> Launch Templates -> Create Launch Template:

- 이름·설명
- **Auto Scaling guidance** 체크
- AMI (Amazon Linux 2·Amazon Linux 2023)
- 인스턴스 타입 (t2.micro·t3.micro)
- 키 페어 (Auto Scaling 에서는 접속 불필요하면 생략 가능)
- 보안 그룹 (HTTP 80 포트 허용 등)
- Advanced details -> **User data**: 인스턴스 부팅 시 실행되는 셸 스크립트

User data 예시 - Apache 설치 후 기본 페이지 배포:

```bash
#!/bin/bash
yum update -y
yum install -y httpd
systemctl enable httpd
systemctl start httpd
echo "<h1>Hello from $(hostname)</h1>" > /var/www/html/index.html
```

### 7.2 Auto Scaling Group 생성

EC2 -> Auto Scaling Groups -> Create:

1. 그룹 이름, Launch Template·Version 선택 (`Latest` 또는 `Default`)
2. **VPC·가용 영역 Subnet 선택** (여러 AZ 선택 권장)
3. Load Balancer 연결 (없으면 나중에 attach)
4. **Desired · Min · Max Capacity** (예: 2 · 1 · 4)
5. Target Tracking Policy (None 또는 CPU 50% 초과 시 스케일 아웃 등)
6. 알림·태그 (선택)
7. 생성

> [!example] 작동 확인
> 생성된 인스턴스 중 하나를 수동으로 terminate 하면, Auto Scaling Group이 desired 값을 지키기 위해 자동으로 새 인스턴스를 생성합니다. 이것이 Auto Scaling의 핵심 동작입니다.

### 7.3 Application Load Balancer (ALB)

EC2 -> Load Balancers -> Create Load Balancer -> **Application Load Balancer**:

| 종류 | 용도 |
|---|---|
| Application | HTTP·HTTPS, 애플리케이션 계층 라우팅 (경로·호스트 기반) |
| Network | TCP·UDP, 초고성능·저지연 |
| Gateway | 네트워크 어플라이언스 로드밸런싱 |

설정 요점:

- Scheme: Internet-facing (외부 공개)
- IP address type: IPv4
- **Mappings**: 2 개 이상 AZ·Subnet 매핑 필수
- Security Group: 80 포트 허용
- Listener: HTTP 80 -> Target Group 라우팅
- **Target Group 생성**: 인스턴스 타입, HTTP 80, VPC default, Target으로 실행 중인 EC2 등록

> [!info] Auto Scaling과 ALB 통합
> Auto Scaling Group -> Edit -> Load balancing에서 기존 ALB의 Target Group을 attach 하면, 신규 인스턴스 생성 시 자동으로 Target Group에 등록되어 트래픽을 받습니다. Auto Scaling은 용량 관리, ALB는 트래픽 분배로 역할이 분리됩니다.

> [!warning] Auto Scaling 서비스 비용
> Auto Scaling 기능 자체는 무료입니다. 생성되는 EC2 인스턴스·EBS 비용만 과금됩니다. 삭제 시에는 Auto Scaling Group부터 지우지 않으면 EC2를 아무리 종료해도 자동 재생성되므로, **ASG -> Launch Template -> 나머지 리소스** 순서로 정리합니다.

## 8. DynamoDB 실습 (Cloud9에서 boto3로)

앞 장에서 DynamoDB 개념과 콘솔 생성 절차를 다뤘으므로, 여기서는 boto3로 테이블을 만들고 다양한 쿼리 패턴을 시연합니다.

### 8.1 Table 생성 + 데이터 적재 (createTable.py)

```python
import boto3
import configparser
import json


def readConfig():
    config = configparser.ConfigParser()
    config.read('./config.ini')
    return config['DynamoDB']


def createTable(client, t):
    client.create_table(
        AttributeDefinitions=[
            {'AttributeName': t['partitionKey'], 'AttributeType': 'S'},
            {'AttributeName': t['sortKey'],      'AttributeType': 'N'},
        ],
        KeySchema=[
            {'AttributeName': t['partitionKey'], 'KeyType': 'HASH'},
            {'AttributeName': t['sortKey'],      'KeyType': 'RANGE'},
        ],
        ProvisionedThroughput={
            'ReadCapacityUnits':  int(t['readCapacity']),
            'WriteCapacityUnits': int(t['writeCapacity']),
        },
        TableName=t['tableName'],
    )


def putNote(table, note):
    table.put_item(Item={
        'UserId': note['UserId'],
        'NoteId': int(note['NoteId']),
        'Note':   note['Note'],
    })


def putDatas(tableName, jsonFileName='Notes.json'):
    with open(jsonFileName) as f:
        notes = json.load(f)
    table = boto3.resource('dynamodb').Table(tableName)
    for n in notes:
        putNote(table, n)


config = readConfig()
tableName = config['tableName']
client = boto3.client('dynamodb')

createTable(client, config)
client.get_waiter('table_exists').wait(TableName=tableName)
putDatas(tableName, 'Notes.json')
```

`AttributeDefinitions`는 key에 사용되는 속성만 나열합니다. 그 외 속성은 스키마리스로 `put_item` 시점에 자유롭게 추가합니다.

### 8.2 3 가지 쿼리 방법

#### 8.2.1 Partition Key 기반 query (queryByKey.py)

```python
import boto3


def queryNotesByPartitionKey(ddbClient, tableName, qUserId):
    response = ddbClient.query(
        TableName=tableName,
        KeyConditionExpression='UserId = :userId',
        ExpressionAttributeValues={':userId': {'S': qUserId}},
        ProjectionExpression='NoteId, Note',
    )
    return response['Items']


ddb = boto3.client('dynamodb')
items = queryNotesByPartitionKey(ddb, 'Notes', 'student')
for item in items:
    print(item)
```

- `KeyConditionExpression`: WHERE 절 (SQL의 조건문)
- `ProjectionExpression`: SELECT 컬럼 목록
- `ExpressionAttributeValues`: 파라미터 바인딩 (값 + 타입 지정)

샘플 데이터 기준으로 `UserId='student'` 항목 5 개가 반환됩니다.

#### 8.2.2 Pagination Scan (queryByPaging.py)

```python
import boto3


def queryAllNotesPaginator(ddbClient, tableName, pageSize):
    paginator = ddbClient.get_paginator('scan')
    page_iterator = paginator.paginate(
        TableName=tableName,
        PaginationConfig={'PageSize': pageSize},
    )
    for page in page_iterator:
        if page['Count'] > 0:
            for note in page['Items']:
                print(note)


queryAllNotesPaginator(boto3.client('dynamodb'), 'Notes', pageSize=3)
```

`pageSize=3`으로 7 건 데이터를 받으면 3 + 3 + 1 페이지로 분할됩니다. Scan은 전체 테이블을 훑으므로 비용·지연이 큽니다. 가능하면 `query`를 쓰세요.

#### 8.2.3 PartiQL (queryByPartiQL.py)

```python
import boto3


def querySpecificNote(ddbClient, tableName, qUserId, qNoteId):
    response = ddbClient.execute_statement(
        Statement='SELECT * FROM ' + tableName + ' WHERE UserId = ? AND NoteId = ?',
        Parameters=[
            {'S': qUserId},
            {'N': str(qNoteId)},
        ],
    )
    return response['Items']


ddb = boto3.client('dynamodb')
print(querySpecificNote(ddb, 'Notes', 'student', 5))
```

> [!note] PartiQL
> DynamoDB에서 표준 SQL 구문(SELECT·INSERT·UPDATE·DELETE)을 사용할 수 있게 해 줍니다. 파라미터는 `?` 플레이스홀더와 타입 기반 `Parameters` 배열로 바인딩합니다. 관계형 DB 경험자에게 익숙한 문법을 제공합니다.

## 9. Lambda - 서버리스 이미지 썸네일 파이프라인

Lambda의 기본 개념부터 다시 짚고, 가장 전형적인 "S3 업로드 -> 썸네일 생성" 예제를 만들어 봅니다.

### 9.1 서버리스 개념 복습

> [!note] 서버리스 (Serverless)
> 사용자가 서버 인스턴스를 프로비저닝하지 않고 코드(함수)만 업로드하면, 이벤트 발생 시에만 실행되는 컴퓨팅 모델입니다. 실행된 시간·횟수에만 과금합니다.

Lambda의 특징:

- 여러 언어 지원: Python, Java, Node.js, .NET, Go, Ruby 등
- 완전 관리형 (인프라 관리 0)
- 자동 스케일링·장애 복구
- 트리거 기반 실행 (S3·DynamoDB·SQS·API Gateway·CloudWatch Events 등)
- 코드 업로드는 무료, 실행 시간만 과금
- 외부 라이브러리는 **레이어(Layer)**로 별도 추가

### 9.2 제약 사항

| 항목 | 제한 |
|---|---|
| 리전당 기본 동시 실행 | 1,000 건 (상향 가능) |
| 함수·계층 총 스토리지 | 계정·리전별로 정해진 상한 (현재 기준 수십 GB 단위, AWS 공식 문서 확인 권장) |
| 함수 메모리 | 최대 10,240 MB |
| 실행 시간 | 최대 15 분 |
| 배포 패키지 크기 | 압축 상태 50 MB, 해제 시 250 MB (레이어 포함) |

> [!info] 제약 회피 전략
> 단일 함수에 모든 로직을 몰아넣지 말고, 기능을 단일 책임으로 분리해 여러 함수로 체이닝합니다. 모델 학습처럼 오래 걸리는 작업은 EC2·SageMaker에 두고, 추론·후처리처럼 짧은 작업만 Lambda로 돌립니다.

### 9.3 썸네일 파이프라인 아키텍처

```
[클라이언트] --업로드--> [S3: origin 버킷]
                            |
                        ObjectCreated 이벤트
                            v
                       [Lambda 함수]
                    (Pillow로 리사이즈)
                            |
                            v
                    [S3: resize 버킷]
```

### 9.4 사전 준비

**IAM 역할 생성**:

IAM -> 역할 만들기:

- 신뢰할 수 있는 엔터티: AWS 서비스 > Lambda
- 권한 정책 연결:
    - `AmazonS3FullAccess`
    - `AWSLambdaBasicExecutionRole`
- 역할 이름 지정 후 생성

**S3 버킷 2 개 생성**:

- 소스 버킷: 예를 들어 `my-demo-origin`
- 대상 버킷: `my-demo-origin-resize` (소스 버킷 이름 + `-resize`)

### 9.5 Lambda 함수 생성과 트리거

1. Lambda 콘솔 -> 함수 생성
2. "새로 작성" 선택
3. 함수 이름 지정
4. 런타임: 콘솔에서 지원되는 최신 안정 Python 버전
5. 실행 역할: 앞에서 만든 IAM 역할 선택
6. 함수 생성
7. 함수 상세 -> 트리거 추가 -> S3
    - 버킷: `my-demo-origin`
    - 이벤트 유형: All object create events
    - 접두사·접미사 (선택): 특정 디렉터리·확장자만 반응시키려면 지정

### 9.6 함수 코드 (Python + Pillow)

```python
import boto3
import uuid
from PIL import Image

s3_client = boto3.client('s3')


def resize_image(image_path, resized_path):
    with Image.open(image_path) as image:
        image.thumbnail((128, 128))
        image.save(resized_path)


def lambda_handler(event, context):
    for record in event['Records']:
        bucket = record['s3']['bucket']['name']
        key = record['s3']['object']['key']
        tmpkey = key.replace('/', '')
        download_path = '/tmp/{}{}'.format(uuid.uuid4(), tmpkey)
        upload_path = '/tmp/resized-{}'.format(tmpkey)

        s3_client.download_file(bucket, key, download_path)
        resize_image(download_path, upload_path)
        # 대상 버킷 이름은 소스 버킷 이름 + '-resize' 규칙입니다
        s3_client.upload_file(
            upload_path,
            '{}-resize'.format(bucket),
            key,
        )
```

> [!warning] 버킷 네이밍 규약 주의
> 대상 버킷명을 `{source}-resize`로 구성하는 관례입니다. 별도 이름으로 만든다면 위 코드에서 `{}-resize` 포맷 자리를 실제 대상 버킷 이름으로 바꾸거나, 환경 변수로 읽어 들이도록 수정하세요.

### 9.7 Pillow 레이어 추가

Lambda 런타임에는 `PIL`(Pillow) 이 기본 포함되지 않습니다. `module not found` 에러를 피하려면 외부 라이브러리를 레이어로 첨부합니다.

**EC2에서 Lambda 용 Pillow 레이어 빌드** (Lambda 런타임과 동일한 Amazon Linux 환경 권장):

```bash
# Amazon Linux EC2에 접속
sudo yum update -y
sudo amazon-linux-extras install python3.11 -y   # Lambda 런타임과 같은 버전

# 작업 디렉터리
mkdir -p ~/pillow_layer/python
cd ~/pillow_layer

# 레이어 표준 경로(python/)에 Pillow 설치
python3.11 -m pip install --target python/ Pillow

# zip으로 패키징
zip -r pillow_layer.zip python
```

생성된 `pillow_layer.zip`을 로컬로 내려받은 뒤, Lambda 콘솔에서:

1. Lambda -> 계층 -> 계층 생성
2. zip 파일 업로드 또는 S3 객체 URL 지정
3. 호환 런타임: 함수와 같은 Python 버전
4. 생성

**함수에 레이어 연결**:

1. 함수 상세 -> 계층 -> 계층 추가
2. 사용자 지정 계층, 앞서 만든 레이어 선택, 버전 선택, 추가

### 9.8 테스트 실행

코드 반영은 반드시 "Deploy" 버튼으로 수행합니다. 그 뒤 Test:

1. 테스트 이벤트 구성
2. 템플릿: `s3-put` (S3 PUT 이벤트)
3. 이벤트 JSON에서 `bucket.name`을 `my-demo-origin`, `object.key`를 테스트용 이미지 파일명으로 수정
4. 테스트 실행 전에 `my-demo-origin`에 실제 이미지를 미리 업로드
5. Test 버튼 -> `my-demo-origin-resize` 버킷에 썸네일이 생성되는지 확인

### 9.9 버전 발행과 구성 편집

- **새 버전 발행**: 현재 코드 상태를 스냅샷으로 고정합니다. 트리거를 특정 버전에 고정해 배포 안정성을 확보할 수 있습니다
- **일반 구성 편집**:
    - 메모리: 최대 10,240 MB (CPU는 메모리에 비례 할당)
    - 제한 시간: 최대 15 분

## 10. Lambda + Polly 통합 파이프라인

DynamoDB에서 텍스트를 꺼내 Polly로 음성을 만들고, S3에 올려 URL을 돌려주는 완결된 서버리스 API를 만듭니다.

### 10.1 Lambda 함수의 3 요소 복습

1. **Event Source(트리거)**: S3 업로드, DynamoDB Streams, SNS·SQS, API Gateway, ALB, CloudWatch Events 등
2. **Function(코드)**: 실제 로직. 여러 언어 지원
3. **Execution Role(IAM Role)**: 함수가 접근할 AWS 리소스에 대한 권한

### 10.2 실행 역할 (IAM Role)

IAM -> 역할 -> 역할 만들기:

1. 사용 사례: Lambda
2. 권한 정책 연결 (이 실습에 필요한 4 가지)
    - AmazonS3FullAccess
    - AmazonDynamoDBFullAccess
    - AmazonPollyFullAccess
    - AWSLambdaBasicExecutionRole

### 10.3 app.py - DynamoDB -> Polly -> S3

```python
import boto3
import os
from contextlib import closing

dynamoDBResource = boto3.resource('dynamodb')
pollyClient = boto3.client('polly')
s3Client = boto3.client('s3')


def lambda_handler(event, context):
    UserId = event['UserId']
    NoteId = event['NoteId']
    VoiceId = event['VoiceId']
    mp3Bucket = os.environ['MP3_BUCKET_NAME']
    ddbTable = os.environ['TABLE_NAME']

    text = getNote(dynamoDBResource, ddbTable, UserId, NoteId)
    filePath = createMP3File(pollyClient, text, VoiceId, NoteId)
    signedURL = hostFileOnS3(s3Client, filePath, mp3Bucket, UserId, NoteId)
    return signedURL


def getNote(ddb, ddbTable, UserId, NoteId):
    table = ddb.Table(ddbTable)
    records = table.get_item(Key={
        'UserId': UserId,
        'NoteId': int(NoteId),
    })
    return records['Item']['Note']


def createMP3File(polly, text, VoiceId, NoteId):
    resp = polly.synthesize_speech(
        OutputFormat='mp3',
        Text=text,
        VoiceId=VoiceId,
    )
    filePath = ''
    if 'AudioStream' in resp:
        postId = str(NoteId)
        with closing(resp['AudioStream']) as stream:
            filePath = os.path.join('/tmp/', postId)
            with open(filePath, 'wb') as file:
                file.write(stream.read())
    return filePath


def hostFileOnS3(s3, filePath, mp3Bucket, UserId, NoteId):
    key = UserId + '/' + str(NoteId) + '.mp3'
    s3.upload_file(filePath, mp3Bucket, key)
    os.remove(filePath)
    url = s3.generate_presigned_url(
        ClientMethod='get_object',
        Params={'Bucket': mp3Bucket, 'Key': key},
    )
    return url
```

### 10.4 테스트 이벤트 (event.json)

```json
{
  "UserId": "student",
  "NoteId": "2",
  "VoiceId": "Joey"
}
```

- `UserId` + `NoteId`로 DynamoDB에서 텍스트를 조회합니다
- `VoiceId`는 Polly의 TTS 음성 식별자입니다 (Joey는 영어 남성 음성)

### 10.5 환경 변수 설정 (CLI)

```bash
aws lambda update-function-configuration \

```

앱 코드에서는 `os.environ['MP3_BUCKET_NAME']`로 접근합니다.

### 10.6 Amazon Polly 음성 목록

> [!note] Amazon Polly
> Text-to-Speech 서비스입니다. 수십 개 언어를 지원하며, 표준(Standard)·신경망(Neural) 음성 엔진이 있습니다. 건당·시간 단위 종량제 과금입니다.

- 한국어: Seoyeon
- 영어(US): Joanna, Matthew, Joey, Ivy 등

### 10.7 실행 흐름

1. Lambda 콘솔 -> "Test" 버튼 -> `event.json` 내용 입력
2. `lambda_handler`가 호출됩니다
3. DynamoDB에서 `student/2` 항목의 Note 텍스트를 조회합니다
4. Polly로 해당 텍스트를 MP3로 합성 -> `/tmp/2`에 저장
5. S3 버킷에 `student/2.mp3`로 업로드
6. Presigned URL 반환

> [!example] 서비스 확장 아이디어
> DynamoDB에 새 노트가 insert 될 때 Stream 트리거로 Lambda를 자동 호출하면 MP3가 자동 생성됩니다. 프런트엔드는 S3 정적 웹사이트, 백엔드 API는 API Gateway + Lambda로 둔 서버리스 음성 노트 서비스가 완성됩니다.

## 11. AI 모델을 이 파이프라인에 얹는 법

본편 Part 8에서 만든 AI 서빙 코드는 이 챕터의 구성 요소로 그대로 확장됩니다.

- **HTTP API**: Lambda + API Gateway를 붙이면 Flask 서버 없이도 외부 요청을 받아 모델 추론 결과를 반환할 수 있습니다. 단 모델 로드 시간이 콜드 스타트에 추가되므로 Provisioned Concurrency를 고려합니다
- **큰 모델 추론**: 모델이 Lambda 용량 한계를 넘으면 EC2(+ ALB + Auto Scaling) 조합으로 돌리고, 앞단에 CloudFront를 두어 정적 자산을 캐싱합니다
- **학습 워크로드**: 학습은 Lambda가 아니라 SageMaker Training Job 또는 GPU 탑재 EC2에서 돌리는 것이 표준입니다. 이 부록은 SageMaker 상세는 다루지 않지만, 본편과 부록 C의 IAM·S3·EC2 개념은 SageMaker 진입의 전제입니다
- **데이터 수집**: S3는 업로드 이벤트 기반으로 Lambda를 트리거할 수 있으므로, 사용자가 올린 이미지를 즉시 전처리·라벨링해 학습 데이터로 축적하는 구조를 만들기 쉽습니다

## 13. 부록 C 전체 정리

부록 C 3 개 챕터는 AWS를 처음부터 차근차근 쌓아 올리는 구조였습니다.

| Ch | 주제 | 핵심 |
|---|---|---|
| 01 | AWS 개요 | 클라우드 개념·리전·요금·IAM·VPC |
| 02 | 스토리지와 데이터베이스 | EBS·S3·EFS·Glacier·RDS·DynamoDB·Redshift |

이 세 챕터를 관통하는 질문은 하나였습니다. "내 애플리케이션을, 내가 직접 데이터 센터를 운영하지 않고도, 사용한 만큼만 지불하면서, 전 세계 어디서든 쓸 수 있게 만들려면 어떻게 조립해야 하는가?" 답은 클라우드 인프라 위에서 IAM으로 권한을 자르고, S3·DynamoDB로 데이터를 담고, EC2·Lambda로 코드를 돌리고, CloudFront·Route 53·ALB로 바깥 세상과 연결하는 것입니다.

본편의 AI 코드를 AWS에 얹기 위한 최소 지식은 이 세 챕터로 확보됩니다. 이 위에 SageMaker·API Gateway·Step Functions 같은 AI·통합 서비스를 얹으면 "학습 -> 배포 -> 서비스" 전체 흐름이 클라우드 네이티브로 완성됩니다. 그 다음 단계는 AWS Certified Cloud Practitioner 또는 Solutions Architect Associate 자격증 학습으로 자연스럽게 이어집니다.
