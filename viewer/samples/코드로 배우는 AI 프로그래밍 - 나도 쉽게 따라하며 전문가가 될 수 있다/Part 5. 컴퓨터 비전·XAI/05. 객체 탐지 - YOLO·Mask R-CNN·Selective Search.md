# 05. 객체 탐지 - YOLO·Mask R-CNN·Selective Search

> "이미지 전체의 클래스 한 개"를 분류하는 것은 한 단계고, "이미지 안의 여러 객체 각각의 위치와 종류"를 동시에 찾는 **객체 탐지(Object Detection)**는 다음 단계입니다. 이 챕터에서는 2-stage 계열(R-CNN -> Mask R-CNN)과 1-stage 계열(YOLO)의 두 갈래를 대조하고, 평가지표와 YOLOv5 실습을 짚습니다.

## 1. 분류 vs 탐지 vs 분할

CV에서 "이미지를 본다"는 작업은 난이도에 따라 계층이 나뉩니다.

| 작업 | 출력 | 예시 |
|---|---|---|
| **Classification** | 이미지 한 장 -> 클래스 라벨 1개 | "이 사진은 강아지" |
| **Object Detection** | 여러 박스 + 각 박스의 클래스·점수 | "여기 강아지, 저기 고양이, 저기 사람" |
| **Semantic Segmentation** | 픽셀마다 클래스 라벨 | "이 픽셀은 도로, 저 픽셀은 차" |
| **Instance Segmentation** | 픽셀마다 + 개체별 구분 | "차 1, 차 2, 차 3을 각각 픽셀 마스크로" |

객체 탐지는 분류와 분할 사이에 있으며, 결과물은 "**클래스 + 박스 좌표 (x, y, w, h) + 신뢰도**"의 리스트입니다.

## 2. 두 갈래 접근 - 2-Stage vs 1-Stage

탐지 모델은 크게 두 갈래입니다.

- **2-Stage 계열**: 먼저 "객체가 있을 만한 영역"을 제안(region proposal) 하고, 각 제안에 대해 분류와 박스 정제를 수행. R-CNN -> Fast R-CNN -> Faster R-CNN -> Mask R-CNN 계보. **정확도 우수**, 속도 느림
- **1-Stage 계열**: 이미지 한 번의 CNN 통과로 박스와 클래스를 바로 예측. YOLO 계열, SSD 등. **속도 빠름**, 실시간 응용에 유리

실시간성이 중요하면 YOLO, 최고 정확도가 필요하면 Faster/Mask R-CNN 쪽을 주로 쓰며, 최근에는 YOLOv8·RT-DETR 처럼 두 진영의 장점을 섞은 변종들이 현역입니다.

## 3. 2-Stage 계열 - R-CNN에서 Mask R-CNN까지

### 3.1 Selective Search - 영역 제안의 시작

R-CNN (Girshick 등, 2014)의 1단계는 **Selective Search**라는 비학습 알고리즘으로 약 2,000 개의 후보 영역을 뽑았습니다. 색·질감·크기·형태가 비슷한 인접 영역을 반복적으로 병합해 점진적으로 큰 영역을 만드는 방식입니다.

```python
# OpenCV contrib에 구현되어 있습니다
import cv2

ss = cv2.ximgproc.segmentation.createSelectiveSearchSegmentation()
ss.setBaseImage(img)
ss.switchToSelectiveSearchFast()           # 빠른 모드
rects = ss.process()                        # (N, 4) 박스 리스트
```

Selective Search로 제안된 영역 각각을 CNN에 넣어 분류하는 것이 R-CNN의 원형 구조였습니다. 2천 번의 CNN 추론이 느렸기 때문에 Fast R-CNN (이미지 한 번만 통과), Faster R-CNN (RPN으로 제안 단계도 학습)으로 빠르게 진화했습니다.

### 3.2 Mask R-CNN

**Mask R-CNN** (He 등, 2017)은 Faster R-CNN 위에 **픽셀 단위 마스크 예측 브랜치**를 얹은 모델입니다. 박스만 찾는 것이 아니라, 박스 안에서 "이 객체의 모양"을 픽셀 마스크로 출력하는 **인스턴스 분할** 기능까지 제공합니다.

구조를 요약하면 다음과 같습니다.

```text
입력 이미지
  -> Backbone CNN (ResNet 등)
  -> RPN (Region Proposal Network)     : 후보 박스 제안
  -> RoI Align                          : 후보 박스를 고정 크기로 추출
  -> 3개 브랜치 병렬:
      - 클래스 분류
      - 박스 좌표 정제
      - 마스크 예측 (픽셀 단위)
```

정확도는 매우 높지만 실시간이 어렵고 GPU 메모리를 많이 씁니다. 의료 영상 분할·정확한 오브젝트 크롭이 필요한 영역에서 여전히 현역입니다.

## 4. 1-Stage 계열 - YOLO

**YOLO (You Only Look Once, Redmon 등, 2016)**는 "이미지를 그리드로 나누고, 각 그리드 셀이 담당 영역의 박스와 클래스를 직접 예측" 하는 구조로 등장했습니다. 단일 CNN 통과 한 번으로 모든 박스를 얻어 속도가 극적으로 빠르고, 실시간 비디오·자율주행·드론 등에서 사실상 표준으로 자리 잡았습니다.

### 4.1 핵심 아이디어

- 이미지를 `S × S` 그리드로 분할 (예: 7×7, 13×13)
- 각 셀은 **앵커 박스** `B` 개씩을 후보로 가짐
- 각 박스는 `(x, y, w, h, objectness, class_probs)`를 출력
- 한 번의 forward pass로 모든 후보 박스의 예측을 얻음
- 후처리로 아래 5.2에서 설명할 NMS를 적용해 겹치는 박스 정리

초기 YOLOv1은 GoogLeNet에서 영감을 받은 24-layer 커스텀 CNN을 backbone으로 썼고, v3 이후 Darknet 기반으로 자체 backbone이 자리 잡았습니다. 즉, YOLO 계열은 버전이 올라가며 backbone과 학습 전략이 계속 바뀌어 왔습니다.

최근에는 **Ultralytics**가 PyTorch 기반 생태계를 정리하면서 학습·추론·배포 도구를 한 패키지로 묶어, 실무 진입 장벽을 크게 낮췄습니다.

### 4.2 YOLO 계열의 흐름

| 버전 | 등장 | 특징 |
|---|---|---|
| YOLOv1 | 2016 (Redmon) | 단일 패스 아이디어의 원형. GoogLeNet 영감 24-layer CNN |
| YOLOv2 | 2017 (Redmon & Farhadi) | Anchor box 도입, YOLO9000 (9000 클래스 joint 학습) |
| YOLOv3 | 2018 (Redmon & Farhadi) | 다중 스케일 예측, anchor 개선 |
| YOLOv5 | 2020 (Ultralytics) | PyTorch 기반 재구현, 실무 활용성 대폭 향상 |
| YOLOv8 | 2023 (Ultralytics) | anchor-free, 분할·자세 추정까지 통합 |

실무에서는 오픈소스 성숙도와 커뮤니티 규모 덕에 YOLOv5 / YOLOv8이 압도적으로 많이 쓰입니다.

## 5. 평가지표 - IoU, NMS, mAP

### 5.1 IoU (Intersection over Union)

예측 박스와 정답 박스의 겹침 정도를 0~1로 측정합니다.

```text
IoU = (교집합 면적) / (합집합 면적)
```

- `1.0`: 두 박스가 완전히 일치
- `0.5` 정도: 합격 기준으로 흔히 쓰임 (PASCAL VOC)
- `0.0`: 겹치지 않음

IoU가 임계값(보통 0.5) 이상이면 "올바르게 탐지"로 간주합니다. 학습 시 손실 함수의 일부로도 들어갑니다.

```python
def iou(b1, b2):
    # b = (x, y, w, h), (x, y)는 좌상단 기준.
    # YOLO 라벨 포맷인 (cx, cy, w, h)를 쓰려면 (cx - w/2, cy - h/2, w, h)로 변환 후 전달.
    x1 = max(b1[0], b2[0])
    y1 = max(b1[1], b2[1])
    x2 = min(b1[0] + b1[2], b2[0] + b2[2])
    y2 = min(b1[1] + b1[3], b2[1] + b2[3])
    inter = max(0, x2 - x1) * max(0, y2 - y1)
    union = b1[2] * b1[3] + b2[2] * b2[3] - inter
    return inter / union if union > 0 else 0.0
```

### 5.2 NMS (Non-Maximum Suppression)

모델이 같은 객체에 대해 여러 겹치는 박스를 내놓는 경우가 많습니다. **NMS**는 "서로 IoU가 높은 박스들 중 신뢰도가 가장 높은 하나만 남긴다"는 후처리입니다.

```text
1. 박스를 신뢰도(score) 내림차순으로 정렬
2. 맨 위 박스를 결과에 넣고 목록에서 제거
3. 남은 박스 중 방금 결과로 간 박스와 IoU > 임계값(예: 0.5) 인 것을 모두 제거
4. 남은 박스가 없을 때까지 1~3 반복
```

OpenCV와 PyTorch 모두 NMS 함수를 기본 제공합니다 (`cv2.dnn.NMSBoxes`, `torchvision.ops.nms`).

### 5.3 mAP (mean Average Precision)

탐지 모델의 종합 성능 지표입니다.

- 각 클래스에 대해 신뢰도 임계값을 0~1로 바꿔 가며 precision-recall 곡선을 그린다
- 그 곡선 아래 면적이 **AP (Average Precision)**
- 전체 클래스의 AP를 평균한 값이 **mAP**
- IoU 임계값 `0.5` 기준이 흔히 쓰이고 (`mAP@0.5`), `0.5 ~ 0.95` 평균(`mAP@[.5:.95]`)은 COCO의 엄격한 지표

mAP는 결국 "클래스별 AP의 평균"이라고 이해하면 됩니다. 연구 논문이나 Kaggle 리더보드에서 볼 수 있는 "mAP 50" / "mAP 50-95" 같은 수치가 이것입니다.

## 6. Ultralytics YOLO 실습 맛보기

Ultralytics YOLO는 명령줄·Python API 둘 다 제공합니다. 사전학습 모델로 즉시 추론부터 해 볼 수 있습니다.

### 6.1 설치와 추론

```bash
pip install ultralytics
```

```python
from ultralytics import YOLO

# 사전학습된 YOLOv8n (nano) - 소형이라 빠르게 테스트
model = YOLO("yolov8n.pt")

# 이미지 한 장 추론
results = model("street.jpg")
results[0].boxes.xyxy     # 박스 좌표
results[0].boxes.cls      # 클래스 번호
results[0].boxes.conf     # 신뢰도
results[0].save(filename="out.jpg")   # 주석이 그려진 결과 저장
# 또는 추론 시점에: model("street.jpg", save=True)
```

사전학습 모델은 COCO 80 클래스(사람·자동차·개·고양이 등)로 학습되어 있어 일반 사진에 바로 쓰면 꽤 잘 작동합니다.

### 6.2 커스텀 데이터 학습

자기 도메인(헬멧 검출·손 검출 등)에 맞추려면 데이터셋을 YOLO 형식으로 준비한 뒤 명령줄 한 줄로 학습합니다.

```text
dataset/
  data.yaml           # 클래스 이름·경로 정의
  images/train/*.jpg
  images/val/*.jpg
  labels/train/*.txt  # 각 이미지 라벨: class x_center y_center w h (정규화)
  labels/val/*.txt
```

`data.yaml` 예시:

```yaml
train: dataset/images/train
val:   dataset/images/val
names:
  0: hat
  1: no-hat
```

학습:

```bash
yolo detect train data=dataset/data.yaml model=yolov8n.pt epochs=50 imgsz=640
```

학습이 끝나면 `runs/detect/train/weights/best.pt`에 가중치가 저장됩니다. 새 이미지에 추론할 때도 방식이 동일합니다.

```python
model = YOLO("runs/detect/train/weights/best.pt")
results = model("test.jpg")
```

### 6.3 실전 팁

- **데이터 라벨링**: Roboflow·CVAT·LabelImg 같은 도구로 박스 라벨을 만듭니다. 라벨 품질이 최종 성능을 좌우합니다
- **소규모 데이터**: 전이학습이 이미 기본이라 200~500 장 정도로도 실용적 결과가 나옵니다
- **증강**: Ultralytics는 기본 증강이 강력하게 켜져 있어 별도 튜닝이 크게 필요하지 않습니다
- **비디오·스트림**: `model("video.mp4", stream=True)`로 실시간 처리 가능
- **작은 객체**: `imgsz=1280`으로 입력 해상도를 키우거나, 큰 모델(`yolov8m` 이상)로 교체

## 7. 마무리

객체 탐지는 분류 한 장 위에 "여러 객체 + 위치"라는 차원을 얹은 문제입니다. 정확도를 우선하면 Mask R-CNN 계열, 속도와 실시간성이 우선이면 YOLO 계열이라는 이분법이 오랫동안 유지됐고, 최근에는 이 경계가 흐려지는 방향으로 발전하고 있습니다. 평가지표인 IoU·NMS·mAP는 모델·프레임워크가 바뀌어도 그대로 쓰이는 공통 언어이므로 한 번 단단히 잡아 두면 다음 모델로 넘어갈 때 재학습 비용이 거의 없습니다.
