# 책 프로젝트: 코드로 배우는 AI 프로그래밍

이 문서는 이 폴더에서 Claude Code(및 서브 에이전트)가 작업할 때 읽는 **설계 문서 겸 작업 지침**이다. 루트 `CLAUDE.md`(볼트 전체 규칙)를 먼저 따르고, 이 문서는 이 책 프로젝트에만 적용되는 추가 규칙을 담는다.

- 작성일: 2026-04-20
- 상태: 설계 (v0.9)
- 원본 자료: `notes/1. 파이썬 활용 인공지능 이론과 실습/`, `notes/2. 머신러닝_딥러닝 고급 기술과 AWS 클라우드 실습/`, `notes/3. 지식공학, 머신러닝_딥러닝을 활용한 AI 서비스 기획 및 구현/` 의 정제본

## 1. 이 책은 왜 만드는가

AI 특강 3강좌(각 120시간, 총 360시간)의 원본 스크립트를 `강의정제.md` 스킬로 self-contained 정제본(약 40,000줄)으로 1차 가공했다. 정제본은 **강의 회차 단위**로 작성되어 있어 다음 문제가 있다.

- 한 강에 여러 주제가 섞임 (예: 3강좌 33강 = 메타버스 + NFT + ResNet50 전이학습)
- 같은 주제가 여러 강에 분산 (예: 전이학습은 2·3강좌에 걸쳐 8~9회 재등장)
- AI 역사, 윤리, 메타버스, 블록체인 등 비-기술 주제가 기술 주제와 섞여 있음

이 상태로는 **학습 레퍼런스**로 쓰기 어렵다. "딥러닝 CNN 배우고 싶다"는 사람이 주제를 보려면 여러 강에 흩어진 조각을 독자가 찾아 다녀야 한다. 이 책은 정제본을 **주제별로 재편성**하여 레퍼런스이자 튜토리얼로 쓸 수 있는 기술서로 만드는 **2차 가공**이다.

### 1.1 1차·2차 목표

| 순위 | 목표 | 설명 |
|---|---|---|
| 1차 (주) | 학습 레퍼런스·기술서 | 주니어~중급 개발자가 파이썬·기초 수학은 아는 상태로 "AI를 실무에서 써먹기 위해" 손에 쥘 교재. 코드 위주, 따라하기 쉬운 톤 |
| 2차 (부) | 자기 자산·포트폴리오 어필 | 목차·챕터 구성만 봐도 "이 저자가 어디까지 다뤄봤는지" 드러나게. 면접·이력서 연장선에서 활용 가능 |

1차가 기본 방향이다. 2차는 1차를 충실히 하면 자연스럽게 따라오도록 설계한다. 2차를 위해 1차의 톤을 굽히지 않는다.

### 1.2 타깃 독자

- 파이썬·기초 수학(미분·행렬 기본)은 아는 주니어~중급 개발자
- "AI 입문서"가 아니라 "AI를 실무에서 활용하기 위한 기술서"를 찾는 독자
- 현재 정제본 톤(기술 블로그, 코드·수식 포함)과 같은 눈높이

## 2. 책의 철학

### 2.1 레퍼런스북과 튜토리얼북의 결합

- **레퍼런스북 성격**: 각 챕터가 **자족적**으로 읽힌다. 관심 있는 Part만 독립적으로 읽어도 된다.
- **튜토리얼북 성격**: 1장부터 순서대로 읽으면 **학습 흐름**이 끊기지 않는다. Part 구성은 의존 관계를 고려해 배열된다.

두 성격은 상충하기 쉬운데, 이 책은 다음 원칙으로 조화시킨다.

- Part·챕터 **순서**는 튜토리얼북(학습 흐름)을 기준
- Part·챕터 **본문**은 레퍼런스북(자족성)을 기준
- 선행 개념이 필요해도 **독자 본문에는 메타 안내를 노출하지 않는다**. AI 작업용 정보는 frontmatter 안의 `#` YAML 주석으로 기록하고, 본문에서는 정말 필요한 경우에만 자연스럽게 "앞서 다룬 ..." 정도로 언급한다

### 2.2 코드 위주, 따라하기 쉬운 톤

- 개념 설명은 간결하게, **코드와 실행 결과는 풍성하게**
- 수학·이론은 "왜 이 코드가 이렇게 작동하는가"를 이해할 만큼만
- 각 챕터는 가능한 한 실행 가능한 최소 예제로 시작해 점진적 확장
- 데이터셋·실습 환경은 재현 가능한 형태로 명시 (버전·경로·준비 스크립트)

### 2.3 기술 주제 중심, 비-기술은 부록으로

- AI 윤리·프라이버시·철학·메타버스·NFT·블록체인 등 비-기술 주제는 **부록**으로 분리
- 본편 Part는 기술 주제만 담는다. 어떤 주제가 본편이고 어떤 것이 부록인지는 [[MOC]] 참조

## 3. 원본과의 관계

### 3.1 절대 규칙

- `notes/1, 2, 3/` 아래 원본 정제본은 **건드리지 않는다**. 읽기 전용.
- 이 책 폴더(`books/코드로 배우는 AI 프로그래밍 - 나도 쉽게 따라하며 전문가가 될 수 있다/`)는 원본을 **재작성·재배치**한 결과물이다.

### 3.2 재작성 방식의 이유

원본을 책으로 엮는 방식은 4가지 후보가 있었다. 최종 선택은 (d)이다.

| 방식 | 장점 | 단점 | 판정 |
|---|---|---|---|
| (a) 원본 파일 이동 | 중복 없음 | 원본 파괴, 강좌 단위 서사 손실 | 탈락 |
| (b) 트랜스클루전(`![[...]]`) 임베드만 | 중복 없음, 자동 동기 | PDF·외부 공개 시 경계 깨짐. 원본의 강의 맥락 문장이 그대로 들어와 레퍼런스북 톤이 무너짐 | 탈락 |
| (c) 섹션 복사-붙여넣기 | 독립적 | 학습 흐름에 맞춘 재편집이 안 되어 책 톤 안 맞음 | 탈락 |
| (d) 재작성 (원본 참조하며 본문을 새로 씀) | 책 톤·자족성·학습 흐름 모두 확보 | 작성 비용 큼, 원본과 이중 유지 | 선택 |

### 3.3 재작성 규칙

- 섹션(`##` 헤더) 단위로 분해해 주제별로 재배치. 강 단위 이동은 금지(한 강에 여러 주제가 섞인 경우가 많기 때문).
- 강의 맥락 문장·단어 제거 (§3.4 독자 은닉 원칙 참조)
- 학습 흐름에 맞게 순서 재배치. 같은 주제가 여러 강에 중복되면 가장 잘 정리된 버전을 기준으로 통합
- **독자 이해가 최우선**이다. 원본 정제본은 **기본 참조처**이며 절대 기준이 아니다. 원본을 기계적으로 베끼지 말고, 독자에게 가장 잘 전달되는 방식을 택한다
- 원본의 **내용**(다룬 주제·개념·기술 팩트)은 빠뜨리지 않는다. 내용을 누락해 책의 퀄리티가 떨어지면 안 된다
- 원본의 **설명 방식**은 우선 참고하되, 독자 이해에 더 나은 접근이 있으면 그쪽을 택하고, 원본의 설명이 오히려 방해되면 개선·재구성한다. 원본 설명이 최적이면 그대로 존중
- 원본에 없는 내용도 **독자에게 도움이 되면 추가**한다. 책 재구성은 2차 가공이므로 강의정제 단계의 "원본에 없는 내용 추가 금지" 규칙은 **완화**된다
- 원본 외 내용 추가 시 원칙:
    - **기술적 사실에 근거**해야 한다. 공식 문서, 표준 라이브러리 동작, 검증 가능한 소스가 근거일 것
    - **거짓말·환각 절대 금지**. 그럴듯하게 아무말을 지어내는 것은 책 전체의 신뢰를 무너뜨린다. 확신이 없으면 추가하지 않거나 불확실성을 본문에 명시
    - 원본이 낡은 환경·도구를 쓰고 있다면 **현대 실무 표준으로 재편하는 것을 권장** (예: Anaconda+Jupyter Notebook → VSCode+Jupyter 확장)
    - 불확실한 수치·역사·인용은 추가하지 않거나 "출처 확인 필요" 플래그로 남긴 뒤 사람에게 검수 요청
- 각 챕터 frontmatter 안의 `# source:` YAML 주석에 **출처 원본 경로를 반드시 기록** (§5.3 참조). 원본 외 내용을 추가한 챕터는 `source` 에 "+ 외부 자료(공식 문서 등)" 를 명시할지 §5.3 에서 별도 규정 가능

### 3.4 독자에게 원본(3개 강좌)을 은닉

이 책은 **처음부터 쓴 기술서로 읽히도록** 한다. 독자는 이 내용이 3개 강좌(파이썬 활용 AI 이론과 실습·머신러닝/딥러닝 고급 기술과 AWS 클라우드 실습·지식공학 기반 AI 서비스 기획 및 구현)를 기반으로 재구성됐다는 사실을 **알 필요 없다**. 원본 강좌·강의·교수·회차·수업 운영 맥락은 본문에서 **일체 드러내지 않는다**.

- 저자(사용자)·재구성 에이전트(Claude)는 챕터의 frontmatter 안 `#` 주석, CLAUDE.md, MOC.md 를 통해 원본을 안다. 이건 **내부용**
- 독자는 완성된 본문에서 내부 메타를 볼 필요가 없다. 따라서 원본 추적 정보는 **본문이 아니라 frontmatter 안 `#` 주석에만** 둔다
- **본문에서 금지되는 표현**:
    - 강의·강좌·수업·교수·강사·수강생·동료·학생·팀·팀원 같은 학습 맥락 단어
    - "오늘 수업에서는", "지난 시간에", "이번 강의에서는", "과제로", "중간 발표에서", "기말 발표에서"
    - 강의 회차 지칭 ("1강에서", "10강에서는", "지난 회차")
    - 강좌 이름 ("파이썬 활용 인공지능 이론과 실습에서", "3강좌에서")
    - "(사전 녹화)", "라이브 강의", "LMS" 같은 운영 맥락
    - 교수·강사·수강생 실명, 그들의 개인 에피소드 삽입
- **허용되는 표현**: "이 책에서는", "앞서 Part N 에서 다룬 ...", "다음 챕터에서 이어진다" 같은 **책 내부 참조**는 자연스럽게 사용
- 본문 톤은 "저자가 독자에게 직접 가르치는" 기술서. 강의 요약·노트가 아니라 **스스로 선 책**으로 읽혀야 한다

§3.3 의 "강의 맥락 문장·단어 제거" 규칙은 이 §3.4 의 구체적 적용이다.

## 4. 폴더 구조

고정 파일과 고정 폴더만 여기에 명시한다. 구체적 Part 폴더 이름·개수는 [[MOC]] 에 따라 결정되므로 이 문서에 박지 않는다.

```
books/코드로 배우는 AI 프로그래밍 - 나도 쉽게 따라하며 전문가가 될 수 있다/
├── CLAUDE.md                ← 이 문서 (설계 원칙·재작성 규칙)
├── MOC.md                   ← 목차 허브 (Part 구조·상세 챕터, 독자 관점)
├── 원본매핑.md               ← 원본 정제본 섹션 -> 책 Part·챕터 매핑 트래킹 (저자·에이전트 내부용)
├── !book.base               ← Bases 뷰, 전체 챕터 메타데이터 일람 (작성 예정)
├── 00. 들어가며/             ← 서문·이 책 읽는 법·실습 환경 준비
├── Part {N}. {제목}/          ← 본편 Part. MOC.md 기준
│   ├── _assets/              ← 해당 Part 그림·도식·스크린샷
│   └── {NN}. {챕터 제목}.md
└── 부록 {X}. {제목}/          ← 비-기술 주제 부록. MOC.md 기준
```

- Part 폴더 앞 `Part N. ` 프리픽스로 옵시디언 자연 정렬
- 챕터 파일도 `NN. xxx.md` 프리픽스 정렬
- 부록은 모든 본편 Part 뒤, 즉 책의 맨 끝으로 배치

### 4.1 이미지 자산 규칙

- 책 그림은 볼트 공용 첨부 폴더로 모으지 않고 **해당 Part 폴더의 `_assets/`** 에 둔다
- Obsidian 임베드는 **bare 파일명** 을 기본으로 쓴다. 예: `![[p2-train-test-validation.svg|700]]`
- 파일명은 **`p{part}-{짧은설명}.{ext}`** 형식을 기본으로 한다. 예: `p2-train-test-validation.svg`
- 챕터 번호(`ch01`)·그림 번호(`fig01`) 는 파일명에 기본적으로 넣지 않는다. 챕터 재정렬 시 rename 비용이 커지기 때문이다
- 도식·박스·화살표·벡터 기반 그림은 `.svg`, 스크린샷·사진은 `.png` 를 우선한다
- 캡션은 이미지 바로 아래 본문 한 줄로 적는다. 예: `*그림 1. 학습·검증·테스트 데이터 분할*`

## 5. 챕터 파일 스키마

### 5.1 frontmatter 예시

아래는 한 챕터의 frontmatter 형식 예시다. `part`·`chapter` 의 구체 값은 [[MOC]] 기준 실제 값으로 기입한다.

```yaml
---
part: 5
chapter: 3
title: 전이학습으로 Distracted Driver 분류하기
summary: MobileNet 사전학습 가중치를 freeze한 뒤 마지막 층만 재학습해 10클래스 분류를 빠르게 구현
keywords: [전이학습, MobileNet, Keras, Fine-tuning]
# source:
#   - "[[머신러닝_딥러닝 고급 기술과 AWS 클라우드 실습 26강]]"
#   - "[[지식공학, 머신러닝_딥러닝을 활용한 AI 서비스 기획 및 구현 7강]]"
# prerequisites:
#   - "[[Part 4. 딥러닝 기초/05. CNN 기초]]"
generated_by: ai-assisted
tags: [ai-generated, book, 전이학습, MobileNet]
---
```

### 5.2 필드 의미

| 필드 | 필수 | 설명 |
|---|---|---|
| `part` | 필수 | Part 번호. 숫자. Bases 정렬용 |
| `chapter` | 필수 | Part 내 챕터 번호. 숫자 |
| `title` | 필수 | 챕터 제목 (프리픽스 숫자 없이) |
| `summary` | 필수 | 한 줄 요약. LLM 스캔 및 독자 미리보기용 |
| `keywords` | 권장 | 기술 키워드 배열. 검색·Bases 필터링용 |
| `generated_by` | 필수 | AI가 재작성했으면 `ai-assisted`, 사람이 재작성했으면 생략 |
| `tags` | 필수 | `ai-generated`, `book` 과 주제 태그 |

### 5.3 출처 추적 원칙

- frontmatter 안 `# source:` 주석은 거짓말하지 않는다. **해당 챕터 본문에 실제로 녹아 있는 원본 정제본만** 기록
- 원본 정제본이 수정되면 `source` 로 연결된 챕터를 역추적해 재점검 (루틴 작업 예정)
- 볼트 규칙: YAML 값이 따옴표로 시작하면 홑따옴표로 래핑

### 5.4 YAML 주석 메타

- 독자에게 직접 필요하지 않은 작업 메모는 frontmatter 안 `#` YAML 주석으로 기록한다
- 출처와 선행 개념은 다음 형식으로 남긴다

```yaml
---
part: 5
chapter: 3
title: 전이학습으로 Distracted Driver 분류하기
summary: MobileNet 사전학습 가중치를 freeze한 뒤 마지막 층만 재학습해 10클래스 분류를 빠르게 구현
keywords: [전이학습, MobileNet, Keras, Fine-tuning]
# source:
#   - "[[머신러닝_딥러닝 고급 기술과 AWS 클라우드 실습 26강]]"
# prerequisites:
#   - "[[Part 4. 딥러닝 기초/05. CNN 기초]]"
generated_by: ai-assisted
tags: [ai-generated, book, 전이학습, MobileNet]
---
```

- `# source:` 는 모든 챕터에 기록한다
- `# prerequisites:` 는 **강한 의존이 있는 챕터에만** 기록한다
- 강한 의존의 기준은 이 챕터를 독립적으로 읽거나 실행하기 어렵고, 앞선 챕터의 개념·설정·산출물을 사실상 전제로 삼는 경우다
- 단순히 먼저 읽으면 더 편한 정도의 약한 연결에는 `# prerequisites:` 를 쓰지 않는다
- 독자 안내 문구인 `> 선행: ...` 는 사용하지 않는다

## 6. Part 대분류·목차

Part 대분류, 원본 정제본 매핑, 제외·축약 대상, Part별 상세 챕터 목차는 모두 별도 파일 [[MOC]] 에 정리한다. 이 CLAUDE.md 는 설계 원칙·재작성 규칙·볼트 규칙만 담고, 목차 구조 변경은 MOC.md 쪽에서 수행한다.

## 7. 작업 방식

### 7.1 재작성 실행 전략

- **섹션 단위 분해 후 주제별 재배치**가 기본 단위. 강 단위 이동 금지(§3.3)
- 재작성은 AI 서브 에이전트가 수행하고, 사람이 구조·톤·최종 검수 담당
- 반복되는 재작성 작업을 표준화하기 위해 **`책재구성.md` 스킬 문서**를 추후 작성 예정 (`강의정제.md` 구조를 참고해 self-contained 스킬로)

### 7.2 작업 순위

1. Part별 챕터 상세 목차 확정 ([[MOC]] §1 각 Part의 `챕터:` 아래 확장)
2. `00. 들어가며/` 서문·실습 환경 챕터 작성
3. MOC.md 기준 본편 Part 순서대로 재작성
4. 진행하며 필요시 선행 개념·크로스 레퍼런스 재조정
5. `MOC.md`, `!book.base` 는 챕터가 채워지는 대로 점진적으로 업데이트

### 7.3 AI 생성물 마커

- 재작성 본문은 AI가 작성하므로 모든 챕터 frontmatter에 `generated_by: ai-assisted`, `tags: [ai-generated, book, ...]` 를 명시
- 사람이 초안을 직접 쓰고 AI가 포맷팅만 한 경우도 `ai-assisted`. 사람이 직접 쓴 케이스는 `generated_by` 생략
- 루트 `CLAUDE.md` §"AI 생성 노트 규칙" 준수

## 8. 볼트 규칙 (이 폴더 내에서도 반드시 준수)

- em-dash `—` 사용 금지. 하이픈 `-` 또는 쉼표·괄호로 대체
- frontmatter `---` 종료선 바로 다음 줄에 `#` 제목 또는 본문 시작 (빈 줄 금지)
- 태그에 공백 금지. 하이픈 사용 (예: `Transfer-Learning`)
- YAML frontmatter 값이 따옴표로 시작하면 홑따옴표로 래핑 (`summary: '"x" 추가텍스트'`)
- callout·table 내부에서 `=` 포함 inline 백틱 금지 (Dataview 파싱 오류 유발)
- LF 줄바꿈 (`.gitattributes` 기본값)
