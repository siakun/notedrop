# 01. 실습 환경 준비 - VSCode와 Jupyter 확장

> 이 장에서는 이 책의 실습을 한곳에서 이어 갈 수 있는 개발 환경을 준비합니다. Python 인터프리터와 VSCode, Jupyter 확장을 함께 설정하고, 프로젝트마다 가상환경을 나누어 패키지가 서로 섞이지 않도록 하겠습니다.

## 1. 왜 이 조합인가요

실습 환경으로는 몇 가지 선택지가 있지만, 이 책은 처음부터 **VSCode + Python 확장 + Jupyter 확장**을 기준으로 진행합니다.

AI 실습에서는 코드를 한 번에 길게 작성하는 것보다, 셀 단위로 나누어 실행하면서 중간 결과를 바로 확인하는 과정이 중요합니다. 배열의 모양이 맞는지, 표가 예상대로 읽혔는지, 그래프가 어떻게 나오는지, 모델 출력이 어디서 달라지는지를 한 단계씩 눈으로 확인해야 하기 때문입니다. 그래서 이 책은 단일 `.py` 파일 하나만 붙들고 가는 방식보다 `.ipynb`로 작업 단위를 나누어 실행할 수 있는 환경을 기본으로 삼습니다.

- **VSCode + Python 확장 + Jupyter 확장** (✅, 이 책이 추천하는 환경):
    - 노트북 셀 실행, 코드 편집, 터미널, 디버깅을 한 창에서 처리할 수 있습니다. 이미 VSCode에 익숙한 독자도 많고, 뒤에서 Flask 서버나 배포 스크립트를 다룰 때도 편집기를 바꾸지 않아도 됩니다. 지금은 VSCode의 `.ipynb` 지원과 Jupyter 확장만으로도 이 책 실습에 필요한 셀 실행, 커널 선택, 출력 확인을 처리할 수 있습니다.
- **Anaconda + Jupyter** (❌, 실습으로 권장하지 않는 환경):
    - 데이터 분석 입문에서 가장 널리 쓰인 조합 중 하나이고, 설치하면 Jupyter Notebook과 주요 패키지가 함께 들어와 시작은 빠릅니다. 다만 이 책은 배포판 전체를 먼저 익히기보다 Python 설치, 가상환경 생성, 패키지 설치를 직접 해 보는 흐름을 택합니다. 뒤로 갈수록 서버 코드와 배포 스크립트도 다뤄야 하므로, 처음부터 편집기와 실행 환경을 분리해 두지 않겠습니다.
- **PyCharm 같은 IDE** (❌, 실습으로 권장하지 않는 환경):
    - 디버깅과 리팩터링은 강하지만, 노트북 작업이 별도 흐름으로 분리되는 경우가 많습니다. 설정과 버전에 따라 `.ipynb` 작업이 VSCode처럼 같은 화면 안에서 이어지지 않고 Jupyter 쪽 흐름으로 넘어가기도 해서, 이 책처럼 `.py` 파일과 `.ipynb` 파일을 오가며 실습하기에는 맞지 않습니다.

## 2. Python 설치

이 책은 Python **3.12** 계열을 기준으로 진행합니다. 처음 설치할 때는 가장 최신 버전을 받아야 할 것처럼 느껴질 수 있지만, 실습 환경에서는 새 기능보다 예제가 안정적으로 그대로 실행되는 편이 더 중요합니다. 2026년 4월 집필 시점에는 3.12 계열이 이미 새 기능 추가와 일반 버그 수정이 끝나고 보안 패치만 이어지는 단계에 들어가 있었고, Windows와 macOS용 설치 파일이 함께 제공된 마지막 버전은 **3.12.10**이었습니다. 그래서 이 책에서는 [python.org/downloads](https://www.python.org/downloads/)에 들어간 뒤 **All releases**에서 **Python 3.12.10**을 찾아 설치하겠습니다.

이 책은 NumPy, Pandas, scikit-learn 같은 주요 라이브러리를 함께 사용하므로, 전체 예제를 검증한 버전에 맞춰 두는 편이 훨씬 안정적입니다. 이 책의 실습 코드는 **Python 3.12.10**에서 검증했습니다. 반면 2026년 4월 기준으로 Python 3.15는 아직 pre-release 단계였으므로, 처음 실습 환경을 맞추는 버전으로는 권하지 않겠습니다.

버전 번호도 여기서 한 번만 짚고 넘어가겠습니다. `3.12.10`은 `major.minor.patch` 형식이며, 각각 큰 버전, 기능 버전, 패치 버전을 뜻합니다. 같은 `3.12.x` 안에서는 패치 번호만 달라질 뿐 문법이나 사용 방식이 크게 달라지지는 않습니다. 이 책에서는 설치 파일을 받을 수 있는 마지막 3.12 버전인 3.12.10을 기준으로 설명을 이어가겠습니다.

아래 그림처럼 Python 다운로드 페이지에서는 각 버전의 릴리스 단계와 지원 상태를 함께 확인할 수 있습니다.

![[python-version-releases.png|600]]

1. 다운로드한 설치 관리자를 실행합니다.
2. 첫 화면 하단의 **Add python.exe to PATH**를 반드시 체크합니다. 이 항목을 놓치면 터미널에서 `python` 명령이 인식되지 않아 이후 실습이 막힐 수 있습니다.
3. **Install Now**를 클릭합니다.

> [!warning] Windows 사용자라면 Microsoft Store판 Python이 이미 깔려 있을 수 있습니다. Store판은 경로 구조가 달라서 `pip install`이나 가상환경 생성에서 예상과 다르게 동작하는 경우가 있습니다. 터미널에서 `where python`을 실행해 Store 경로(`WindowsApps`)가 잡혀 있다면, Windows 설정 → **앱 실행 별칭**에서 Python 관련 항목을 꺼 두는 편이 이후 충돌을 줄여 줍니다.

설치가 끝나면 터미널을 새로 열고 버전을 확인합니다.

```bash
python --version
# Python 3.12.x

pip --version
# pip 24.x.x
```

두 명령 모두 버전 숫자가 나오면 정상입니다. `python` 명령이 인식되지 않으면 PATH 설정이 빠진 상태이므로, 설치 관리자를 다시 실행해 **Modify → Add to PATH**를 활성화한 뒤 터미널을 다시 열어 확인합니다. macOS·Linux는 대부분 기본 PATH에 포함되어 있어 이 문제가 생기지 않습니다.

## 3. VSCode 설치와 확장

VSCode 자체는 가벼운 텍스트 편집기에 가깝고, Python이나 Jupyter 지원은 확장(Extension)을 통해 추가하는 구조입니다. 설치할 확장은 두 개뿐이니 금방 끝납니다.

1. [code.visualstudio.com](https://code.visualstudio.com/)에서 운영체제에 맞는 설치 파일을 다운로드해 설치합니다.
2. VSCode를 실행한 뒤, 좌측 사이드바에서 **Extensions** 아이콘(블록 네 개 모양)을 클릭합니다.
3. 다음 두 확장을 검색해 각각 **Install**을 누릅니다.
    - **Python** (게시자: Microsoft) — 설치하면 Pylance(코드 자동완성·타입 힌트를 담당하는 언어 서버)와 Python Debugger가 함께 들어옵니다. `.py` 파일을 편집하거나 디버깅할 때 기본이 되는 확장입니다.
    - **Jupyter** (게시자: Microsoft) — `.ipynb` 파일을 VSCode 안에서 바로 열고, 셀 단위로 실행하고, 출력을 확인할 수 있게 해 줍니다. 이 확장이 없으면 노트북 파일은 JSON 텍스트로만 보입니다.

두 확장을 설치하고 나면, 이 책 실습에 필요한 편집기 쪽 준비는 끝입니다.

## 4. 프로젝트 폴더와 가상환경

Python 패키지는 전역에 설치하면 프로젝트마다 버전이 엉키기 쉽습니다. 예를 들어 한 실습에서 `numpy 1.26`을 쓰고, 다른 실습에서 `numpy 2.0`을 설치하면 먼저 만든 쪽이 깨질 수 있습니다. 가상환경은 프로젝트 폴더 안에 독립된 Python 사본과 패키지 저장소를 만들어 이 문제를 막아 줍니다.

Python 3.3부터 표준 라이브러리에 포함된 `venv` 모듈을 사용하면 별도 설치 없이 가상환경을 만들 수 있습니다. 이 책에서는 프로젝트 이름을 `ai-learn`으로 두고 진행합니다.

먼저 프로젝트 폴더를 만들고 VSCode로 엽니다.

```bash
mkdir ai-learn
cd ai-learn
code .
```

VSCode 메뉴 **Terminal → New Terminal**로 통합 터미널을 연 뒤, 가상환경을 생성합니다.

```bash
python -m venv ai-learn
```

이 명령을 실행하면 프로젝트 폴더 안에 `ai-learn/`이라는 하위 폴더가 생기고, 그 안에 Python 인터프리터 사본과 `pip`, 그리고 앞으로 설치할 패키지가 들어갈 `Lib/site-packages/` 디렉터리가 만들어집니다. 이후 이 환경을 활성화한 상태에서 `pip install`을 하면 패키지는 이 폴더 안에만 설치됩니다.

생성한 뒤 바로 활성화합니다.

```bash
# Windows (PowerShell)
ai-learn\Scripts\Activate.ps1

# Windows (cmd)
ai-learn\Scripts\activate.bat

# macOS / Linux
source ai-learn/bin/activate
```

터미널 프롬프트 앞에 `(ai-learn)`이 붙으면 활성화된 상태입니다. VSCode 하단 상태바에도 인터프리터 경로가 표시되는데, **Python 3.12.x ('ai-learn')** 같은 항목을 클릭해 선택합니다. 자동으로 잡히지 않으면 상태바를 클릭한 뒤 목록에서 `ai-learn` 환경을 직접 골라 줍니다.

## 5. 실습용 패키지 설치

가상환경이 활성화된 상태에서(`(ai-learn)` 프롬프트 확인), 이 책 실습 전반에 걸쳐 쓰이는 기본 패키지 다섯 개를 한 번에 설치합니다.

```bash
pip install numpy pandas scikit-learn matplotlib jupyter
```

이 다섯 패키지는 서로 독립적으로 보이지만, 실습에서는 하나의 흐름으로 이어집니다. NumPy가 n차원 배열과 벡터 연산의 기반을 제공하고, Pandas는 그 위에서 표 형태 데이터(DataFrame)를 다루며, scikit-learn은 Pandas로 정리한 데이터를 받아 머신러닝 모델을 학습시킵니다. Matplotlib은 중간 결과를 그래프로 확인할 때, Jupyter는 이 모든 과정을 셀 단위로 나누어 실행하고 출력을 바로 볼 때 쓰입니다. 각 패키지의 상세 사용법은 뒤 챕터에서 실습과 함께 다루므로, 지금은 설치만 해 두면 됩니다.

설치가 끝나면 현재 환경의 패키지 목록을 파일로 기록해 둡니다.

```bash
pip freeze > requirements.txt
```

이 파일이 있으면 나중에 다른 컴퓨터나 새 가상환경에서 같은 패키지 상태를 그대로 복원할 수 있습니다.

```bash
pip install -r requirements.txt
```

## 6. 첫 노트북 만들기

환경 구성이 제대로 되었는지 확인하는 가장 빠른 방법은 노트북 파일을 하나 만들어 직접 실행해 보는 것입니다. `.ipynb` 파일은 코드를 셀 단위로 나누어 담고, 각 셀의 실행 결과를 바로 아래에 기록해 두는 형식입니다. 이 책의 실습 대부분이 이 형식으로 진행됩니다.

VSCode 탐색기에서 프로젝트 폴더를 우클릭 → **New File**을 선택하고 `hello.ipynb`를 입력합니다. Jupyter 확장이 설치되어 있으면 노트북 편집 화면이 바로 열립니다.

노트북이 열리면 우측 상단에 **Select Kernel** 버튼이 보입니다. 커널은 셀 안의 코드를 실제로 실행하는 Python 인터프리터를 가리키는데, 여기서 앞서 만든 `ai-learn` 환경의 Python을 선택해야 합니다. 목록에 바로 보이지 않으면 **Python Environments**를 눌러 수동으로 지정합니다.

첫 셀에 다음 코드를 입력하고 `Shift+Enter`로 실행합니다.

```python
print("Hello, AI!")
```

셀 바로 아래에 `Hello, AI!`가 출력되면 Python과 Jupyter 확장이 정상적으로 연결된 것입니다.

이어서 두 번째 셀에서 앞서 설치한 패키지들이 제대로 들어왔는지 확인합니다.

```python
import numpy as np
import pandas as pd
import sklearn

print("NumPy:", np.__version__)
print("Pandas:", pd.__version__)
print("scikit-learn:", sklearn.__version__)
```

세 패키지의 버전 숫자가 모두 출력되면 이후 챕터를 따라갈 준비가 끝난 것입니다.

## 7. 자주 겪는 문제

환경 구성에서 막히는 경우는 대부분 "설치한 패키지가 있는 곳"과 "코드를 실행하는 Python"이 서로 다를 때 발생합니다. 아래 네 가지가 가장 흔한 사례입니다.

### 7.1 커널이 가상환경을 찾지 못하는 경우

노트북 우측 상단에서 커널을 골라도 시스템 전역 Python이 선택되는 경우가 있습니다. VSCode가 `ai-learn` 환경을 자동으로 감지하지 못한 것이므로, 명령 팔레트(`Ctrl+Shift+P` / `Cmd+Shift+P`)에서 **Python: Select Interpreter**를 실행한 뒤 `ai-learn/Scripts/python.exe`(Windows) 또는 `ai-learn/bin/python`(macOS/Linux)을 직접 지정합니다.

### 7.2 `ModuleNotFoundError: No module named 'numpy'`

패키지를 분명히 설치했는데 이 오류가 나온다면, 원인은 거의 두 가지 중 하나입니다.

1. **가상환경을 활성화하지 않은 상태에서 `pip install`을 실행한 경우.** 패키지가 전역 Python에만 설치되고 `ai-learn` 환경에는 들어가지 않습니다. 터미널에서 `(ai-learn)` 프롬프트를 확인한 뒤 다시 설치합니다.
2. **노트북 커널이 다른 Python을 가리키는 경우.** 7.1의 절차로 `ai-learn` 커널을 다시 선택하면 해결됩니다.

두 문제 모두 "패키지가 설치된 환경"과 "코드를 실행하는 환경"이 일치하는지를 확인하는 것이 핵심입니다.

### 7.3 Windows PowerShell에서 활성화 스크립트가 막힐 때

Windows PowerShell은 기본 실행 정책이 `Restricted`로 되어 있어, `.ps1` 스크립트 실행 자체를 차단합니다. `Activate.ps1`이 막히는 것도 이 정책 때문입니다. PowerShell에서 아래 명령을 한 번만 실행해 두면 이후에는 현재 사용자 범위에서 스크립트가 정상적으로 실행됩니다.

```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```

### 7.4 Jupyter 확장이 `.ipynb`를 열지 못할 때

Jupyter 확장이 설치는 되어 있지만 VSCode 내부에서 제대로 로드되지 않은 상태일 수 있습니다. VSCode를 완전히 종료했다가 다시 열면 대부분 해결됩니다. 그래도 노트북이 열리지 않으면 **Extensions** 탭에서 Jupyter 확장을 **Uninstall** 한 뒤 다시 **Install**합니다.
