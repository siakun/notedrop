# 04. Pandas 맛보기 - DataFrame과 Feature·Label

> Pandas는 표 형식 데이터를 읽고 다듬고 탐색하는 라이브러리입니다. AI 실습에서는 모델에 데이터를 넣기 전 단계인 **전처리**의 거의 모든 일을 Pandas로 처리합니다. 이 챕터에서는 `DataFrame`의 기본 동작과 함께, 머신러닝 데이터의 보편적인 형식인 **Feature**와 **Label**을 처음 도입합니다.

## 1. Pandas의 두 기본 자료구조

Pandas의 핵심은 두 자료구조입니다. 설치는 앞 챕터에서 이미 끝냈으니 바로 불러오겠습니다. Pandas는 내부적으로 NumPy `ndarray` 위에 이름표(인덱스·컬럼명)를 덧씌운 구조라고 생각하면 이해가 쉬워집니다.

```python
import pandas as pd
```

| 자료형 | 의미 | 시각적 이해 |
|---|---|---|
| `Series` | 1차원 배열 + 인덱스 | 한 줄짜리 표의 한 컬럼 |
| `DataFrame` | 2차원 표 (여러 Series의 묶음) | 엑셀 시트 한 장 |

`DataFrame`에서 한 컬럼만 뽑으면 `Series`가 되고, `Series` 여러 개를 나란히 붙이면 `DataFrame`이 됩니다.

## 3. 기본 탐색 API

새 데이터를 받으면 가장 먼저 실행하는 네 가지 호출이 있습니다. 이 조합만으로 데이터 규모·컬럼 구성·결측 분포·수치 분포를 한 번에 파악할 수 있습니다.


## 4. Feature와 Label

머신러닝 데이터는 대개 "여러 입력 컬럼으로 **정답 하나를 예측**"하는 구조를 가집니다. 타이타닉 데이터에서는 승객 정보로 생존 여부를 예측합니다.

```text
┌─────────────── Features (특성) ───────────────┐   ┌─ Label (정답) ─┐
  Pclass | Sex | Age | SibSp | Parch | Fare | ...      Survived
```

- **Label (클래스, 정답)**: 예측하고 싶은 컬럼입니다. 타이타닉에서는 `Survived`(0=사망, 1=생존)입니다.
- **Feature (특성, 특징)**: 정답을 예측하는 데 사용하는 입력 컬럼들입니다.

정형 데이터 머신러닝에서는 대부분 "Label 컬럼 1개 + Feature 컬럼 여러 개" 형태로 데이터를 정리합니다. 모델이 바뀌어도 이 구조는 거의 그대로이므로, Part 3에서 회귀·분류 알고리즘이 달라져도 데이터 준비 단계는 비슷한 모양으로 반복됩니다.

타이타닉 데이터의 12개 컬럼은 다음과 같이 구성되어 있습니다. `Survived` 하나가 Label이고 나머지는 모두 Feature 후보입니다.

| 컬럼 | 의미 | 비고 |
|---|---|---|
| PassengerId | 승객 ID | 식별자. 예측에 쓰지 않음 |
| Survived | 생존 여부 (0=사망, 1=생존) | **Label** |
| Pclass | 객실 등급 (1/2/3) | 비행기의 비즈니스/일반석과 유사 |
| Name | 이름 | 보통 제거 |
| Sex | male / female | |
| Age | 나이 | 결측 많음 (714/891) |
| SibSp | 형제·배우자 동반 수 | siblings + spouse |
| Parch | 부모·자녀 동반 수 | parents + children |
| Ticket | 티켓 번호 | 보통 제거 |
| Fare | 운임 | 등급과 상관 있을 가능성 |
| Cabin | 객실 번호 | 결측 많음 (204/891), 보통 제거 |
| Embarked | 승선 경유지 | |

## 5. 전통 프로그래밍과 머신러닝의 패러다임 차이

여기서 개발 패러다임이 한 번 뒤집힙니다. AI 프로그래밍을 처음 접하는 분께 특히 중요한 개념이므로 짚고 넘어가겠습니다.

- **전통 프로그래밍**: 개발자가 "답을 내는 알고리즘"을 직접 설계합니다. 예를 들어 "소수 판정"이라면 "2부터 √n까지 나눠 본다"는 규칙을 코드로 작성합니다.
- **머신러닝**: 개발자는 **데이터와 학습 알고리즘**만 제공합니다. 모델이 스스로 규칙을 찾아내며, 개발자조차 특정 입력에 대해 모델이 어떻게 판단할지 **사전에 정확히 알 수 없습니다**.

머신러닝이 하는 일의 상당 부분은 결국 **분류(classification)**로 요약됩니다. 생존/사망, 양성/음성, 고양이/강아지처럼 입력을 몇 개의 범주 중 하나로 나누는 일이 중심입니다. 회귀(연속값 예측)·강화학습·생성 모델 등 다른 축도 있지만, 머신러닝을 처음 익힐 때는 "정답 라벨을 맞힌다"는 분류 관점에서 시작하면 전체 윤곽을 빠르게 잡을 수 있습니다. 규칙 기반(기호주의)과 학습 기반(연결주의)의 대비는 Part 2에서 다시 본격적으로 다룹니다.

## 6. 컬럼 추가·파생·삭제

전처리의 핵심은 "원본 데이터를 그대로는 학습시킬 수 없다. 필요 없는 것은 빼고, 쓸 만한 것은 더 만든다"는 원칙입니다.

### 6.1 컬럼 추가

기존에 없는 컬럼명을 대입하면 새 컬럼이 만들어집니다. 상수도 되고, 다른 컬럼으로부터 계산한 값도 됩니다.

```python
# 모든 행에 0 채운 새 컬럼
titanic_df["Age_0"] = 0

# 기존 컬럼 기반 파생
titanic_df["Age_by_10"] = titanic_df["Age"] * 10

# 자기 자신 포함 가족 수
titanic_df["Family_No"] = titanic_df["SibSp"] + titanic_df["Parch"] + 1
```

원본 컬럼을 조합해 만든 **파생 feature**가 원본보다 더 강한 예측력을 갖는 경우가 흔합니다. 키와 몸무게로 BMI를 만드는 것도 같은 원리입니다.

### 6.2 벡터화 사고

Pandas의 산술 연산은 NumPy처럼 컬럼 전체에 한 번에 적용됩니다. 앞 챕터에서 본 `ndarray`의 벡터화가 그대로 이어집니다.

```python
titanic_df["Age_by_10"] = titanic_df["Age_by_10"] + 100
```

초보자 중에는 `for` 루프로 각 행을 순회하며 값을 수정하는 코드를 먼저 떠올리는 경우가 있습니다. 가능은 하지만, 행 수가 많아지면 훨씬 느려지고 가독성도 떨어집니다. **"컬럼 전체를 한 번에 계산한다"는 감각을 기본으로 삼는 것**이 Pandas를 제대로 쓰는 첫걸음입니다.

### 6.3 컬럼·행 삭제

`drop`으로 삭제합니다. 삭제 방향은 `axis`로 지정합니다. 기본값이 `0`(행)이므로 **컬럼을 지울 때는 반드시 `axis=1`을 명시**해야 합니다. 기본 동작은 새 `DataFrame`을 반환하고 원본은 유지합니다. 원본을 직접 수정하고 싶으면 `inplace=True`를 줍니다.

```python
# 컬럼 하나 삭제 (원본 유지)
titanic_drop_df = titanic_df.drop("Age_0", axis=1)

# 여러 컬럼 삭제 + 원본 직접 수정
titanic_df.drop(
    ["Age_0", "Age_by_10", "Family_No"],
    axis=1,
    inplace=True,
)

# 행 삭제 (앞 3행 제거)
titanic_df.drop([0, 1, 2], axis=0, inplace=True)
```

`axis=0`이 행, `axis=1`이 열이라는 규칙은 `drop`뿐 아니라 Pandas의 다른 집계 함수에서도 동일하게 쓰입니다. 앞 챕터에서 본 NumPy의 `axis` 규칙과 같은 맥락입니다.
