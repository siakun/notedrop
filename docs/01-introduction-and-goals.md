# 01. Introduction and Goals

## 1.1 무엇을 만드는가

옵시디언 vault 안의 노트 또는 책 (= 폴더 + 챕터 .md 파일들) 을 한 번의 명령으로 GitHub Pages 위 **책 뷰어 형태 사이트** 에 발행하는 플러그인 + 그에 동반되는 Static SPA 뷰어. 두 부분은 한 프로젝트의 두 산출물로 본다.

발행된 페이지는 다음을 만족한다:

- A4 등 A3 ~ B6 사이 사용자 선택 페이지 사이즈로 페이지네이션 (paged.js)
- 한 권의 책은 하나의 URL 에서 챕터 사이드바 TOC + 앵커 네비게이션
- 단일 문서도 같은 뷰어로 (책에는 사이드바, 문서엔 없음)
- 페이지 우상단 다운로드 버튼 → 브라우저 print 엔진으로 즉석 PDF
- 작가가 vault 에서 편집하는 동안 로컬 미리보기 (`localhost:7777`) 가 실시간 갱신

## 1.2 왜 만드는가

### 1.2.1 사용자 페인포인트 (현재)

사용자는 한국어 기술서 *코드로 배우는 AI 프로그래밍* 을 옵시디언에서 집필 중. 원고는 자주 (2일 단위로 큰 변동) 갱신되고, 일부 챕터를 지인에게 보여 피드백 받고 싶어한다. 현 워크플로:

- 보여줄 때마다 폴더를 zip 으로 압축 → 메신저로 전송
- 받은 사람이 옵시디언 또는 다른 도구로 열어야 하는데 다들 그게 없음
- 며칠 뒤 원고가 바뀌면 다시 zip → 다시 전송
- 옵시디언 자체엔 웹 공유 기능 없음 (Obsidian Publish 는 별도 유료)

요지: *비싼 공유, 늦은 공유, 부담스러운 공유* 가 피드백 사이클을 늘려 책 품질에도 영향.

### 1.2.2 노션 모델 차용

해결 방향은 노션의 페이지 공유 모델: *발행 토글 한 번 → 공개 URL 즉시 생성 → 이후 편집은 자동 반영*. 단 노션은 백엔드 의존이고 비용·잠금이 있어 옵시디언 + GH Pages 조합으로 동등 UX 구현.

### 1.2.3 책 정체성 보존

단순 마크다운 호스팅이 아니라 *책에 어울리는 UX 개선드 페이지 뷰어* 가 명시적 요구. PDF Expert / Google Play Books 톤. 그래서 paged.js 기반 페이지네이션 + 사이즈 선택 + PDF 다운로드 가 1차 기능에 포함.

### 1.2.4 비공개·공개 공존

같은 vault 에 비공개 일기 + 공개 책 + 공개 단독 문서가 섞여 있다. 사고로 일기가 새면 안 되므로 화이트리스트 + 구조적 격리가 필수. 2-레포 구조와 다층 안전장치가 여기서 출발.

## 1.3 1차·2차 목표

| 순위 | 목표 | 의미 |
|---|---|---|
| 1차 (주) | 본인 책 발행 워크플로 해결 | 옵시디언에서 한 번에 공개 URL 생성 + 자동 갱신. zip 전송 0회 |
| 1차 (주) | 비공개 누설 0건 보장 | 화이트리스트 + 구조적 격리. 단 한 번도 비공개 콘텐츠가 public 레포에 들어가서는 안 됨 |
| 1차 (주) | 책에 어울리는 페이지 뷰어 | 사이즈 선택, PDF 다운로드, 챕터 사이드바, KaTeX 수식, Mermaid 다이어그램 |
| 2차 (부) | 라이브 미리보기 | 로컬 HTTP 서버 + SSE, 옵시디언에서 편집 → 브라우저 자동 갱신 |
| 2차 (부) | 단일 문서 발행 | 책 외 단독 노트도 같은 뷰어로 공유 |
| 3차 (장기) | 일반 사용자 OSS 배포 | 옵시디언 community plugins 등록, 다른 사용자도 자기 vault 로 동일 워크플로 |

1차 셋이 전부 되어야 v0.1.0 release. 2차는 강력 권장이지만 필수는 아님 (그래도 라이브 미리보기는 사실상 1차에 포함되는 분위기). 3차는 v1.0+ 후.

## 1.4 합격 기준 (release readiness)

v0.1.0 출시 전 충족할 객관적 조건:

- [ ] Domain layer 단위 테스트 커버리지 90% 이상 (안전장치 100%)
- [ ] 본인 책 *코드로 배우는 AI 프로그래밍* dogfood 1주일 (실제 발행, 실제 갱신, 실제 공유)
- [ ] 단일 문서 발행 dogfood (예: 자소서 또는 트레이딩 봇 정찰 기획서)
- [ ] 라이브 미리보기 1시간 연속 사용 (메모리 누수, SSE 끊김, 포트 누수 없음)
- [ ] 안전장치 케이스 모두 단위 테스트 통과:
    - publish flag 없는 노트는 어떤 경로로도 발행 X
    - vault frontmatter 비-`notedrop-*` 키는 public 출력에 누설 X
    - `%%` 주석 strip 검증
    - 미발행 위키링크·임베드 안전장치 작동
- [ ] 에러 메시지 명확성 검증 (PAT 만료, 네트워크 끊김, 충돌)
- [ ] README + 설치·설정 가이드 작성 (사용자 본인 onboarding 기준)

## 1.5 비-목표 (의도적 제외)

다음은 *목표 아님*. 시간·복잡도 절약을 위해 명시적 제외. 작업 도중 *이거 더 하면 좋지 않나* 충동이 생기면 이 표로 돌아온다.

| 비-목표 | 사유 |
|---|---|
| 백엔드·DB·인증·결제 | 정적 사이트 + GH Pages 만으로 모든 1차 목표 달성. 백엔드는 운영 부담 큰 부채 |
| 노션 수준 실시간 협업 | 단일 작가 시나리오. CRDT·실시간 동기는 폭발적 복잡도 |
| 댓글·피드백 위젯 (MVP) | v2 검토 (Giscus 등). MVP 는 외부 채널 링크만 |
| 검색 (MVP) | v2 검토 (Lunr.js 클라이언트 인덱스). TOC 사이드바로 우선 충분 |
| 모바일 옵시디언 publish | 모바일은 Node http 서버 불가. 작가 워크플로는 데스크톱 중심이라 손실 작음 |
| 옵시디언 외 마크다운 도구 호환 | Domain layer 는 옵시디언 의존 없게 짜지만, 어댑터 추가는 v2+ |
| Obsidian Publish 같은 동적 그래프·백링크 위젯 | 책 뷰어 정체성과 충돌. 단순 책으로 읽히는 게 우선 |
| 한국어 외 다국어 | 본인용 우선. 콘텐츠 자체는 다국어 가능하지만 UI 한국어 only |
| 결제 모델, 광고 | 개인 사용 + OSS. 수익 모델 X |
| 다크 테마 (MVP) | 책 가독성 라이트 테마 우선. v2 |
| 가로 모드 페이지 (MVP) | 세로 고정. v2 |
