# ADR-0007: 책 1권 = 1 URL, 챕터는 SPA 앵커

- **Status**: Accepted (2026-04-26)

## Context

책 한 권에 챕터가 수십 개. URL 구조 옵션:

C1. 챕터별 URL: `/notedrop/<book>/<chapter>` - 특정 챕터 직접 공유 가능
C2. SPA 앵커: 책 1 URL + `#chapter-3-2` 앵커, SPA 가 스크롤·라우팅

사용자 결정: **C2 채택**.

## Decision

**한 책 = 한 URL** (`/notedrop/<book-hash-or-slug>`). 챕터는 같은 URL 안에서 SPA 앵커 (`#chapter-...`) 로 네비.

뷰어 동작:
- 책 entry 페이지 진입 시 manifest 의 chapters 배열로 사이드바 TOC 렌더
- 사이드바 챕터 클릭 → `window.scrollTo` + URL 해시 갱신 (SPA, 페이지 reload X)
- 본문은 모든 챕터를 한 페이지에 길게 (paged.js 가 페이지로 분할)

각 챕터 파일은 여전히 자체 hash 와 `/content/<chapter-hash>/index.md` 를 가지지만 URL 직접 접근은 지원 안 함 (또는 책 URL + 앵커로 redirect).

## Consequences

긍정:
- URL 단순. 책 1권 = 외울 수 있는 1개 URL
- 페이지네이션 (paged.js) 이 책 전체를 통일 적용 - 페이지 번호, 헤더/푸터, 사이즈 변경이 일관
- SPA 네비가 빠름 (반복 fetch X)

부정:
- 챕터 직접 링크 공유 불가 (URL 에 fragment 만 추가하거나 책 URL 안에서 찾아야)
- 큰 책 (수백 챕터) 일 때 첫 로드 시 전체 markdown fetch - 트래픽·페이지네이션 비용 큼
- SEO 측면에서 챕터별 페이지가 검색 인덱스에 안 잡힘 (페이지 1개로 보임)

## Alternatives Considered

### C1. 챕터별 URL

`/notedrop/<book>/<chapter>` 또는 `/notedrop/<chapter-hash>`.

거부 사유:
- "URL 평면" ([ADR-0006](0006-url-flat-구조.md)) 와 충돌
- 챕터 사이 네비 시 페이지 reload 또는 lazy fetch 필요 (SPA 복잡도)
- paged.js 페이지네이션이 챕터마다 다시 시작 → 페이지 번호 일관성 깨짐

### C3. 하이브리드: 책 URL 기본 + 챕터 직접 URL 도 작동

`/notedrop/<book>` (전체) 와 `/notedrop/<chapter-hash>` (챕터 단독) 둘 다 지원.

거부 사유:
- 두 가지 라우팅 모드 = 코드 복잡 (산탄총 수정 위험)
- 챕터 단독 URL 시 페이지 사이즈·헤더·표지 등 책 컨텍스트 손실
- v2 검토 가능하지만 MVP 에는 과함

## 큰 책 성능 mitigation (필요 시 v2)

수백 챕터 책의 첫 로드 부담 완화:
- Lazy fetch: 사이드바에서 클릭한 챕터만 fetch
- 청크 단위 로드: 가까운 챕터 prefetch
- Service Worker 캐싱

이 최적화는 *필요할 때* 도입. MVP 는 단순 전체 로드.
