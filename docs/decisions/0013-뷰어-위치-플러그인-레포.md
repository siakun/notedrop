# ADR-0013: 뷰어 소스 위치 = 플러그인 레포 안 (option β)

- **Status**: Accepted (2026-04-26)

## Context

뷰어는 Next.js 프로젝트. 플러그인 (옵시디언 TS) 과 별개의 산출물이지만 공통 contract (HTTP API: manifest, content) 로 통신.

소스 코드 위치 후보:

α. **Public 레포 안** (`siakun/notedrop/viewer/`) - 콘텐츠와 뷰어 같은 레포
β. **플러그인 레포 안** - 플러그인이 뷰어 소유. 빌드 결과를 플러그인 번들 + public 레포 둘 다 배포
γ. **별도 3번째 레포** (`siakun/notedrop-viewer`) - 완전 분리. submodule 또는 release artifact 로 끌어옴

## Decision

**β 채택**: 뷰어 소스는 플러그인 레포 안 (`notedrop/viewer/` 같은 디렉터리).

플러그인 빌드 시:
1. 뷰어 빌드 (`npm run build` in viewer/) → 정적 HTML/JS/CSS 출력
2. 플러그인 번들 생성 시 뷰어 빌드 결과를 plugin assets 로 포함
3. publish 액션 시 플러그인이 같은 빌드 결과를 public 레포에 push (또는 사전에 포함)

```
notedrop/                      ← 별도 개발 디렉터리 (TBD)
├── plugin/                    ← 옵시디언 플러그인 (TS + esbuild)
│   ├── manifest.json
│   ├── main.ts
│   ├── src/...
│   └── viewer-dist/           ← 빌드 결과 복사 (빌드 단계에서 채워짐)
├── viewer/                    ← Next.js 뷰어 소스
│   ├── next.config.ts         ← output: 'export'
│   ├── package.json
│   └── src/...
└── package.json               ← root, monorepo 관리 (workspace 또는 단순 npm script)
```

빌드 스크립트:
```json
{
  "scripts": {
    "build:viewer": "cd viewer && npm run build && cp -r out ../plugin/viewer-dist",
    "build:plugin": "cd plugin && npm run build",
    "build": "npm run build:viewer && npm run build:plugin"
  }
}
```

## Consequences

긍정:
- 플러그인이 뷰어를 own → 버전 일치 보장 (플러그인 v0.1.0 = 뷰어 v0.1.0)
- 사용자 (작가) 입장에선 "notedrop 프로젝트 전체" 가 한 디렉터리
- 별도 디렉터리 결정 ([project_notedrop_별도디렉토리](../../C--Users-User-..../memory/project_notedrop_별도디렉토리.md) 참조) 과 자연스럽게 맞물림
- 뷰어 빌드는 한 번, 두 곳 (플러그인 번들 + public 레포) 에 배포

부정:
- monorepo 관리 약간 복잡 (npm workspaces 또는 lerna)
- 플러그인만 발전 (뷰어 변경 X) 시에도 뷰어 빌드 필요할 수 있음 (캐시·skip 로직 필요)

## Alternatives Considered

### α. Public 레포 안 (`siakun/notedrop/viewer/`)

뷰어 소스가 콘텐츠와 같은 레포.

거부 사유:
- 콘텐츠와 뷰어 관심사 섞임 (공유 콘텐츠가 들어 있는 레포에 코드 PR 들어옴)
- 플러그인이 push 시 viewer/ 도 매번 push 해야 (push 부담)
- 뷰어 코드 변경 시 플러그인 변경과 동기 어려움 (다른 레포)

### γ. 별도 3번째 레포

거부 사유:
- 초기에는 과도한 분리
- submodule 관리 부담
- 뷰어 - 플러그인 동시 변경 시 두 레포 PR 동기 필요

### α 변형: viewer 가 public 레포에 있되 npm package 로 publish

거부 사유:
- npm publish 부담
- 사용자 (single user) 가 npm install 받는 패턴이 plugin 환경에 안 맞음

## v1.0+ 시 재검토

플러그인이 안정화되고 community plugins 마켓에 등록 시점:
- 뷰어를 별도 npm package 로 분리 가능
- 플러그인 패키지 사이즈 줄이기 위해 뷰어 CDN 호스팅 검토

지금은 β 가 단순·일관성 우위.
