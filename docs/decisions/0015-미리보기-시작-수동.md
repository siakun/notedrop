# ADR-0015: 라이브 미리보기 시작 = 수동 명령어 + 설정 토글

- **Status**: Accepted (2026-04-26)

## Context

라이브 미리보기 ([ADR-0014](0014-라이브-미리보기-http-sse.md)) HTTP 서버를 언제 시작할지 정책 필요.

후보:
- a) 옵시디언 시작 시 자동
- b) 수동 명령어로 시작·중지
- c) 설정 토글로 시작·중지

자동은 편리하지만 포트 점유 + 메모리 상시 사용. 항상 켜놓을 사용자도 있고 가끔 켜는 사용자도 있어 정책이 사용자별로 다름.

## Decision

**기본: 수동 명령어 + 설정 토글 버튼**. 자동 시작은 옵션 (default off).

### 시작·중지 채널

1. **명령어 (Cmd+P)**:
   - `Notedrop: Start preview server`
   - `Notedrop: Stop preview server`

2. **설정 화면 토글**:
   - Settings → Notedrop → "Preview server" 토글 버튼
   - 현재 상태 (실행 중 / 중지) + 포트 표시
   - 클릭으로 즉시 토글

3. **status bar 인디케이터**:
   - `▶ Notedrop :7777` (실행 중)
   - `■ Notedrop` (중지)
   - 클릭하면 토글

### 옵션: 자동 시작

설정에 토글 추가:
- "Start at Obsidian launch" (default OFF)
- ON 으로 설정 시 옵시디언 시작 = 서버 자동 시작

### 시작 시 동작

1. http.createServer() 로 listen 시도
2. 포트 점유 시 fallback (7777 → 7778 → ... → 7800)
3. 시작 성공 시 클립보드에 URL 복사 + Notice 표시
4. 옵션: 기본 브라우저 열기 (별도 토글, default OFF)

### 중지 시 동작

1. server.close()
2. SSE 연결 종료
3. status bar 갱신
4. 인메모리 캐시 GC

### 옵시디언 종료 시

`onunload` 에서 자동 stop. 명시적 정리.

## Consequences

긍정:
- 안 쓰는 사용자에게 부담 없음 (포트 점유·메모리 사용 X)
- 명시적 시작이 안전 (사용자가 의도하지 않은 서버 노출 방지)
- 자동 시작 옵션으로 자주 쓰는 사용자도 만족
- 채널 3개 (명령어, 설정 토글, status bar) 가 사용자 선호 다양성 커버

부정:
- 초회 사용 시 "Start" 미실행하면 미리보기 미작동 (가이드 필요)
- 명령어 이름 암기 부담 (Cmd+P 검색으로 발견 가능)

## Alternatives Considered

### a. 자동 시작 (default ON)

거부 사유:
- 옵시디언 켤 때마다 포트 점유 + 메모리
- 서버 안 쓰는 세션에서도 부담
- 옵시디언 시작 시간 미세 증가

자동 시작은 사용자가 명시적 ON 한 경우만 (기능 자체는 제공).

### b. 명령어만 (설정 토글 없음)

거부 사유:
- 명령어 외우거나 Cmd+P 매번 검색 부담
- 토글 버튼이 시각적으로 더 직관적 (현재 상태도 보임)

### c. 설정 토글만 (명령어 없음)

거부 사유:
- 키보드 워크플로 사용자 (단축키, Cmd+P) 불편
- 명령어가 더 빠른 경우 있음

## 포트 점유 처리

7777 사용 중 (다른 앱이 점유) 시:
1. 7778 시도
2. 7779 시도
3. ... 7800 까지
4. 모두 실패 시 사용자에게 명확한 에러 + 다른 포트 입력 가이드

성공한 포트는 status bar 와 클립보드 URL 에 반영.
