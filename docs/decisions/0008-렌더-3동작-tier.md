# ADR-0008: 렌더 정책 3-동작 + 옵시디언 코어 Tier

- **Status**: Accepted (2026-04-26)

## Context

옵시디언 마크다운에는 코어 문법 + 플러그인 문법 + 주석 등 다양한 요소가 있다. 어떤 걸 어떻게 렌더할지 정책 필요.

초기 안 (tier-based) 시도 후 사용자가 핵심 정정:

> "렌더 안함" 이 *렌더링 거쳐 숨김* 인지 *파서가 손 안 댐* 인지 혼용하지 말 것.

이게 결정적 통찰이라 정책을 3-동작으로 분리.

## Decision

### 3 동작 정의

| 동작 | 정의 | 출력 결과 |
|---|---|---|
| **HIDE** | 파서가 의미를 이해하고 출력에서 완전 제거 | 아무것도 안 남음 (텍스트로도 X) |
| **RENDER** | 옵시디언 의미로 풀 렌더 | 옵시디언 읽기 모드와 동일 |
| **PASSTHROUGH** | 파서가 변경하지 않음 → 기본 마크다운 규칙으로 떨어짐 | 코드블록이면 코드블록, 일반 텍스트면 텍스트 |

### 우선순위

**HIDE > RENDER > PASSTHROUGH**

- 어떤 요소가 `%%` 안에 있으면 무조건 HIDE (Waypoint 블록처럼 플러그인 문법이라도 `%%` 안이면 HIDE 적용)
- 옵시디언 코어 문법으로 인식되면 RENDER
- 그 외 (= 우리가 모르는 모든 것) 는 PASSTHROUGH

### 분류 표

| 요소 | 동작 | 이유 |
|---|---|---|
| 표준 마크다운 + GFM 전부 | RENDER | 기본 |
| 코드블록 + syntax highlighting | RENDER | 옵시디언 코어 |
| 위키링크 (`[[]]`, `[[\|alias]]`, `[[#heading]]`, `[[#^block]]`) | RENDER | 옵시디언 코어 |
| 이미지 임베드 + 사이즈 (`![[img.png\|400]]`) | RENDER | 옵시디언 코어 |
| 콜아웃 (`> [!info]`, `> [!warning]` 등) | RENDER | 옵시디언 코어 |
| 하이라이트 (`==text==`) | RENDER | 옵시디언 코어 |
| 수식 (`$ $`, `$$ $$`) | RENDER (KaTeX) | 옵시디언 코어 |
| Mermaid (` ```mermaid `) | RENDER | 옵시디언 코어 |
| 노트 임베드 (`![[Note]]`) | RENDER (재귀 깊이 1) | 옵시디언 코어 |
| 블록 ID (`^id`) | RENDER | 옵시디언 코어 |
| 풋노트 (`[^1]`) | RENDER | 옵시디언 코어 |
| 태그 (`#tag`) | RENDER (텍스트로) | 옵시디언 코어 |
| 태스크 (`- [ ]`, `- [x]`) | RENDER | 옵시디언 코어 |
| `%%주석%%` | **HIDE** | 옵시디언 읽기 모드 비표시 |
| frontmatter 전체 | **HIDE** | 본문에 출력 안 함. `# YAML 주석` 도 자동 사라짐 |
| Waypoint `%% Begin/End Waypoint %%` 블록 | **HIDE** | `%%` 안이라 HIDE 우선. 챕터 추출용으로만 내부 사용 |
| ` ```dataview ` 블록 | **PASSTHROUGH** | 파서 미구현 → 일반 코드블록으로 표시 |
| ` ```mermaid ` 블록 | RENDER | 옵시디언 코어 |
| Templater `<%* %>` | **PASSTHROUGH** | 사용자 저장 시 실행되어 결과만 남는 패턴이라 raw 거의 없음 |
| `.base` 파일 | (발행 대상에서 제외) | 마크다운 아님 |
| `.excalidraw.md` | **PASSTHROUGH** | 형식 보존, 의미 안 풀림 |

### 안전장치 (별도 동작)

[ADR-0009](0009-미발행-ref-안전장치.md) 참조. 사용자 의도와 무관하게 강제 적용:
- 미발행 위키링크 → 빨간 dead link
- 미발행 임베드 → "접근할 수 없는 문서" placeholder

## Consequences

긍정:
- 세부 케이스 대부분이 자동 결정 (3 동작 + 우선순위 규칙으로)
- 옵시디언 읽기 모드와 결과가 일치 (사용자 멘탈 모델 일치)
- HIDE 와 PASSTHROUGH 혼동 제거 (이전 안의 모호함 해소)
- 새 문법 만나면 PASSTHROUGH 가 안전한 default - 깨지지 않고 raw 로 보임

부정:
- 분류 표를 정해야 함 (새 옵시디언 문법 추가 시 분류 필요)
- PASSTHROUGH 된 dataview 등은 사용자 책에 코드블록 형태로 보임 - 사용자가 책에서 dataview 안 쓰도록 유의

## Alternatives Considered

### 1. Tier 1/2/3 (초기 안)

MVP 필수 / 권장 / 후순위 분류.

거부 사유:
- "렌더 안함" 이 HIDE 인지 PASSTHROUGH 인지 혼용 → 사용자 정정
- 우선순위 규칙 없어서 케이스마다 결정 필요

### 2. 화이트리스트만 (옵시디언 코어 외 모두 strip)

거부 사유:
- 새 문법 만나면 사라짐 - 사용자가 *왜 비표시인가?* 혼란
- PASSTHROUGH (raw 로 보임) 가 더 정직

### 3. 모두 RENDER 시도

거부 사유:
- 플러그인 의존 (Dataview 등) 실행은 옵시디언 환경에서만 가능. 뷰어에서 못 함
- 직접 구현은 폭발적 작업량
